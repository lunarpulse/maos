# ADR-049 — Cross-region convergent replication with enforced re-attestation (TL-anchored CRDT)

> **Naming (corrected 2026-07-02).** This mechanism was originally framed as "consensus." It is **not** consensus in the CP/Raft sense — there is no leader, no quorum, and no linearizable agreement. It is a **TL-anchored CRDT that converges** by deterministic last-writer-wins over a grow-only set. Calling it "consensus" overclaims a property it does not deliver, so the committed name is **cross-region convergent replication with enforced re-attestation**. The file slug retains `…-consensus` for link stability only.

**Decision.** Cross-region collective memory **converges** via a **TL-anchored CRDT** — a grow-only set of target tuples with **timestamp-aware last-writer-wins per target**, **per-region-sovereign**. Cross-region propagation is a **mediated re-attestation of the `collective_memory` KV rows**, never transparent replication and never a re-projection of TL frames: a mediator verifies a source region's signed **`CrossRegionReplicationBundle`** (a Merkle root over per-row `canonical_kv_leaf` bytes, signed under the source region's 9.4b TL-**derived** key), re-admits the rows through the destination's region chokepoint, and stamps cross-region `source_log_ref` provenance. **"TL-anchored" means the re-attestation SIGNING KEY is the Transparency-Log-derived per-region HKDF key — the same trust root as 9.4b — NOT that the row content lives in a TL frame** (it does not — see §Code-grounding). **Raft-style CP consensus is REJECTED.** Convergence is **measured**, by independent per-region re-derivation of the Story-10.4b oracle discipline (canonical-leaf serde + Merkle root + payload-multiset + exact row-count) applied to the KV rows. On partition, the Collective tier **degrades locally** to Private/Shared with **no global halt**, fail-closed on region identity. Replication + the timestamp-aware merge + the re-attestation orchestration live in `maos-loom-lite`; verification + re-signing live in `maos-audit`; the kernel is touched by exactly **one bounded, compile-gated `WriteEntryPoint::CrossRegionReadmit` provenance arm** (re-pin 22964→~22980) that *names* re-admit provenance and nothing more.

## Context

Story 11.2a multi-instances the Loom collective tier across regions. The governing constraint is the **9.4b region weld** (ADR-047 §3, the TL-anchored trust root): the canonical region tag is mixed into the HKDF derivation of the per-region Transparency-Log signing key, and the resulting Ed25519 signature covers the region tag. This makes a region's data **cryptographically unusable** in another region unless it is deliberately re-attested under the destination key. Any "just replicate the rows" design is therefore not merely discouraged — it is **structurally impossible** to do silently, which is the property this ADR builds on rather than fights.

### Code grounding (survey 2026-06-29; F2 mechanism verified 2026-07-02) — and two corrections to the ratified wording

This ADR is grounded in the landed tree, not an aspirational design:

- **Region type + canonical form.** `Region(String)` newtype, frozen `ascii-v1`, grammar `^[a-z0-9-]{2,32}$` (`crates/maos-domain/src/region.rs:39,44,56-80`). `RegionError::ERegionViolation { expected, found, detail }` (`region.rs:141-148`). `RegionSection { home_region: Option<Region> }` is the operator.toml `[region]` config (`crates/maos-kernel-core/src/security/operator_config.rs:166-169`) — region binding is **governance-only** via this config + the entry-point chokepoints; there is **no per-row `RegionTag`** type.
- **The weld is HKDF→signing-key, in `maos-audit`, not kernel-core.** `derive_region_signing_seed(base_seed, region)` mixes `region.as_bytes()` into the HKDF-SHA256 `info` (`REGION_INFO_PREFIX = b"maos.region.ascii-v1:"`, salt `REGION_TL_SIGNING_SALT = b"maos.region.tl-signing.v1"`) → the per-region Ed25519 signing seed; `derive_region_pubkey` is the verify-side companion (`crates/maos-audit/src/sealed_export.rs:14,18,26-42`). `maos-kernel-core` contains no HKDF.
- **CORRECTION 1 — there is no AEAD/AAD.** The 2026-06-29 wording said the region tag is welded into "the TL signing key (HKDF info) **+ sealed-export AEAD AAD**." Against the code, **the AEAD half does not exist.** Under the re-ratified **Option A**, sealed TL/export artifacts are **signed, not encrypted**, and working-memory rows are **plaintext** (ADR-047 §3 D1 waiver; `maos-audit` crypto deps are `{ed25519-dalek, sha2, hkdf}` only). The region binding is two-fold: **(a)** HKDF `info` → the Ed25519 signing key, and **(b)** the region tag is **covered by the signature** (R-RG4′ tamper test, `sealed_export.rs:396-413`). This ADR commits the **sign-only** mechanism.
- **CORRECTION 2 (2026-07-02) — the collective-memory content is NOT TL-anchored; the crossing unit is the KV row, not a TL frame.** A code check of the collective write path settled this: `collective_write` (`crates/maos-kernel-core/src/memory/mod.rs:210-270`) does exactly two durable things — `caps.verify_and_audit(...)` then `port.write(spirit_pid, namespace, key, value)`. The KV value (key/namespace/value) lives **only** in the `collective_memory` Postgres row; it is **never** written into a Transparency-Log `AuditEntry`. The one TL frame on the path — a `FrameKind::CapabilityInvocation` emitted by `verify_and_audit` — is **fire-and-forget and droppable** (`try_send` → `record_drop()` under backpressure, `capability/mod.rs:234-256`), carries `{token_id, spirit_pid, outcome}` (NOT the row content), is **not per-row**, and returns **no `frame_id`** the caller can reference. Therefore "re-attest the TL frames and reuse the 10.4b frame oracle" rests on infrastructure that is not landed; the honest, buildable design re-attests and converges the **KV rows** (§2/§4), and "TL-anchored" is honored through the **signing key** (a TL-derived per-region HKDF key), not through frame-crossing.
- **The convergence oracle discipline is built** (Story 10.4b, byte-identity-proven) — canonical-leaf serde, payload oracle over the sorted multiset of row hashes, Merkle root, row-count + triple-oracle verify-before-commit, and engine-independent readers that re-derive from **uncommitted** rows (`crates/maos-loom-lite/src/canonical.rs`, `migration.rs`). **But it canonicalizes the 11-column `transparency_log` frame shape, not the `collective_memory` KV-row shape** — so 11.2a authors a NEW `canonical_kv_leaf` mirroring the pinned engine-independent layout, and generalizes `maos_audit::erasure::merkle::build_tree_from_frame_ids` → `build_tree_from_leaves(&[[u8;32]])` (the frame-ids fn becomes a 2-line wrapper, preserving 9.x `AuditBundle` byte-identity).
- **CRDT-shaped store semantics exist, single-instance and non-convergent.** `store.rs:169-205` writes via `INSERT … ON CONFLICT (spirit_pid, namespace_kind, namespace_detail, key) DO UPDATE` (`schema.rs:51` UNIQUE) — a grow-only set of targets with **blind** LWW: unconditional overwrite, **no timestamp comparison** (`:188-191`), and the `timestamp_ns` is **re-minted from local wall-clock at apply time** (`:181-184`). That is not convergent across regions (final state depends on arrival order). `collective_memory` has **no region/actor/frame_id column** to order on. True timestamp-aware merge across instances is greenfield.
- **`source_log_ref` provenance exists — intra-region only.** A `source_log_ref TEXT` column (`schema.rs:47`) names a single region's TL frame_id and is never populated by `write`. A **cross-region** provenance is greenfield.
- **Degrade primitives exist; no global halt.** `MemoryError::CollectiveNotYetAvailable` (`memory.rs:285-288`) and the typed `CollectivePortError::Unreachable/Timeout` (`ports/collective_memory.rs:23-39`) surface collective-tier failure as a per-call typed `Err`; Private/Shared are unaffected; nothing halts globally. An *automatic* Collective→Private/Shared downgrade router is greenfield.
- **The collective path has ZERO region enforcement today.** `collective_write/read/scan` (`mod.rs:210/274/317`) do capability mediation only and call `enforce_region` **nowhere**; region-pin runs only on the trait `DirectWrite`/`DirectRead` path (`mod.rs:683/770/824/863`). So re-admit enforcement is greenfield — resolved by the §6 `CrossRegionReadmit` arm.

**Replication, CRDT-merge, gossip, anti-entropy, Raft, mediator — none exist** (workspace sweep returns zero). Raft is not being torn out; it was never present. The decision is which model to *build*.

## Decision

### 1. The model is a TL-anchored CRDT, per-region-sovereign, source-timestamp-ordered

Collective memory is a **grow-only set of target tuples** `(spirit_pid, namespace_kind, namespace_detail, key)` (the existing UNIQUE keyspace, `schema.rs:51` — **region does NOT enter the UNIQUE key**, or cross-region rows for the same logical key would never collide and never converge) with a **last-writer-wins register per target**. To be conflict-free and convergent regardless of propagation order, LWW resolves by a **deterministic total order over `(source_ts, source_region)`** — replacing today's blind unconditional overwrite (`store.rs:188-191`) with a conditional upsert: apply only if `excluded.source_ts > stored.source_ts OR (excluded.source_ts = stored.source_ts AND excluded.source_region > stored.source_region)`. Two new **additive** columns carry the order: `source_ts BIGINT` (the **source region's** write timestamp, **preserved verbatim across re-attestation apply — never re-minted**; re-minting on apply destroys convergence) and `source_region TEXT` (populated from the re-admit provenance; local writes stamp the home region). A region's own writes are monotonic-within-Spirit (`schema.rs:26`), so intra-region same-key/same-`source_ts` collisions are serialized at the source; the per-row `canonical_kv_leaf` hash is available as a final deterministic tiebreak if ever required. Every region is **sovereign over its own writes**; it never serves a foreign region's row that has not been re-attested under its own key.

### 2. Cross-region propagation = mediated re-attestation of the KV rows, never transparent replication

A row crosses a region boundary only inside a signed **`CrossRegionReplicationBundle`** (`maos-loom-lite/src/replication/`):

```
CrossRegionReplicationBundle {
  schema_version: u16,
  source_region:  Region,
  root:           [u8;32],              // build_tree_from_leaves over per-row canonical_kv_leaf hashes
  leaves:         Vec<CollectiveKvLeaf>, // (source_region, source_ts, spirit_pid, namespace, key, value)
  region_sig:     Signature,            // Ed25519 over: SIG_DOMAIN || schema_version || source_region || root
}
```

The mediator:

1. **verifies** — `verify_bundle` where the public key is **always** `derive_region_pubkey(claimed_source_region)` (`sealed_export.rs:40,235`), **never** a key carried inside the bundle (or forgery is a one-liner). The signing seed is `derive_region_signing_seed(source_region)` — the 9.4b TL-derived key; **no new key is introduced**;
2. **re-admits** — through the destination's region chokepoint, the `WriteEntryPoint::CrossRegionReadmit` provenance arm (§6);
3. **merges** — applies each verified leaf via the §1 timestamp-aware conditional upsert;
4. **stamps** — cross-region `source_log_ref = SourceLogRef { source_region, merkle_root }`, a **dereferenceable** provenance record (loom-lite retains or can re-derive the signed bundle, so a forensic query resolves the root back to the actual rows — a hash you cannot dereference is not provenance).

`AuditBundle`/`AuditEntry` is **NOT reused** (the audit shape ≠ the KV-row shape). Transparent row replication is **rejected and impossible**: a source region's leaves are signed under a key the destination cannot reproduce (the 9.4b weld), so a naive copy fails closed at verify time. Re-attestation is the *only* path across a boundary, and it is auditable (every re-admitted row names its origin region + the bundle root).

### 3. Raft-style CP consensus is REJECTED

A cross-region Raft/quorum leader is rejected on three independent grounds:

- **It contradicts the region weld.** Raft assumes a single replicated log copied verbatim across nodes; the 9.4b weld makes a verbatim foreign-region log cryptographically unusable. CP replication would require dissolving the per-region signing keys (unwinding 9.4b/ADR-047) or re-signing every entry (which is re-attestation, i.e. this ADR, not Raft).
- **It contradicts operator-local sovereignty.** A global consensus leader centralizes write authority across regions, contradicting ADR-009 (operator-local trust) and ADR-047 (substrate-as-substrate, no central authority). Regions are sovereign; there is no global leader to elect.
- **It sacrifices availability the substrate wants to keep.** CP halts the minority partition; the substrate's posture (air-gap-first; per-tier isolation) favors **AP-local-degrade** (§5). CRDT is the AP-consistent model; LWW-register + grow-only-set are the canonical conflict-free types.

### 4. Convergence is proven by independent per-region re-derivation over the KV rows

Convergence is **measured**, not asserted. Each region independently re-derives, over its own `collective_memory` rows on read-back, the oracle set: `canonical_kv_leaf` bytes → per-row SHA-256 leaf hashes → **Merkle root** (`build_tree_from_leaves`) + **payload oracle** (sorted multiset of leaf hashes) + **exact row-count**. Two regions have converged **iff all** match. The **payload oracle catches any single-byte divergence the frame-id-only Merkle root is blind to** (the Merkle root is a SET oracle, not a correctness oracle). The re-derivation must be **genuinely independent of the write codec** (no encode-then-decode-with-the-same-buggy-codec tautology), and the empty-set case is reported **N/A, not a meaningful pass**.

`canonical_kv_leaf` is domain-separated (`KV_LEAF_DOMAIN`), with a **u32-BE length prefix on every field** (load-bearing — without it `region="ab" key="c"` and `region="a" key="bc"` collide) in fixed order `(source_region, source_ts, spirit_pid, namespace, key, value)`, hashing the **source-authoritative** `source_ts`/`source_region`, never a store-minted timestamp. Every persisted crossing column must participate in the leaf pre-image; a silently-excluded column collapses divergent states to one leaf and is a defect.

### 5. Partition → AP-local-degrade, no global halt, fail-closed on region identity

On a cross-region partition, the Collective tier **degrades locally**: a region keeps serving its own + previously-re-attested data; un-propagated foreign writes are simply absent until the partition heals (grow-only + LWW means healing is a deterministic re-merge, no rollback). The degrade is a per-call typed condition (the existing `CollectiveNotYetAvailable` / `CollectivePortError::Unreachable` surfaces) routed through a NEW **automatic Collective→Private/Shared downgrade router** — **never a global halt**, and Private/Shared tiers are unaffected. Degrade is **fail-closed on region identity**: a region under partition must never serve foreign-region data to satisfy a Collective read (that would be the transparent-replication failure §2 forbids). This is proven on a **real** partition (real severed transport after real propagation), not a mocked `Unreachable`.

### 6. Placement — out of kernel, one authorized bounded kernel touch

Replication + the timestamp-aware merge + re-attestation orchestration + the downgrade router live in **`maos-loom-lite`**; verification + re-signing + `build_tree_from_leaves` live in **`maos-audit`**; the region primitives are in `maos-domain` (pure) + `maos-audit` (crypto). They surface to the kernel **only** through the existing `CollectiveMemoryPort` seam (ADR-006/ADR-041).

The kernel touch is **authorized and bounded** (party-mode 2026-07-02, Winston FLAG): a single, compile-gated **`WriteEntryPoint::CrossRegionReadmit { source_region, source_log_ref }`** variant. `ReplayApply` is **not** reused — it is ADR-028 audit-bundle-replay provenance and carries no `source_log_ref`; overloading it is the category error the exhaustive **no-wildcard** `WriteEntryPoint` match (`write_entry_point.rs:25-58`, the AC-9 type-guard) exists to catch. The kernel **names and type-guards re-admit provenance** (region *attribution*, an authz invariant — not data-residency; the collective tier is replicated across regions by design) and nothing more: `enforce_region` (`:69-86`) is generic over `source_region()` → **0-LOC** there; the additive `CollectiveMemoryPort` re-admit param carries `source_region + source_log_ref` (content-free); all cryptographic verification stays in `maos-audit`, all merge/replication in `maos-loom-lite`. **Re-pin `kernel-core-baseline.toml` 22964 → ~22980** (+≤16 LOC), the surface named in HISTORY, tracked separately from the WASM ADR-038 budget. Any kernel-core churn outside that named surface is a finding.

### 7. Origin provenance ≠ authorization provenance — the dropped-audit-orphan (surfaced, not laundered)

Because `verify_and_audit` is **fire-and-forget and droppable** (`record_drop()`) while `port.write` durably persists and replicates (§Code-grounding), a row can converge and re-attest with its **authorization**-audit frame never having landed. The `CrossRegionReplicationBundle` establishes **provenance-of-origin** (which region signed these bytes — audit-frame-independent, and it holds); it does **NOT** establish **provenance-of-authorization** (that a capability check passed *and left a record*). This story introduces the re-attest+converge capability that could otherwise silently upgrade an audit-orphan to apparent-clean ("an audit-orphan wearing a green badge"), so **this story owns the tripwire that it doesn't**: reconciliation counts "row present, authorization-audit absent" as an observable state and never rolls it into a clean "converged" total. No claim anywhere — AC, gate, or doc — may assert the bundle establishes authorization provenance.

## Alternatives considered and rejected

- **Raft / CP quorum across regions** — rejected (§3): incompatible with the region weld, operator-local sovereignty, and AP-degrade; and moot (no CP code exists).
- **Transparent row replication (copy the Postgres rows / logical replication)** — rejected (§2): cryptographically fails closed under the 9.4b weld; loses provenance and auditability.
- **Cross the TL frames and reuse the 10.4b frame oracle** — rejected 2026-07-02 (§Code-grounding correction 2): `collective_write` does not anchor row content into a TL frame; the only TL frame is a droppable, content-free `CapabilityInvocation`. Making collective writes content-anchor to the TL would be a significant new kernel+audit change, would blow the +16 LOC ceiling, would drag replication crypto into the kernel against §6 placement, and would make the append-only TL a **second copy of the KV state**. Anchor the trust (the signing key), not the bytes.
- **Vector-clock / multi-value register CRDT** — rejected for v2.0: a timestamp-ordered LWW-register + grow-only-set is sufficient for the collective-memory access pattern and reuses the existing target-tuple keyspace; multi-value conflict surfacing adds resolution UX with no journey demand.
- **Keep the current blind LWW** — rejected: unconditional overwrite is not convergent across regions (final state depends on arrival order); a source-timestamp total order is required for the CRDT property.
- **Region in the UNIQUE key** — rejected: cross-region rows for the same logical key must collide and merge, or the CRDT never converges (two immortal rows per key).
- **Host replication/re-attestation in `maos-kernel-core`** — rejected: verification belongs in `maos-audit` (where the keys are) and replication in `maos-loom-lite` (where the store is), per ADR-006/ADR-041 and the ADR-038 ceiling. The kernel names provenance only.

## Consequences

- **No transparent replication anywhere**; every cross-region row is re-attested and provenance-stamped — auditable by construction, consistent with the 9.4b weld rather than fighting it.
- **The 10.4b oracle discipline is reused** (canonical-leaf + Merkle + payload + row-count, independent per-region re-derivation) but re-pointed at the KV rows via a NEW `canonical_kv_leaf`; `build_tree_from_frame_ids` generalizes to `build_tree_from_leaves`.
- **The blind LWW becomes source-timestamp-aware** and **two additive columns** (`source_region`, `source_ts`) land on `collective_memory` (UNIQUE unchanged); `source_log_ref` gains a cross-region meaning `{source_region, merkle_root}`.
- **Kernel-core takes one authorized bounded delta** — `WriteEntryPoint::CrossRegionReadmit` — re-pin 22964→~22980, FLAG-Winston, named surface.
- **Region-identity reflex** (Epic-11 §9): the count gate over propagated rows cryptographically verifies each row's source-region identity (Ed25519 under `derive_region_pubkey(source_region)`), not merely counts — the analogue of the language/form-identity reflex. A same-region self-comparison is rejected as a vacuous tautology.
- **Origin ≠ authorization**: audit-orphans (dropped `verify_and_audit`) are surfaced by reconciliation, never laundered to apparent-clean.
- **AP-degrade is a release-class behavior**, proven-red on a real partition (not a mocked unreachable).

## Gate

Binding at **Story 11.2a** (binding-v2.0 **after** all five gate legs are proven red→green — do NOT flip while any leg is unproven):

- **Timestamp-aware CRDT convergence.** Reorder-independence proven-red over a fixture containing a key collision where a *lower*-`source_ts` write arrives last; source-timestamp preserved across apply (not re-minted).
- **Mediated re-attestation proven-red.** A foreign-region row *copied* (not re-attested) fails closed at `verify_bundle`; a *re-attested* row carries destination-key acceptance + dereferenceable `source_log_ref` provenance. No transparent-replication path exists; no AEAD introduced.
- **Independent convergence oracle over KV rows.** Two regions declared converged only when the `canonical_kv_leaf` + Merkle + payload + row-count set matches under independent, codec-independent per-region re-derivation. A planted single-byte divergence is caught by the payload oracle (proven-red); a canonicalizer field-coverage proven-red (region/ts/value-only diffs → distinct leaves; boundary-shift no-collision).
- **Region-identity reflex** over propagated rows (source-region identity verified per row, not counted); forge negative-control moves the converged count; single-region loopback rejected.
- **Dropped-audit-orphan** surfaced, not laundered (SHIP-BLOCKER if a converged row cannot be distinguished from an audit-orphan).
- **AP-local-degrade proven-red** on a real partition: Collective degrades to Private/Shared, no global halt, no foreign-region data served.
- **Kernel-core abi-diff proven-red** — the single named `WriteEntryPoint::CrossRegionReadmit` arm with a HISTORY re-pin to ~22980; dependency closure excludes the Postgres crates.
- One `check-cross-region-consensus` gate, one `{ v1_0 = advisory, v1_5 = advisory, v2_0 = blocking }` disposition, **five independently-falsifiable legs** (`reattestation-mediated`, `convergence-oracle`, `region-identity`, `ap-degrade`, `kernel-abi-diff`); §A7.5 WOULD-HAVE-BLOCKED banner in the advisory window; absent/unmeasured → BLOCK@v2.0.
- Registered in `docs/adr/index.md`.
