# I4: Every approval captures intent, not just decision

See Architecture §3.2 for the full invariant definition and rationale.

## Enforcement Mechanism (v0.1-α type codification)

Type-level codification lives at `crates/maos-domain/src/invariants/i4.rs`:
the `InvariantI4` marker type anchors I4 in the type system. Runtime enforcement
ships in future stories per Architecture §3.2.1; at v0.1-α the type codification is
the structural enforcement anchor.

See Story 1a.1 for the type-codification rationale; Architecture §3.2 + §3.2.1
for the full enforcement matrix.

## v0.1-β runtime anchor

Story 1b.1 promotes I4 from structural type codification to runtime enforcement.
- `TransparencyLogAdapter::insert_approval_decision` writes to a DISTINCT SQLite table.
- `approval_decision_log` table has no foreign key into `transparency_log` (schema-level independence).
