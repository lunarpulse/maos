# I10: Every Spirit lifecycle transition is journaled

See Architecture §3.2 for the full invariant definition and rationale.

## Enforcement Mechanism (v0.1-α type codification)

Type-level codification lives at `crates/maos-domain/src/invariants/i10.rs`:
the `InvariantI10` marker type anchors I10 in the type system. Runtime enforcement
ships in future stories per Architecture §3.2.1; at v0.1-α the type codification is
the structural enforcement anchor.

See Story 1a.1 for the type-codification rationale; Architecture §3.2 + §3.2.1
for the full enforcement matrix.

## v0.1-β runtime anchor

Story 1b.1 promotes I10 from structural type codification to runtime enforcement.
- `JournalAdapter::append_transition` writes NDJSON + flushes + fsync per transition.
- `JournalAdapter::recover_in_flight` rehydrates last-known state per Spirit on cold boot.
- Raw file chosen over SQLite for deterministic <1ms P99 latency (NFR-Rel-8).
- Runtime body: `crates/maos-kernel-core/src/journal/mod.rs`
