# MAOS v1.0.0-rc.1 — release notes (release candidate)

Every statement below is traced to a file in this repository. "Hosted" means a GitHub Actions run whose id
is cited; nothing here was verified on a stable performance runner, a signed tag, or production keys.

## 1. What this candidate is

`v1.0.0-rc.1` is a **release candidate** for `v1.0.0`. It is a pre-release (GitHub `prerelease: true`,
never `latest`) and comes after the `v0.x` alpha lineage (`v0.1.0-alpha.1` was the only alpha tag cut,
`sprint-status.yaml` `ops-first-signed-tag`). It is evidence, not a promise: **the release candidate starts no LTS
clock**. The 1-year LTS commitment (NFR-Maint-6) starts at the `v1.0.0` (GA) tag commit only
([`lts-policy.md`](lts-policy.md)). Tagging is **operator policy**: only the key holder pushes the tag and no agent
tags, signs or publishes. This is a policy, not an enforced control: a pushed accepted tag triggers artifact signing
with the key held by CI, no Git tag signature is verified, and protecting the `release` environment (required
reviewers) is **UNCLAIMED** (boundary 6; [`tag-procedure.md`](tag-procedure.md),
[`decisions-2026-11-12.md`](decisions-2026-11-12.md)).

### Operator ruling of 2026-11-12 (what this release does not do)

**No external penetration test (NFR-Sec-7) was performed and no ECCN determination (NFR-Comp-1) was made.**
Assurance is AI-agent review plus the hermetic CI proof only. **Neither NFR is claimed met.** The WASM engine
stays off by default (`RELEASE-HOLDS.md`, "Standing mitigations"). Source: `RELEASE-HOLDS.md` "Claim
boundaries — Holds 1–2", `decisions-2026-11-12.md`.

Labels read by `xtask check-rc-readiness` (each alone on its line, verbatim):

Perf verdicts: ABSENT
Release environment protection: NOT PROVISIONED

- `Perf verdicts: ABSENT`: the stable-runner timing claim is withdrawn; no NFR-Perf timing figure was measured
  on a stable runner (see boundary table, `ops-stable-perf-runner`).
- `Release environment protection: NOT PROVISIONED`: the GitHub `release` environment is absent (read with `gh`
  on 2026-11-12, `decisions-2026-11-12.md`); required reviewers, tag restrictions and self-review prevention are
  not configured.

### T3 fuzz chain

The T3 fuzz chain (`fuzz-prerelease`, aggregate >= 86,400 libFuzzer worker-seconds per target, five serial
links; `cpu_seconds` is the sum over workers, not wall-clock) is dispatched at the candidate SHA and enforced by
`check-release-precondition --fuzz-ledger`; the release job refuses a SHA without a complete chain. The run id and
result are recorded in the post-tag record commit. No claim of fuzz completion is made in these notes.

## 6. How to verify

```bash
maos --version                                   # reports the workspace version of the build
cargo run --locked -p xtask -- check-rc-readiness --tag v1.0.0-rc.1 --json
cargo run --locked -p xtask -- check-release-precondition --help   # CI-evidence half: aggregate, T3 fuzz chain, perf verdicts
```

- `check-rc-readiness` reads committed files only (version, STABILITY.md, `20-*` story states, provisioning
  rows, these notes, `deny.toml` vs `deferred-work.md`). It never tags, signs or fetches.
- The CI-evidence half and the exact-SHA fuzz chain are `check-release-precondition`
  ([`tag-procedure.md`](tag-procedure.md) steps 2-3).
- Verifying release artifacts and signatures: [`docs/runbooks/release-signing.md`](../runbooks/release-signing.md).
- LTS rule: [`lts-policy.md`](lts-policy.md); STABILITY contract: [`STABILITY.md`](../../STABILITY.md).
