# Manifest 스키마 v2 (N-1 지원)

스키마 v2는 Stories 6.2, 6.4, 6.5에 걸쳐 들어온 네 가지 추가 섹션을 추적하기 위해 Epic 6(소급 2026-05-28)에서 올려졌습니다.

## 상태

**지원(N-1).** v2 manifest는 문서화된 저하와 함께 허용됩니다: (v3에서 추가된) `[model_provenance]` 섹션은 `#[serde(default)]`로 기본값 처리되며 kernel이 `WARN` 수준 저하 알림을 내보냅니다.

## v1 대비 추가

| 섹션 | Story | 설명 |
|---------|-------|-------------|
| `[[cli_wrapper]]` | 6.2 | CLI 래퍼 Spirit 선언(`command`, `output_shape_version`, `recovery_policy`, `posture`, `shutdown_signal`) |
| `[[schedule]]` | 6.4 | 스케줄된 훅 발화(`id`, `cadence`, `rate_limit_per_hour`, `compliance_claim_ref_hex`, `side_effect_scopes`, `payload_b64`) |
| `[[gateway]]` | 6.5 | 외부 메시징 게이트웨이(`id`, `type`, `auth_secret_ref`, `inbound_routing`) |
| `ConsentEnvelope` 확장 | 6.4 | 동의 봉투(consent envelope) 형태에 `intent_class` + `valid_until_ns` |

네 가지 추가는 모두 TOML/serde 계층에서 와이어 호환됩니다. 스키마 v2의 kernel은 v1 기준으로 작성된 manifest도 허용합니다(N-1 지원 하한선).

## v3로 마이그레이션

v2 manifest를 v3로 업그레이드하려면 선택적인 `[model_provenance]` 섹션을 추가하세요. 필드 상세 내용은 [v3 참조](./v3)를, 절차는 [마이그레이션 가이드](/migrate/)를 참조하세요.

## 예시

```toml
manifest_schema_version = 2

[class]
name = "scheduled-reporter"
version = "1.0.0"
min_substrate_version = "0.3.0"
trust_tier = "sandboxed"
description = "A Spirit with scheduled reporting and a Telegram gateway."

[author]
name = "Ops Team"

[budget]
context_window_size = 8192
time_cap_seconds = 600

[[schedule]]
id = "hourly-check"
cadence = 3600
rate_limit_per_hour = 1
side_effect_scopes = []

[[gateway]]
id = "telegram-alerts"
type = "telegram"
auth_secret_ref = "secret:telegram:bot-token-prod"
inbound_allowlist = ["chat_id:123456789"]
outbound_allowlist = ["chat_id:123456789"]
```
