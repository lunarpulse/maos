# Manifest 스키마 v3 (현재)

스키마 v3는 현재 manifest 버전으로, `[model_provenance]` 섹션을 추가하기 위해 Story 9.4b AC-6(2026-06-15)에서 올려졌습니다. 권위 있는 상수는 `crates/maos-spirit-abi/src/lib.rs`의 `MANIFEST_SCHEMA_VERSION = 3`입니다.

모든 v3 추가는 와이어 호환됩니다: `[model_provenance]` 섹션은 읽기 시 선택 사항이므로, v3의 kernel은 여전히 v2 manifest를 허용합니다(N-1 지원 하한선).

---

## `[class]` — Spirit 신원

`[class]` 섹션은 Spirit의 신원, 버전, 신뢰 자세(trust posture)를 선언합니다.

| 필드 | 타입 | 필수 | 설명 |
|-------|------|----------|-------------|
| `name` | `string` | Yes | Spirit 이름. 비어 있으면 안 됩니다. |
| `version` | `string` | Yes | Spirit 버전(semver). |
| `min_substrate_version` | `string` | Yes | 필요한 최소 MAOS kernel 버전. |
| `manifest_schema_version` | `u32` | Yes | 이 스키마에서는 `3`이어야 합니다. |
| `trust_tier` | `string` | Yes | trust tier — `sandboxed`, `trusted`, 또는 `privileged`. |
| `description` | `string` | Yes | 사람이 읽을 수 있는 설명. |
| `abi` | `string` | Yes | ABI 버전 문자열. |
| `forms` | `string[]` | Yes | Spirit 폼 — 예: `["subprocess"]`. |

### 예시

```toml
[class]
name = "hello-spirit"
version = "1.2.0"
min_substrate_version = "0.5.0"
manifest_schema_version = 3
trust_tier = "sandboxed"
description = "A greeting Spirit that responds to prompts."
abi = "0.5.0"
forms = ["subprocess"]
```

## `[budget]` — 리소스 한도

`[budget]` 섹션은 kernel이 시행하는 훅당 리소스 예산을 선언합니다.

| 필드 | 타입 | 필수 | 범위 | 설명 |
|-------|------|----------|-------|-------------|
| `context_window_size` | `u32` | Yes | > 0 | 토큰 단위 최대 컨텍스트 윈도우 크기. |
| `time_cap_seconds` | `u32` | Yes | 1–86400 | 훅 호출당 최대 경과(wall-clock) 시간(1초 ~ 1일). |

### 예시

```toml
[budget]
context_window_size = 8192
time_cap_seconds = 300
```

## `[[cli_wrapper]]` — CLI 래퍼 Spirits (Story 6.2)

`[[cli_wrapper]]` 섹션은 이 Spirit이 네이티브 Rust Spirit ABI 대신 외부 CLI 바이너리(예: `claude`, `opencode`, `gemini-cli`)를 감싼다고 선언합니다. manifest는 `[[cli_wrapper]]` 또는 네이티브 훅 중 하나를 가집니다 — 두 모드는 어드미션 시점에 상호 배타적입니다.

| 필드 | 타입 | 필수 | 설명 |
|-------|------|----------|-------------|
| `command` | `string` | Yes | CLI 바이너리 경로. `which` 또는 절대 경로로 해결됩니다. |
| `argv_prefix` | `string[]` | No | 모든 호출 앞에 붙는 인자(예: `claude code`의 `["code"]`). 기본값: `[]`. |
| `output_shape_version` | `string` | Yes | 선언된 출력 형태 버전(semver). kernel이 어드미션 시점에 단언합니다. |
| `skill_bundle` | `string[]` | No | 페르소나 + `maos-bridge` 스킬 번들 참조. 기본값: `[]`. |
| `recovery_policy` | `string` | No | 서브프로세스 충돌 시 복구 정책. 값 중 하나: `respawn_with_context`(기본값), `respawn_fresh`, `escalate`. |
| `posture.stdio_shape` | `string` | Yes | 와이어 stdio 형태: `ndjson_over_stdio`, `json_rpc_over_stdio`, 또는 `raw`. |
| `posture.control_channel` | `string` | Yes | 제어 채널 메커니즘: `signal`(Linux/macOS 시그널). |
| `posture.shutdown_signal` | `string` | No | `unload` 시 보내는 시그널(예: `SIGTERM`, `SIGINT`). 기본값: 없음(kernel 기본값). |

### 예시

```toml
[[cli_wrapper]]
command = "claude"
argv_prefix = ["code"]
output_shape_version = "1.0.0"
skill_bundle = ["cli-wrapper-template:claude:1.0.0"]
recovery_policy = "respawn_with_context"

[cli_wrapper.posture]
stdio_shape = "ndjson_over_stdio"
control_channel = "signal"
shutdown_signal = "SIGTERM"
```

## `[[schedule]]` — 스케줄된 훅 발화 (Story 6.4)

`[[schedule]]` 섹션은 하나 이상의 스케줄된 발화를 선언합니다. 각 항목은 불투명한 페이로드와 함께 선언된 케이던스로 `on_schedule` 훅을 발화합니다.

| 필드 | 타입 | 필수 | 범위 | 설명 |
|-------|------|----------|-------|-------------|
| `id` | `string` | Yes | `[a-zA-Z0-9_-]{1,64}` | 이 manifest 내 고유 스케줄 식별자. |
| `cadence` | `u32` | Yes | 1–604800 | 초 단위 발화 케이던스(1초 ~ 1주). |
| `rate_limit_per_hour` | `u32` | Yes | 1–3600 | 케이던스와 무관하게 시간당 최대 발화 수. |
| `compliance_claim_ref_hex` | `string` | No | 16진수 64자 | ComplianceClaim 봉투 참조(32바이트 16진수). Story 7.3이 암호화 검증을 도입합니다. |
| `side_effect_scopes` | `string[]` | Yes | — | 부작용(side-effect) 허용 목록 — 발화별 토큰에 부여되는 역량 `Scope` 이름. 빈 값 = 메모리 전용. |
| `payload_b64` | `string` | No | — | `on_schedule`에 전달되는 Base64 인코딩 불투명 페이로드. 없으면 빈 값. |

### 예시

```toml
[[schedule]]
id = "daily-report"
cadence = 86400
rate_limit_per_hour = 1
side_effect_scopes = ["FileRead", "FileWrite"]
payload_b64 = "eyJyZXBvcnQiOiJkYWlseSJ9"

[[schedule]]
id = "health-ping"
cadence = 60
rate_limit_per_hour = 60
side_effect_scopes = []
```

## `[[gateway]]` — 외부 메시징 게이트웨이 (Story 6.5)

`[[gateway]]` 섹션은 Spirit이 연결하는 외부 메시징 게이트웨이(Telegram, Slack, Discord 등)를 선언합니다. kernel이 게이트웨이 라이프사이클을 관리하고, Spirit이 인바운드/아웃바운드 메시지를 처리합니다.

| 필드 | 타입 | 필수 | 범위/형식 | 설명 |
|-------|------|----------|--------------|-------------|
| `id` | `string` | Yes | `[a-zA-Z0-9_-]{1,64}` | 이 manifest 내 고유 게이트웨이 식별자. |
| `type` | `string` | Yes | `telegram`, `slack`, `discord`, `signal`, `email`, `echo` | 게이트웨이 프로토콜 타입. |
| `auth_secret_ref` | `string` | Yes | `^secret:[a-z][a-z0-9_-]*:[A-Za-z0-9_-]{1,256}$` | 시크릿 매니저의 시크릿 참조(주소 전용 — kernel은 시크릿 내용을 해석하지 않습니다). |
| `inbound_allowlist` | `string[]` | No | — | 인바운드 메시지 전송이 허용된 외부 식별자. 빈 값 = 인바운드 수락 안 함. |
| `outbound_allowlist` | `string[]` | No | — | 아웃바운드 전송이 허용된 외부 식별자. 빈 값 = 아웃바운드 없음. |
| `on_inbound` | `string` | No | — | 인바운드 메시지 시 호출되는 훅. 기본값: `on_frame`. |
| `reconnect_backoff_secs` | `u32` | No | 1–3600 | 초 단위 초기 재연결 지연. 지수 백오프 상한은 5분. 기본값: `5`. |
| `max_message_bytes` | `u32` | No | 256–1048576 | 메시지당 바이트 크기 상한. 기본값: `4096`. |

### 예시

```toml
[[gateway]]
id = "telegram-ops"
type = "telegram"
auth_secret_ref = "secret:telegram:bot-token-prod"
inbound_allowlist = ["chat_id:123456789"]
outbound_allowlist = ["chat_id:123456789"]
on_inbound = "on_frame"
reconnect_backoff_secs = 5
max_message_bytes = 4096

[[gateway]]
id = "slack-alerts"
type = "slack"
auth_secret_ref = "secret:slack:webhook-url"
outbound_allowlist = ["channel:C0123ALERTS"]
```

## `[model_provenance]` — 모델 출처 (Story 9.4b)

`[model_provenance]` 섹션은 커버드 모델(covered model)을 감싸거나 내장한 Spirit의 AI 모델 출처를 선언합니다. 스키마 v3에서 추가되었습니다. **선택 사항** — v3 이전 manifest와 모델 커버리지가 없는 Spirit은 이를 생략합니다.

어드미션 시점에 kernel은 섹션 형태를 검증하고, `training_data_lineage`에 역방향-DNS 제약을 시행하며(자유 텍스트 불가 — D5), 운영자 구성 윈도우에 대해 유효기간(staleness)을 검사하고, 출처 트리플에 대한 콘텐츠 해시를 담아 거버넌스 이벤트를 Transparency Log로 내보냅니다.

| 필드 | 타입 | 필수 | 제약 | 설명 |
|-------|------|----------|------------|-------------|
| `covered_model_id` | `string` | Yes | 비어 있으면 안 됨 | 커버드 모델 식별자(예: `anthropic.claude-opus-4-8`). |
| `training_data_lineage` | `string[]` | Yes | 역방향-DNS 전용 | 구조화된 출처(lineage) 참조. 각 항목은 유효한 역방향-DNS 라벨이어야 합니다(`[a-z0-9-]` 세그먼트, 점으로 구분된 라벨 둘 이상). 자유 텍스트는 거부됩니다. |
| `last_eval_timestamp` | `string` | Yes | RFC 3339 UTC | 마지막 모델 평가 타임스탬프(예: `2026-06-01T00:00:00Z`). 유효기간(staleness) 검사에 사용됩니다. |

### 어드미션 정책

운영자는 환경 변수로 모델 출처 시행을 제어합니다:

| 변수 | 기본값 | 설명 |
|----------|---------|-------------|
| `MAOS_REQUIRE_MODEL_PROVENANCE` | `false` | `true`이면 `[model_provenance]`가 없는 Spirit을 `EModelProvenanceMissing`으로 거부합니다. |
| `MAOS_MODEL_PROVENANCE_MAX_AGE_SECS` | `0` (비활성) | `last_eval_timestamp`의 최대 허용 기간(초). `0`은 유효기간 검사를 비활성화합니다. |

### 예시

```toml
[model_provenance]
covered_model_id = "anthropic.claude-opus-4-8"
training_data_lineage = [
  "lineage.public-web.cc-2024",
  "lineage.curated.textbooks-2024"
]
last_eval_timestamp = "2026-06-01T00:00:00Z"
```

## `deployment_operator_id`와 `provider_history` (Story 9.4b)

이들은 Story 9.4b에서 추가된 **런타임 구성물**로, manifest 필드가 아닙니다. 거버넌스와 어드미션 표면에 참여합니다.

### `deployment_operator_id`

Transparency Log로 내보내지는 모든 모델 출처 거버넌스 이벤트에 찍히는 상수 식별자. 다음으로 구성됩니다:

```bash
export MAOS_DEPLOYMENT_OPERATOR_ID="acme-corp.maos.prod-us-east"
```

기본값은 `maos.deployment.operator.default`입니다. 이것이 v1.0에서 레코드별 테넌시 예약이 되는 **유일한** 지속 레코드입니다 — 일반적인 레코드별 테넌트 필드는 존재하지 않습니다(D7).

### `provider_history`

kernel의 `SecurityManagerAdapter`에 있는 경계 있는(bounded) 인메모리 트래커로, 같은 `spirit_id`에 대한 연속된 `admit_spirit` 호출 간 프로바이더 전환을 감지합니다. 4096 항목으로 경계 지어지며 초과 시 가장 오래된 항목을 제거하는 정책을 따릅니다(Story 9.4b AC-8). 전환이 감지되면 `ProviderSwitched` 라이프사이클 이벤트가 저널로 내보내집니다.
