# Manifest 스키마 v5 (현재)

스키마 v5는 `wasm-component` form과 필수 `[class].artifact` 경로를 추가합니다. 권위 있는 값은 `maos-spirit-abi`의 `MANIFEST_SCHEMA_VERSION = 5`입니다.

## WASM component class 선언

WASM component Spirit는 정확히 하나의 form인 `wasm-component`와 상대 `.wasm` artifact 경로를 선언합니다. 경로는 launch 경로가 manifest 디렉터리를 기준으로 해석하며, 스키마 검증은 artifact를 열지 않습니다.

```toml
[class]
name = "third-party-component"
version = "0.1.0"
abi = "1.0"
manifest_schema_version = 5
min_substrate_version = "0.1.0"
forms = ["wasm-component"]
artifact = "dist/spirit.wasm"
trust_tier = "local"
description = "A component-model Spirit"

[sandbox]
tier = "T2"
```

`wasm-component`는 다른 form과 결합할 수 없습니다. schema v5와 `artifact`가 필요하며, 다른 모든 form은 `artifact`를 금지합니다. artifact 경로는 비어 있지 않은 상대 경로여야 하고, 최대 4096바이트이며, `..` segment가 없고 `.wasm`으로 끝나야 합니다.

## Admission 경계

WASM-component Spirit는 sandbox tier `T2`를 선언합니다. 기본 MAOS binary는 전체 manifest를 검증한 뒤 Export Hold 2가 `wasm-host` feature를 비활성화하는 동안 `wasm_engine_off`로 component를 거부합니다. `wasm-host` build는 17-3c가 launch 경로를 제공할 때까지 `wasm_launch_not_built`를 보고합니다.

schema v4 manifest는 N-1 window에서 계속 허용됩니다. v4 manifest는 `wasm-component`를 선언할 수 없습니다.
