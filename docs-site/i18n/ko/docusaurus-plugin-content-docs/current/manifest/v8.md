# Manifest 스키마 v8

Story 21-9의 스키마 8(D-21-9-02 A)은 `21-9-manifest-schema-8`로 비준되었습니다.
`ABI_VERSION`과 manifest 버전 하한은 모두 `1`로 유지됩니다.
게스트 와이어 형식은 바뀌지 않으며 새 capability `Scope` variant도 추가되지 않습니다.

## 텔레메트리 구독

구독하려면 기존 manifest의 `[class].manifest_schema_version`을 `8`로 설정하고
`[lifecycle].enabled_hooks` 목록에 `on_telemetry_event`를 명시한 뒤 아래 테이블을 추가합니다.
Spirit에 필요한 다른 훅도 목록에 그대로 둡니다.

```toml
[lifecycle.telemetry]
scope = "scalar.tap.*"
time_cap_seconds = 5
```

- `scope`는 정확히 `"scalar.tap.*"`여야 합니다. 게스트 capability 토큰이 아니라 호스트 구독을 가리킵니다.
- `time_cap_seconds`는 1 이상 5 이하의 정수이며 `[budget].time_cap_seconds`를 초과할 수 없습니다.
  `[budget]`이 없으면 전체 상한은 30초입니다. 전달 시간은 선언된 텔레메트리 상한과
  유효한 전체 상한의 95% 중 작은 값으로 제한됩니다.
- 두 필드 모두 필수이며 알 수 없는 필드는 거부됩니다.

새 `governance:telemetry-subscription:granted` 감사 이벤트에는 실제 전달 시간 상한이
`effective_wall_ms`로 기록됩니다. 이전 허가 이벤트와 해지 이벤트에는 이 필드가 없습니다.

최초 어드미션과 후속 버전 로드 시 테이블 없이 훅만 나열하거나, 훅을 나열하지 않고 테이블만
선언하거나, 잘못된 테이블을 선언하면 거부됩니다. 스키마 8 미만에서는 훅의 명시적 나열이나
테이블 중 하나라도 있으면 경고만 내고 무시하는 대신 거부합니다. 둘 다 선언하지 않은 스키마 1–7은
계속 지원합니다. 훅 목록을 생략하거나 비워 두어도 텔레메트리를 구독하지 않습니다.

이 선언은 기존 형태 및 클래스 정책을 변경하지 않습니다. `wasm-component`는 `lifecycle`
export를 통해 이 훅을 받으며, 컴파일 내장 Spirit 중에서는 `observer` 클래스만 대상이 됩니다.
`[cli_wrapper]` Worker는 Spirit 형태가 아닙니다. [라이프사이클 훅](../cookbook/lifecycle-hooks)을 참조하세요.
