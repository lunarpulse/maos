# Manifest 스키마 v9

스키마 9는 Story 22-9(D-22-9-04 A)에서 `22-9-manifest-schema-9`로 제안되었으며
운영자가 아직 비준하지 않았습니다. `ABI_VERSION`과 manifest 버전 하한은 모두 `1`로 유지됩니다.
게스트 와이어 형식은 바뀌지 않으며 새 capability `Scope` variant도 추가되지 않습니다.

## consent 선언

`[consent.recall]`을 선언하는 발신 Spirit은 `[class].manifest_schema_version`을
`9` 이상으로 설정합니다:

```toml
[consent.recall]
peer-b = "header_only"
peer-c = "withheld"
```

- 스키마 9 미만에서 `[consent]` table은 경고만 내고 로드하지 않고 어드미션에서
  타입화된 `manifest_section_invalid`로 거부됩니다. `[consent]`를 선언하지 않는 스키마 1–8은
  계속 지원되며 제한이 없습니다.
- 각 수신자 id는 Spirit이 어드미션될 때 Host가 알고 있는 id여야 합니다: 설치된
  패키지, host 파일의 cast 또는 topology의 구성원, 또는 이미 로드된 Spirit. 설치와 로드 순서는
  무관합니다. 그 밖의 id는 `consent_recipient_unknown`으로 거부되며 선언은 부분적으로 어드미션되지 않습니다.
- 부여 내용 자체는 [스키마 7](./v7#consent-recall)과 같습니다.

자동 되돌림(auto-revert)되는 핫스왑은 선행 Spirit의 선언을 scope 및 promotion 집합과 함께
복원합니다. [라이프사이클 훅](../cookbook/lifecycle-hooks)을 참조하세요.
