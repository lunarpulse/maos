# Manifest 스키마 v7

스키마 7은 [스키마 v6](./v6)에 선택적인 네 섹션을 추가합니다. 각 목록은 중복 없는 이름 1–32개이며 각 이름은 `[a-z0-9_.:-]`의 1–128바이트입니다. 알 수 없는 키는 거부합니다. 스키마 7 미만의 manifest는 여전히 지원되며 이 네 섹션은 경고와 함께 무시됩니다.

```toml
[skills]
uses = ["example-prerequisite"]

[explanation_shape]
required_fields = ["reason"]

[intent_promotion_set]
allowed = ["consult"]

[swap_invariants]
preserve = ["example-state"]
```

`skills.uses`는 정해진 검색 위치에서 발견되고 운영자가 이미 승인한 skill을 지정합니다. 각 skill의 필요 capability는 Spirit의 선언된 action에 포함되어야 합니다. Spirit이 검색 경로를 지정할 수는 없습니다. `intent_promotion_set`은 `TaskAssign`으로 전달되는 이전 distillate의 저장된 intent lineage를 제한합니다. 생략하면 기존 동작을 유지합니다.

`explanation_shape`는 검증 및 저널 기록되지만 **강제되지 않습니다**. 결정 프레임에 설명 본문이 없기 때문입니다. 커널 landing 전에는 `swap_invariants`도 검증 및 기록만 하며 후속 swap에서 검사하지 않습니다. 두 landing 사이에는 릴리스하지 않습니다. 이후 검사도 구조적 검사이며 상태 보존 증명은 아닙니다.

`governance:manifest-declaration` 행은 pid 발급 전에 정확한 manifest SHA-256, 서명된 설치 패키지의 검증된 publisher key(서명 없는 로컬 manifest는 null), 선언된 섹션을 기록합니다. 이는 **admission 증거가 아니라 선언**입니다. 이후 admission이 거부되면 선언 행은 남을 수 있고 거부는 별도로 기록됩니다. I2 저장 실패는 fail-stop입니다.

digest와 publisher는 콜론으로 구분한 소문자 16진수 네 자리 그룹 16개로
인코딩됩니다. `maos_domain::governance::decode_declaration_bytes`로 정확한
32바이트를 복원하며 잘못된 인코딩은 거부합니다.

추가된 `maos:spirit@2.3.0`의 `skills` import는 `author(document)`와 `propose(target-id, target-version, diff)`를 제공합니다. 두 함수는 `handle-frame` 안에서만 호출할 수 있으며 host가 pid, class 및 telemetry를 고정합니다. 오류는 `capability-denied`, `refused(code)`, `unavailable`입니다. skill 콘텐츠 import는 없고 승인은 운영자만 할 수 있습니다.
