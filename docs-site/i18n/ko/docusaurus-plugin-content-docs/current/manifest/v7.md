# Manifest 스키마 v7

스키마 7은 [스키마 v6](./v6)에 선택적인 네 섹션을 추가합니다. 각 목록은 중복 없는 이름 1–32개이며 각 이름은 `[a-z0-9_.:-]`의 1–128바이트입니다. 알 수 없는 키는 거부합니다. 스키마 7 미만의 manifest는 여전히 지원되며 이 네 섹션은 경고와 함께 무시됩니다.

```toml
[skills]
uses = ["example-prerequisite"]

[explanation_shape]
required_fields = ["reason"]

[intent_promotion_set]
allowed = ["standard"]

[swap_invariants]
preserve = ["example-state"]
```

`skills.uses`는 정해진 검색 위치에서 발견되고 운영자가 이미 승인한 skill을 지정합니다. 모든 검색 위치와 버전에서 발견된 같은 id의 모든 사본이 승인되어야 하며 각 사본의 필요 capability는 Spirit의 선언된 action에 포함되어야 합니다. Spirit이 검색 경로를 지정할 수는 없습니다. `intent_promotion_set`은 `TaskAssign`으로 전달되는 이전 distillate의 저장된 intent lineage를 제한합니다. 생략하면 기존 동작을 유지합니다. 허용 이름은 원본 transparency log의 intent 열과 일치하며 라우팅된 프레임은 `high`, `standard`, `readonly`를 사용합니다.

감사 증폭을 제한하기 위해 promotion 거부 기록은 bus당 초당 최대 한 건만 남깁니다. 표본에는 발신자, 수신자, frame, digest 및 사유가 포함되며 전체 거부 건수는 아닙니다.

감사 redactor가 기록된 식별자를 변경하지 않도록 비밀 접두사와 유사하거나 16진수 32자가 연속된 skill 식별자는 거부합니다.

`explanation_shape`는 검증 및 저널 기록되지만 **강제되지 않습니다**. 결정 프레임에 설명 본문이 없기 때문입니다. `swap_invariants`는 hot swap, `--policy migrator`, `--policy cold-swap`에서 강제됩니다. 선행 버전이 선언한 invariant를 후속 버전이 모두 선언하지 않으면 `409 swap_invariant_dropped`로 거부되며 첫 번째로 빠진 invariant를 알려 줍니다. 선행 버전은 계속 서비스합니다. hot swap과 migrator의 거부는 어떤 hook도 실행되기 전, 그리고 control block이 바뀌기 전에 kernel이 수행하며, 중단된 swap의 영수증에는 빠진 이름이 UTF-8 바이트의 콜론 구분 16진수(라벨 포함)로 기록됩니다. 비밀처럼 보이는 이름을 transparency log의 credential redactor가 지워 버리기 때문입니다. cold swap의 거부는 unload 전에 door가 수행합니다. 스키마 7 후속 버전의 `[swap_invariants]`가 잘못된 형식이면 "선언 없음"이 아니라 manifest 파싱 거부입니다. 후속 버전의 `[swap_invariants]`는 admission과 같이 스키마 7 이상에서만 읽으므로 스키마 7 미만의 후속 버전은 아무것도 선언하지 않은 것으로 보고 모두 빠뜨린 것으로 처리됩니다. 반대로 스키마 6 이하 manifest에 이 섹션이 있어도 무시되며(stderr 경고만 출력) 해당 invariant는 강제되지 않습니다. 이 검사는 구조적 검사이며 상태 보존 증명은 아닙니다.

`governance:manifest-declaration` 행은 `load_admit_start`를 통한 pid 발급 전에 정확한 manifest SHA-256, 서명된 설치 패키지의 검증된 publisher key(서명 없는 로컬 manifest는 null), 선언된 섹션을 기록합니다. 이 경로 밖의 내장 first-party root는 이 행을 생성하지 않습니다. 이는 **admission 증거가 아니라 선언**입니다. 이후 admission이 거부되면 선언 행은 남을 수 있고 거부는 별도로 기록됩니다. I2 저장 실패는 fail-stop입니다.

각 선언은 `outcome = "declared"`와 고유한 `attempt_id`를 가집니다. 같은 id의 후속 `governance:manifest-declaration-outcome` telemetry 행은 `admitted` 또는 `refused`를 기록합니다. admission 후 start 실패로 거부가 추가될 수도 있으며 결과가 없다는 것은 승인을 뜻하지 않습니다. skill 문서와 제안 diff는 각각 256 KiB 이하이며 작성자 class당 대기 중인 제출은 최대 64개입니다.

digest와 publisher는 콜론으로 구분한 소문자 16진수 네 자리 그룹 16개로
인코딩됩니다. `maos_domain::governance::decode_declaration_bytes`로 정확한
32바이트를 복원하며 잘못된 인코딩은 거부합니다.

추가된 `maos:spirit@2.3.0`의 `skills` import는 `author(document)`와 `propose(target-id, target-version, diff)`를 제공합니다. 두 함수는 `handle-frame` 안에서만 호출할 수 있으며 host가 pid, class 및 telemetry를 고정합니다. 오류는 `capability-denied`, `refused(code)`, `unavailable`입니다. skill 콘텐츠 import는 없고 승인은 운영자만 할 수 있습니다.
