# Manifest Schema v2 (N-1 Supported)

Schema v2 was bumped in Epic 6 (retro 2026-05-28) to track four additive sections landed across Stories 6.2, 6.4, and 6.5.

## Status

**Supported (N-1).** V2 manifests are admitted with documented degradation: the `[model_provenance]` section (added in v3) defaults via `#[serde(default)]` and the kernel emits a `WARN`-level degradation notice.

## Additions over v1

| Section | Story | Description |
|---------|-------|-------------|
| `[[cli_wrapper]]` | 6.2 | CLI wrapper Spirit declarations (`command`, `output_shape_version`, `recovery_policy`, `posture`, `shutdown_signal`) |
| `[[schedule]]` | 6.4 | Scheduled hook firing (`id`, `cadence`, `rate_limit_per_hour`, `compliance_claim_ref_hex`, `side_effect_scopes`, `payload_b64`) |
| `[[gateway]]` | 6.5 | External messaging gateways (`id`, `type`, `auth_secret_ref`, `inbound_routing`) |
| `ConsentEnvelope` extensions | 6.4 | `intent_class` + `valid_until_ns` on the consent envelope shape |

All four additions are wire-compatible at the TOML/serde layer. Kernels at schema v2 accept manifests authored against v1 (the N-1 supported floor).

## Migration to v3

To upgrade a v2 manifest to v3, add the optional `[model_provenance]` section. See the [v3 reference](./v3) for field details and the [migration guide](/migrate/).

## Example

```toml
manifest_schema_version = 2

[class]
name = "scheduled-reporter"
version = "1.0.0"
min_substrate_version = "0.3.0"
trust_tier = "sandboxed"
description = "A Spirit with scheduled reporting and a Telegram gateway."

[author]
name = "Ops Team"

[budget]
context_window_size = 8192
time_cap_seconds = 600

[[schedule]]
id = "hourly-check"
cadence = 3600
rate_limit_per_hour = 1
side_effect_scopes = []

[[gateway]]
id = "telegram-alerts"
type = "telegram"
auth_secret_ref = "secret:telegram:bot-token-prod"
inbound_allowlist = ["chat_id:123456789"]
outbound_allowlist = ["chat_id:123456789"]
```
