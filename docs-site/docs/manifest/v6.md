# Manifest Schema v6 (Current)

Schema v6 adds `[capabilities.required.skill]`. The authoritative constant is
`MANIFEST_SCHEMA_VERSION = 6` in `maos-spirit-abi`. All schema v5 declarations
remain supported; see [schema v5](./v5) for the other fields.

```toml
[class]
name = "researcher"
version = "0.5.0"
abi = "1.0"
manifest_schema_version = 6
min_substrate_version = "0.1.0"
forms = ["rust-inproc"]
trust_tier = "local"
description = "Native Researcher"

[capabilities.required.skill]
author_self = true
```

`author_self` is a boolean, defaults to `false`, and maps to
`Scope::SkillAuthorSelf`. Unknown keys and non-boolean values are refused.
Below schema v6 the entire table is degraded away and grants no skill authority.
Omitting the table also grants nothing.

This declaration authorizes capability-mediated submissions, not activation.
Every submitted skill or revision still requires operator admission. Policy,
context exhaustion and issuance quotas can refuse a declared capability. The
native Researcher port fixes the author identity and telemetry in the host;
a Spirit cannot name another pid or attach fabricated telemetry. WASM and
TypeScript do not acquire a skill-authoring import through this declaration.

Admitted skill discovery is not skill execution. Revisions are decision-only:
the opaque diff is not automatically applied. A revised document requires its
own submission and admission.
