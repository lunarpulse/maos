# Manifest Schema v8

Schema 8 was ratified for Story 21-9 (D-21-9-02 A) as `21-9-manifest-schema-8`.
`ABI_VERSION` and the manifest version floor both remain `1`.
There is no guest wire change and no new capability `Scope` variant.

## Subscribe to telemetry

In a listener's existing manifest, set `[class].manifest_schema_version` to `8`,
add `on_telemetry_event` to its explicit `[lifecycle].enabled_hooks` list, and
add the following table. Keep any other hook names the Spirit needs in the list.

```toml
[lifecycle.telemetry]
scope = "scalar.tap.*"
time_cap_seconds = 5
```

- `scope` must be the exact literal `"scalar.tap.*"`. It names the host
  subscription, not a guest capability token.
- `time_cap_seconds` must be an integer from 1 through 5 inclusive and cannot
  exceed `[budget].time_cap_seconds`. Without `[budget]`, the overall cap is
  30 seconds. The delivery limit is the smaller of the declared telemetry cap
  and 95% of the effective overall cap.
- Both fields are required; unknown fields are refused.

New `governance:telemetry-subscription:granted` audit events include the
enforced limit in `effective_wall_ms`. Older grants and revocations omit it.

Initial admission and successor loading reject a listing without a table, a
table without the listing, or an invalid table. Below schema 8, either an
explicit listing or a table causes refusal, not warning-level degradation.
Schemas 1–7 that declare neither remain supported. Omitting the hook list or
leaving it empty does not opt in to telemetry.

The declaration does not override the existing form and class policy: a
`wasm-component` receives the hook through its `lifecycle` export, and among
compiled-in Spirits only the `observer` class is eligible. A `[cli_wrapper]`
Worker is not a Spirit form. See [Lifecycle Hooks](../cookbook/lifecycle-hooks).
