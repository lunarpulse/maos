# Manifest Schema v3 (Current)

Schema v3 is the current manifest version, bumped in Story 9.4b AC-6 (2026-06-15) to add the `[model_provenance]` section. The authoritative constant is `MANIFEST_SCHEMA_VERSION = 3` in `crates/maos-spirit-abi/src/lib.rs`.

All v3 additions are wire-compatible: the `[model_provenance]` section is OPTIONAL on read, so kernels at v3 still admit v2 manifests (the N-1 supported floor).

---

## `[class]` — Spirit identity

The `[class]` section declares the Spirit's identity, version, and trust posture.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | `string` | Yes | Spirit name. Must be non-empty. |
| `version` | `string` | Yes | Spirit version (semver). |
| `min_substrate_version` | `string` | Yes | Minimum MAOS kernel version required. |
| `manifest_schema_version` | `u32` | Yes | Must be `3` for this schema. |
| `trust_tier` | `string` | Yes | Trust tier — `sandboxed`, `trusted`, or `privileged`. |
| `description` | `string` | Yes | Human-readable description. |
| `abi` | `string` | Yes | ABI version string. |
| `forms` | `string[]` | Yes | Spirit forms — e.g., `["subprocess"]`. |

### Example

```toml
[class]
name = "hello-spirit"
version = "1.2.0"
min_substrate_version = "0.5.0"
manifest_schema_version = 3
trust_tier = "sandboxed"
description = "A greeting Spirit that responds to prompts."
abi = "0.5.0"
forms = ["subprocess"]
```

## `[budget]` — Resource limits

The `[budget]` section declares per-hook resource budgets enforced by the kernel.

| Field | Type | Required | Range | Description |
|-------|------|----------|-------|-------------|
| `context_window_size` | `u32` | Yes | > 0 | Maximum context window size in tokens. |
| `time_cap_seconds` | `u32` | Yes | 1–86400 | Maximum wall-clock time per hook invocation (1 second to 1 day). |

### Example

```toml
[budget]
context_window_size = 8192
time_cap_seconds = 300
```

## `[[cli_wrapper]]` — CLI wrapper Spirits (Story 6.2)

The `[[cli_wrapper]]` section declares that this Spirit wraps an external CLI binary (e.g., `claude`, `opencode`, `gemini-cli`) instead of using the native Rust Spirit ABI. A manifest has either `[[cli_wrapper]]` or native hooks — the two modes are mutually exclusive at admission.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `command` | `string` | Yes | Path to the CLI binary. Resolved via `which` or as an absolute path. |
| `argv_prefix` | `string[]` | No | Arguments prepended to every invocation (e.g., `["code"]` for `claude code`). Default: `[]`. |
| `output_shape_version` | `string` | Yes | Declared output shape version (semver). Kernel asserts at admission. |
| `skill_bundle` | `string[]` | No | Persona + `maos-bridge` skill bundle references. Default: `[]`. |
| `recovery_policy` | `string` | No | Recovery policy on subprocess crash. One of: `respawn_with_context` (default), `respawn_fresh`, `escalate`. |
| `posture.stdio_shape` | `string` | Yes | On-wire stdio shape: `ndjson_over_stdio`, `json_rpc_over_stdio`, or `raw`. |
| `posture.control_channel` | `string` | Yes | Control-channel mechanism: `signal` (Linux/macOS signals). |
| `posture.shutdown_signal` | `string` | No | Signal sent on `unload` (e.g., `SIGTERM`, `SIGINT`). Default: none (kernel default). |

### Example

```toml
[[cli_wrapper]]
command = "claude"
argv_prefix = ["code"]
output_shape_version = "1.0.0"
skill_bundle = ["cli-wrapper-template:claude:1.0.0"]
recovery_policy = "respawn_with_context"

[cli_wrapper.posture]
stdio_shape = "ndjson_over_stdio"
control_channel = "signal"
shutdown_signal = "SIGTERM"
```

## `[[schedule]]` — Scheduled hook firing (Story 6.4)

The `[[schedule]]` section declares one or more scheduled firings. Each entry triggers the `on_schedule` hook at the declared cadence with an opaque payload.

| Field | Type | Required | Range | Description |
|-------|------|----------|-------|-------------|
| `id` | `string` | Yes | `[a-zA-Z0-9_-]{1,64}` | Unique schedule identifier within this manifest. |
| `cadence` | `u32` | Yes | 1–604800 | Firing cadence in seconds (1 second to 1 week). |
| `rate_limit_per_hour` | `u32` | Yes | 1–3600 | Maximum firings per hour regardless of cadence. |
| `compliance_claim_ref_hex` | `string` | No | 64 hex chars | ComplianceClaim envelope reference (32-byte hex). Story 7.3 lands cryptographic verify. |
| `side_effect_scopes` | `string[]` | Yes | — | Side-effect allowlist — capability `Scope` names granted to the per-firing token. Empty = memory-only. |
| `payload_b64` | `string` | No | — | Base64-encoded opaque payload delivered to `on_schedule`. Empty when absent. |

### Example

```toml
[[schedule]]
id = "daily-report"
cadence = 86400
rate_limit_per_hour = 1
side_effect_scopes = ["FileRead", "FileWrite"]
payload_b64 = "eyJyZXBvcnQiOiJkYWlseSJ9"

[[schedule]]
id = "health-ping"
cadence = 60
rate_limit_per_hour = 60
side_effect_scopes = []
```

## `[[gateway]]` — External messaging gateways (Story 6.5)

The `[[gateway]]` section declares external messaging gateways (Telegram, Slack, Discord, etc.) that the Spirit connects to. The kernel manages the gateway lifecycle; the Spirit handles inbound/outbound messages.

| Field | Type | Required | Range/Format | Description |
|-------|------|----------|--------------|-------------|
| `id` | `string` | Yes | `[a-zA-Z0-9_-]{1,64}` | Unique gateway identifier within this manifest. |
| `type` | `string` | Yes | `telegram`, `slack`, `discord`, `signal`, `email`, `echo` | Gateway protocol type. |
| `auth_secret_ref` | `string` | Yes | `^secret:[a-z][a-z0-9_-]*:[A-Za-z0-9_-]{1,256}$` | Reference to a secret in the secrets manager (address-only — the kernel does not interpret the secret content). |
| `inbound_allowlist` | `string[]` | No | — | External identifiers allowed to send inbound messages. Empty = no inbound accepted. |
| `outbound_allowlist` | `string[]` | No | — | External identifiers allowed for outbound sends. Empty = no outbound. |
| `on_inbound` | `string` | No | — | Hook invoked on inbound messages. Default: `on_frame`. |
| `reconnect_backoff_secs` | `u32` | No | 1–3600 | Initial reconnect delay in seconds. Exponential backoff caps at 5 min. Default: `5`. |
| `max_message_bytes` | `u32` | No | 256–1048576 | Per-message size cap in bytes. Default: `4096`. |

### Example

```toml
[[gateway]]
id = "telegram-ops"
type = "telegram"
auth_secret_ref = "secret:telegram:bot-token-prod"
inbound_allowlist = ["chat_id:123456789"]
outbound_allowlist = ["chat_id:123456789"]
on_inbound = "on_frame"
reconnect_backoff_secs = 5
max_message_bytes = 4096

[[gateway]]
id = "slack-alerts"
type = "slack"
auth_secret_ref = "secret:slack:webhook-url"
outbound_allowlist = ["channel:C0123ALERTS"]
```

## `[model_provenance]` — Model provenance (Story 9.4b)

The `[model_provenance]` section declares the AI model provenance for Spirits that wrap or embed a covered model. Added in schema v3. **Optional** — pre-v3 manifests and Spirits without model coverage omit it.

At admission, the kernel validates the section shape, enforces the reverse-DNS constraint on `training_data_lineage` (no free-text — D5), checks staleness against the operator-configured window, and emits a governance event to the Transparency Log carrying a content hash over the provenance triple.

| Field | Type | Required | Constraint | Description |
|-------|------|----------|------------|-------------|
| `covered_model_id` | `string` | Yes | Non-empty | Identifier of the covered model (e.g., `anthropic.claude-opus-4-8`). |
| `training_data_lineage` | `string[]` | Yes | Reverse-DNS only | Structured lineage references. Each entry must be a valid reverse-DNS label (`[a-z0-9-]` segments, two or more dot-separated labels). Free-text is rejected. |
| `last_eval_timestamp` | `string` | Yes | RFC 3339 UTC | Timestamp of the last model evaluation (e.g., `2026-06-01T00:00:00Z`). Used for staleness checks. |

### Admission policy

Operators control model-provenance enforcement via environment variables:

| Variable | Default | Description |
|----------|---------|-------------|
| `MAOS_REQUIRE_MODEL_PROVENANCE` | `false` | When `true`, Spirits without `[model_provenance]` are rejected with `EModelProvenanceMissing`. |
| `MAOS_MODEL_PROVENANCE_MAX_AGE_SECS` | `0` (disabled) | Maximum allowed age of `last_eval_timestamp` in seconds. `0` disables staleness checks. |

### Example

```toml
[model_provenance]
covered_model_id = "anthropic.claude-opus-4-8"
training_data_lineage = [
  "lineage.public-web.cc-2024",
  "lineage.curated.textbooks-2024"
]
last_eval_timestamp = "2026-06-01T00:00:00Z"
```

## `deployment_operator_id` and `provider_history` (Story 9.4b)

These are **runtime constructs** added by Story 9.4b, not manifest fields. They participate in the governance and admission surface.

### `deployment_operator_id`

A constant identifier stamped on every model-provenance governance event emitted to the Transparency Log. Configured via:

```bash
export MAOS_DEPLOYMENT_OPERATOR_ID="acme-corp.maos.prod-us-east"
```

Defaults to `maos.deployment.operator.default`. This is the **only** persisted-record tenancy reservation at v1.0 — no generic per-record tenant field exists (D7).

### `provider_history`

A bounded in-memory tracker in the kernel's `SecurityManagerAdapter` that detects provider switches between consecutive `admit_spirit` calls for the same `spirit_id`. Bounded to 4096 entries with an evict-oldest overflow policy (Story 9.4b AC-8). When a switch is detected, a `ProviderSwitched` lifecycle event is emitted to the journal.

