# Manifest Schema v5

Schema v5 adds the `wasm-component` form, its required `[class].artifact` path, and the `[capabilities.required.iac]` and `[capabilities.required.log]` declarations. The current schema is [v6](./v6); v5 remains supported.

## WASM component class declaration

A WASM component Spirit declares exactly one form, `wasm-component`, and a relative `.wasm` artifact path. The path is resolved relative to the manifest directory by the launch path; schema validation does not open the artifact.

```toml
[class]
name = "third-party-component"
version = "0.1.0"
abi = "1.0"
manifest_schema_version = 5
min_substrate_version = "0.1.0"
forms = ["wasm-component"]
artifact = "dist/spirit.wasm"
trust_tier = "local"
description = "A component-model Spirit"

[sandbox]
tier = "T2"
```

`wasm-component` cannot be combined with another form. It requires schema v5 and `artifact`; every other form forbids `artifact`. Artifact paths are non-empty relative paths of at most 4096 bytes, contain no `..` segment, and end in `.wasm`.

## IAC send capability

`[capabilities.required.iac]` declares which peer classes the Spirit may emit bus frames to. `send` takes entries from a closed set:

- `"broadcast"` — a frame with an empty `to` list.
- `"spirit:peer"` — a frame addressed to at least one Spirit.

```toml
[capabilities.required.iac]
send = ["spirit:peer"]
```

When present, `send` must be non-empty and free of duplicates; any other entry is refused with a validation error naming `capabilities.required.iac.send`. Each entry becomes one `iac.send` scope. The kernel mediates every delivered frame with a capability token for that scope, so the Spirit's bus deliveries appear in `maosctl audit query --spirit` with their token. A manifest declaring schema v4 or older has the table dropped at admission.

`[capabilities.required.provider]` is optional: when absent the Spirit holds no provider capability; when present, `complete` must still be non-empty.

## Log recall and fetch capabilities

```toml
[capabilities.required.log]
recall = true
fetch = true
```

| Key | Type | Default | Scope |
|-----|------|---------|-------|
| `recall` | boolean | `false` | `Scope::LogRecall` |
| `fetch` | boolean | `false` | `Scope::LogFetch` |

The grants are independent; omitting the table grants neither. Unknown keys are refused. Like `[capabilities.required.iac]`, this table requires schema v5: a manifest declaring schema v4 or older has it dropped at admission with a degradation warning, so it grants no log scopes. This is an additive schema v5 declaration, not a schema-version bump.

Each call is separately mediated, minted, and audited by the daemon. Policy, operator denial, or issuance quota can still refuse a declared capability. Native and WASM Spirits share one kernel-mediated `MediatedLogRecall`: local recall covers disclosable frames the caller sent OR is a recorded recipient of, in this boot only. Recipients must be admitted local addressees resolved through the admitted-incarnation map (and accepted by a consent gate if installed); role never confers participation. Audit rows and earlier boots remain excluded; cross-wall recall stays emitter-scoped.

### Capability-issuance quota {#capability-issuance-quota}

`DEFAULT_ISSUANCE_QUOTA` grants each admitted scheduler pid (one incarnation)
**60,000 issuances per 60 s tumbling window**, measured with a monotonic clock.
Capacity is inclusive (exactly B); a burst across one boundary can reach ≤ 2·B.
Mediation is **policy → context → quota → tokens**: policy and context refusals
spend no issuance quota, failed signing refunds its reservation, and only issued
tokens are charged. Revoking an issued token, including recall's per-call revoke,
does not refund issuance.

Exhaustion is `CapError::IssuanceQuotaExhausted`, or
`GovernedMintError::QuotaExhausted` through the governed wrapper.
Spawned-session `iac.send` records verdict `exhausted`; recall/fetch return
`capability-denied`; MCP writes a `mcp.call.refused:capability-denied` receipt.
CLI-wrapper spawn refuses on both local and remote paths; D1's proceed posture
remains only for the absent `proc.exec` grant, not exhaustion.

Operator-only kind-7 audit rows fire once per signal/pid/window:
`cap.quota:pressure` at ⌈80 %⌉, `cap.quota:limit` at ⌈95 %⌉, and
`cap.quota:exhausted` at the first refusal. Kind 7 is never Spirit-recallable.
Delivery is at most one non-blocking enqueue attempt per signal/pid/window:
durable when written, not guaranteed under audit saturation or writer closure.
Drops count under `AuditDropSite::Quota` and are never retried.

**Limits, not controls:** hot swap keeps the window; cold swap, crash restart,
unload/re-admission and every fresh Worker bind get fresh capacity. This is not
a stable-Spirit, principal-wide or Worker-spawn-churn bound. Other governed
callers surface `QuotaExhausted` in string errors; `ShellHost` stringifies the
kernel error on the operator REPL. The budget is not operator- or
manifest-configurable. There is **no Spirit-facing issuance pre-warning**;
a Spirit learns exhaustion from each path's typed denial. `ScheduleWatchdog`
consumes its rate bucket before minting; its narrowed tokens are audit
attestations of authority at fire time, and the hook ABI carries no token.

These are issuance signals, not ADR-016's
`ContextPressure`/`ContextLimit`/`EContextExhausted` for Spirit-self-reported
context tokens versus manifest `[budget].context_window_size`, delivered by
`18-5-context-token-budget-accounting`: optional `[budget]`
`context_pressure_threshold` / `context_limit_threshold` (in (0, 1], pressure
below limit; defaults 0.80 / 0.95) raise one kernel-written `ContextPressure` /
`ContextLimit` frame per upward crossing, and above 100 % new tool calls are
refused `CapError::ContextExhausted` — before the issuance charge, never for
`provider.complete`, memory writes or `iac.send` (distil and hand off). Counts
are Spirit-self-reported; the kernel never estimates them.

### Recall consent and production limits

For recipients other than the sender, expired, grant-ruptured, or `Withheld` envelopes omit the frame from recall and return `consent-withheld` on fetch, with a `log.fetch.refused:consent-withheld` receipt. `HeaderOnly` lists metadata with `payload-available = false` and likewise refuses fetch. `ConsentEnvelope.recall` is daemon-side, defaults to `Full`, and maps unknown values to `Withheld`; it is not in WIT, so guests see only its effect. The lossless-frame exception is ratified as `17-8-consent-recall-policy`.

**Production limits (AC3.6 / rule 11):** at HEAD no production granter sets `HeaderOnly`/`Withheld`, no `ConsentGate` is installed in production, and envelope-bearing frames reach admitted local recipients only through A2A delegation intake. Peer-identity ruptures carry no envelope and withhold nothing. Native compiled-in Spirits' bus sends journal at pid 0 (a non-goal). For the WIT import, errors, consent details, and `handle-frame`-only availability, see [WASM Component Spirit](/cookbook/wasm-component-spirit).

## Admission boundary

A WASM-component Spirit declares sandbox tier `T2`. The default MAOS binary validates the complete manifest and then refuses the component with `wasm_engine_off` while Export Hold 2 keeps the `wasm-host` feature disabled. A build with `wasm-host` launches the component via `maos run` in the contained T2 runner; in-process surfaces it does not provide (operator door, topology, hot-swap successor) are refused as `spawned_surface_unsupported`.

## `[cli_wrapper]` — Worker manifests {#cli-wrapper-worker-manifests}

A Worker manifest uses one `[cli_wrapper]` table instead of `[class]`; declaring both is refused at manifest gate 3 with `manifest_schema_conflict`. A `[cli_wrapper]` manifest has no `manifest_schema_version` (a schema version for it is owned by Story 20-5). Unknown keys are rejected in `[cli_wrapper]` and `[cli_wrapper.posture]`.

| Key | Type | Required / default | Allowed values or constraints |
|-----|------|--------------------|-------------------------------|
| `command` | `string` | Required | Non-empty. |
| `argv_prefix` | `string[]` | Optional; default `[]` | — |
| `output_shape_version` | `string` | Required | For example, `"1.0.0"`. |
| `skill_bundle` | `string[]` | Optional; default `[]` | — |
| `recovery_policy` | `string` | Optional; default `respawn_with_context` | `respawn_with_context`, `respawn_fresh`, or `escalate`; the default is refused at load. |
| `egress` | `string[]` | Optional; default `[]` (no egress) | Entries are `host:port`; duplicates are refused. |
| `[cli_wrapper.posture].stdio_shape` | `string` | Required | `ndjson_over_stdio`, `json_rpc_over_stdio`, or `raw`. |
| `[cli_wrapper.posture].control_channel` | `string` | Required | `signals`, `named_pipe`, or `stdin_commands`. |
| `[cli_wrapper.posture].shutdown_signal` | `string` | Optional | `SIGTERM`, `SIGINT`, `SIGKILL`, `SIGHUP`, `SIGQUIT`, `SIGUSR1`, or `SIGUSR2`. |

Egress hosts are lower-case DNS labels or an IPv4 literal, and ports are `1`–`65535`. Manifest egress must be a subset of the operator's host-grant destinations; a bare host in a grant means `:443`. Upstream traffic uses `HTTPS`, except plain `HTTP` is allowed to an explicitly granted IPv4 loopback literal.

Admission requires `[sandbox] tier` to resolve to `T3`. Only `T0`–`T4` parse; there is no `hardened` tier. A matching operator-owned `MAOS_HOST_GRANTS` grant is required. At load, the default `respawn_with_context` policy is refused. Under `T3`, only `ndjson_over_stdio` or `raw` with `control_channel = "signals"` is admitted; stdin-keeping postures are refused. Supported commands are `codex`, `claude`, `worker-cli-fixture`, and `worker-probe-fixture`.
Worker resources are optional and independent: `cpu_max_pct` is a positive percentage of one CPU (`10` = `--cpus=0.10`), `memory_max_mb` is MiB, `pids_max` is a positive `u32` process/task ceiling, and `fd_max` is an independent file-descriptor ceiling. Each resolves to the strictest manifest/operator limit; omission remains `None` (including on accepted schema v4/v5 manifests). For native Linux T2, delegated writable cgroup v2 is required for explicit CPU/PID ceilings; memory-only requests may fall back to applied `RLIMIT_AS` and optional `RLIMIT_NOFILE`, with one persisted `ResourceCeilingDowngraded=20` informational row per successful fallback launch. `pids_max` is enforced only on Linux; the native macOS and Windows sandboxes neither apply nor refuse it. See [CLI wrapper Spirit cookbook](/cookbook/cli-wrapper-spirit) for T3 runtime defaults and native limitations.

See the [CLI wrapper Spirit cookbook](/cookbook/cli-wrapper-spirit) for its runtime profile and operator prerequisites.

```toml
# A Worker manifest: [cli_wrapper] replaces [class]; never declare both.
[cli_wrapper]
command = "codex"
argv_prefix = ["exec", "--json", "--sandbox", "workspace-write"]
output_shape_version = "1.0.0"
recovery_policy = "escalate"
egress = ["api.openai.com:443"]

[cli_wrapper.posture]
stdio_shape = "ndjson_over_stdio"
control_channel = "signals"
shutdown_signal = "SIGTERM"

[sandbox]
tier = "T3"

[author]
name = "OpenAI"

[on_crash]
action = "nack"
```

Schema v4 manifests remain accepted in the N-1 window. A v4 manifest cannot declare `wasm-component`.
