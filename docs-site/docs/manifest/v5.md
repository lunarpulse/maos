# Manifest Schema v5 (Current)

Schema v5 adds the `wasm-component` form, its required `[class].artifact` path, and the `[capabilities.required.iac]` declaration. The authoritative value is `MANIFEST_SCHEMA_VERSION = 5` in `maos-spirit-abi`.

## WASM component class declaration

A WASM component Spirit declares exactly one form, `wasm-component`, and a relative `.wasm` artifact path. The path is resolved relative to the manifest directory by the launch path; schema validation does not open the artifact.

```toml
[class]
name = "third-party-component"
version = "0.1.0"
abi = "1.0"
manifest_schema_version = 5
min_substrate_version = "0.1.0"
forms = ["wasm-component"]
artifact = "dist/spirit.wasm"
trust_tier = "local"
description = "A component-model Spirit"

[sandbox]
tier = "T2"
```

`wasm-component` cannot be combined with another form. It requires schema v5 and `artifact`; every other form forbids `artifact`. Artifact paths are non-empty relative paths of at most 4096 bytes, contain no `..` segment, and end in `.wasm`.

## IAC send capability

`[capabilities.required.iac]` declares which peer classes the Spirit may emit bus frames to. `send` takes entries from a closed set:

- `"broadcast"` — a frame with an empty `to` list.
- `"spirit:peer"` — a frame addressed to at least one Spirit.

```toml
[capabilities.required.iac]
send = ["spirit:peer"]
```

When present, `send` must be non-empty and free of duplicates; any other entry is refused with a validation error naming `capabilities.required.iac.send`. Each entry becomes one `iac.send` scope. The kernel mediates every delivered frame with a capability token for that scope, so the Spirit's bus deliveries appear in `maosctl audit query --spirit` with their token. A manifest declaring schema v4 or older has the table dropped at admission.

`[capabilities.required.provider]` is optional: when absent the Spirit holds no provider capability; when present, `complete` must still be non-empty.

## Admission boundary

A WASM-component Spirit declares sandbox tier `T2`. The default MAOS binary validates the complete manifest and then refuses the component with `wasm_engine_off` while Export Hold 2 keeps the `wasm-host` feature disabled. A build with `wasm-host` launches the component via `maos run` in the contained T2 runner; in-process surfaces it does not provide (operator door, topology, hot-swap successor) are refused as `spawned_surface_unsupported`.

Schema v4 manifests remain accepted in the N-1 window. A v4 manifest cannot declare `wasm-component`.
