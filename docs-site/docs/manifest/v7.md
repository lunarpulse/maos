# Manifest Schema v7

Schema 7 adds four optional sections to [schema v6](./v6). Each present list must contain 1–32 unique names, each 1–128 bytes from `[a-z0-9_.:-]`; unknown keys are refused. A manifest below schema 7 is still supported: the four sections are ignored with a degradation warning.

```toml
[skills]
uses = ["example-prerequisite"]

[explanation_shape]
required_fields = ["reason"]

[intent_promotion_set]
allowed = ["consult"]

[swap_invariants]
preserve = ["example-state"]
```

`skills.uses` names skills discovered on the conventional roots and already admitted by an operator. Their required capabilities must be covered by the Spirit's declared actions. Spirit-supplied search paths are not supported. `intent_promotion_set` restricts the stored intent lineage of a prior distillate delivered in `TaskAssign`; omitting it retains the existing behavior.

`explanation_shape` is validated and journaled but **not enforced**: no decision frame carries an explanation body. Until the kernel landing, `swap_invariants` is also validated and journaled but a successor swap does not check it; no release is made between the landings. The later check is structural and does not prove state preservation.

A `governance:manifest-declaration` row records the exact manifest SHA-256, verified publisher key for a signed installed package (null for an unsigned local manifest), and declared sections before pid issuance. It is a declaration, **not evidence of admission**: a later admission failure may leave the row, accompanied by a refusal. I2 storage failure is fail-stop.

Digest and publisher are encoded as sixteen colon-separated lowercase
four-hex-digit groups. Consumers can recover the exact 32 bytes with
`maos_domain::governance::decode_declaration_bytes`, which rejects malformed
encodings.

The additive `maos:spirit@2.3.0` `skills` import provides `author(document)` and `propose(target-id, target-version, diff)`. Both only run inside `handle-frame`; the host binds the pid, class and telemetry. Errors are `capability-denied`, `refused(code)`, and `unavailable`. Neither call imports skill content or admits it: approval remains operator-only.
