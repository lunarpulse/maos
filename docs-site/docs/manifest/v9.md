# Manifest Schema v9

Schema 9 is proposed for Story 22-9 (D-22-9-04 A) as `22-9-manifest-schema-9`; the
operator has not yet ratified it. `ABI_VERSION` and the manifest version floor both
remain `1`. There is no guest wire change and no new capability `Scope` variant.

## Declare consent

A sending Spirit that declares `[consent.recall]` sets `[class].manifest_schema_version`
to `9` or higher:

```toml
[consent.recall]
peer-b = "header_only"
peer-c = "withheld"
```

- Below schema 9, a `[consent]` table is refused at admission as a typed
  `manifest_section_invalid` refusal, not loaded with a warning. Schemas 1–8 that declare
  no `[consent]` remain supported and unrestricted.
- Each recipient id must be one the Host knows when the Spirit is admitted: an installed
  package, a member of the host file's cast or of the topology, or a Spirit already
  loaded. Install and load order do not matter. Any other id is refused as
  `consent_recipient_unknown`; the declaration is never partially admitted.
- The grants themselves are unchanged from [schema 7](./v7#consent-recall).

A hot swap that auto-reverts restores the predecessor's declaration together with its
scopes and promotion set. See [Lifecycle Hooks](../cookbook/lifecycle-hooks).
