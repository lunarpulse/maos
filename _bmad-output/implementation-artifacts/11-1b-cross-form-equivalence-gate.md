## Story

**As** the MAOS release engineer,
**I want** a behavioral-oracle **tiered** equivalence gate that runs the *same* deterministic fixture Spirit as both a native subprocess and a WASM component and proves they produce **identical invariant-bearing effects** (halt, frame sequence, capability denials, region-pin, audit frames) with only cosmetic/latency slack,

## ⚠️ PREFLIGHT FLAGS (read first — these are the landmines that make a naïve gate vacuous or false-RED)

### F1 — The flat distributional metric is a TRAP on deterministic Spirits — it is exactly what this story replaces.
`xtask/src/check_cross_form_equiv.rs` (shipped in Story 10.2, **advisory**) computes a Mann-Whitney U-test with `divergent = p_value <= 0.05` (`:318`). It has a **D5 degeneracy branch** (`:276-292`) that fires when a group has `< 2` distinct per-run hashes — i.e. **on every deterministic fixture Spirit** — and emits `verdict = "NOT-APPLICABLE (deterministic output — U-test is vacuous)"` then `return Ok(())`. Its own comment (`:288`) says the quiet part out loud: *"deterministic Spirits require **byte-identical comparison, not a U-test**."* The Epic-11 plan §6 rejects the DRAFT's flat ≥75% distributional metric **for this exact reason** (`epic-11-v20-technical-phase.md:26`). **Do NOT reuse the distributional path for the WASM leg.** The WASM leg uses a **deterministic, byte-exact, per-effect tiered oracle** — which, being deterministic, is safe to run **live in CI** (unlike the noise-sensitive timing metric that motivated 10.2's committed-artifact posture, F1→B).

### F2 — There is NO native binary that speaks CBOR `IacFrame` today. You must build the native twin.
This is the biggest scope reality. The two forms do **not** speak the same body encoding out of the box:
- **WASM form:** `maos-wasm-runner` (`crates/maos-wasm-host/src/runner.rs`) reads/writes **Content-Length + canonical-CBOR `IacFrame`** end-to-end (`pump_frames`, `:230-267`).
- **Native form:** the reference native Spirit `hello-spirit-bench` (`crates/maos-spirit-hello/src/bin/hello_spirit_bench.rs`) speaks Content-Length + **JSON** with a *reduced* `{kind,task_id,response}` schema — NOT CBOR, NOT a full `IacFrame`. The kernel bridge (`spawn_and_bridge`) is content-agnostic (journals frames as opaque `CliSubprocessOutput` bytes). The fuzz target states it plainly: *"IacFrame's PRODUCTION on-wire path is `serde_json` … IacFrame is NEVER CBOR-serialized in production"* (`crates/maos-domain/fuzz/fuzz_targets/frame_deser.rs:10`).
- ⇒ To run the **same logical Spirit** in both forms over **byte-identical CBOR input frames**, factor the fixture Spirit's `handle_frame`/`on_start`/`on_shutdown` logic into a **shared source crate**, then build it two ways: (a) the existing `wasm32-wasip2` component path (`guests/echo-spirit` is the template), and (b) a **new native subprocess binary** that wraps the same logic with `maos_wasm_host::codec` (Content-Length + CBOR `IacFrame`). Same source → two forms is the only construction that makes "equivalence" non-tautological. **This native twin does not exist yet and is the load-bearing new artifact of AC1.**

### F3 — `frame_bridge.rs` DROPS three invariant-candidate fields on the WASM path. Scope the invariant tier to what survives, or you false-RED every run.
`crates/maos-wasm-host/src/frame_bridge.rs` (`lower` `:376-387`, `lift` `:392-406`, doc `:9-21`) **drops on lower / hard-defaults on lift**: `intent` → `IntentClass::Readonly`, `consent_envelope` → `None`, `intent_lineage` → `default()`. `TaskAssignPayload.scope` rides as a `{:?}` debug string and `scope_from_debug_string` **always returns `None`** (`:362-370`) → any non-empty scope round-trips to EMPTY. `DecisionDispatchPayload.working_memory_digest_refs` and `PriorDistillateRef.intent_lineage` are also defaulted. These are **known, pinned, expected divergences** (`tests/frame_bridge_roundtrip.rs` already asserts them). Consequences for the oracle:
- The **frame-sequence** invariant tier (observed at the guest stdout) must compare **only bridge-preserved fields**: `frame_id`(normalized), `timestamp_ns`(normalized), `logical_clock`, `from`, `to`, `kind`, `payload`, `auto_marker`. It must NOT treat `intent`/`consent_envelope`/`intent_lineage`/`scope` as invariant for the WASM leg (they are structurally unobservable there). Record this as an explicit, enumerated exclusion allowlist (AC4's tier-map honesty), not a silent skip.
- The safer observation for `intent`/consent-gated behavior is **kernel-side** (capability denials + audit rows), which are form-agnostic (see F4).

### F4 — 4 of the 5 invariant classes are observed KERNEL-SIDE, not from guest stdout — which is what makes the bridge gap survivable.
Only **frame sequence** is read from the guest's stdout CBOR stream (and is subject to F3). The other four are observed at kernel/audit chokepoints that are identical regardless of form:
- **Halt:** the returned `HaltReceipt` (`crates/maos-domain/src/halt.rs:202`; produced by the single owner `invoke_halt`, `crates/maos-kernel-core/src/halt/mod.rs:504-566`) + the `epistemic.halt` TL row (kind=3) + the `EpistemicHalt` frame (payload **is** bridge-preserved).
- **Capability denials:** `CapError` (`crates/maos-domain/src/ports/capability.rs:112-141`) / `VerifyOutcome` (`crates/maos-capability/src/cap_audit/mod.rs:34-43`) / the `capability.invocation` TL row (kind=7, `crates/maos-kernel-core/src/capability/cap_audit/writer_task.rs:80-106`).
- **Region-pin:** `ERegionViolation` at the write chokepoint `enforce_region` (`crates/maos-kernel-core/src/memory/write_entry_point.rs:69`); region tag is operator/kernel config, not Spirit-emitted → invariant to form by construction.
- **Audit frames:** `AuditEntry` via `maos_audit::query` / `ranged_recall` (`crates/maos-audit/src/lib.rs:90,184`; `log_composition.rs:104`), incl. kind=8 `sandbox.block`.
⇒ For the oracle to observe these, the fixture-Spirit scenarios must actually **run under the real kernel** (capability registry + memory write entry point + audit TL), and the harness queries the TL/journal for both forms via the same `maos_audit` read API. A pure stdout-only harness can only see frame sequence + halt frames — it cannot falsify capability/region/audit equivalence. Design the scenario corpus so each invariant class is exercised by at least one scenario, and observe it at the correct chokepoint.

**Kernel-side is a GENUINE INDEPENDENT ORACLE (verified 2026-07-01 probe, STRONG evidence).** The kernel **derives** every enforcement decision from its own state, not from the frame's in-band fields: capability grant/deny uses kernel-side `Intent`+`Scope`+`manifest.scopes` keyed by `spirit_pid` (`crates/maos-kernel-core/src/capability/cap_policy/mod.rs:78-171`), NOT `frame.intent`; region-pin uses `enforce_region(DirectWrite, home_region)` with `home_region` from `MAOS_REGION_HOME`/`operator.toml`, frame not consulted (`crates/maos-kernel-core/src/memory/write_entry_point.rs:69`, `memory/mod.rs:683`); same-Host consent is decided by an operator-installed `ConsentGate` on recipient identity (`crates/maos-iac/src/adapter/mailbox.rs:54,319-334`), not the envelope; the cross-Host A2A router consumes `consent_envelope` but it is **Host-transport-filled (not Spirit-asserted)** and bound to the TLS-verified peer + matched vs the operator allowlist (`crates/maos-a2a-core/src/router.rs:789-886`). ⇒ dropping these fields on the WASM path **cannot fail-open**, and the kernel-side observation of both forms yields identical decisions *by construction* (same manifest/spirit_pid/home_region) — the tier is falsified by a genuinely-divergent component, not by the bridge gap.

**The real-kernel context is CHEAP — do NOT build a rig.** Reuse the existing in-process `KernelCtx` builder: `crates/maos-kernel-core/tests/kernel_ctx_round_trip.rs:11-65` stands up `MemoryManagerAdapter` (routes through `enforce_region`; `with_home_region(Some(Region::canonicalize("eu")?))` arms region-pin) + `CapabilityRegistryAdapter` (over a `PolicyTable`; unknown `spirit_pid`/unmatched `Scope` → `Deny`, pattern in `cap_registry_integration.rs::make_adapter`) + `IacBusAdapter`, all in-memory with a `TransparencyLogAdapter::open_in_memory(0)` for audit rows. `spawn_and_bridge` (`runtime.rs:449`) does NO cap/region mediation ("cap-policy is NOT in this bridge", `:619-624`) — it is only needed if a scenario must be an out-of-process subprocess emitting `CliSubprocessOutput` rows; it is **not** the cap/region/audit oracle.

### F5 — Live execution + anti-canned is NON-NEGOTIABLE. A committed results artifact would be cannable.
§A7.3 (feature-flag ≠ measurement): "A gate that can only go red by editing a constant is theater. (10.2→10.4c canned J4.)" The 10.2 committed-artifact posture was justified for the **noise-sensitive distributional timing** metric only. The tiered invariant oracle is **deterministic** → it MUST run live in CI (a `cargo test` gate, the J4 pattern) and the equivalence numerator MUST be **derived from actually-captured effects**, not read from a hand-committed JSON. Model the anti-canned tripwire on `crates/maos-bench/tests/t_10_4c_j4_mutation.rs` (fault-injection must move the number → "green-when-it-must-be-red" if re-stubbed) + the CI grep that asserts the mutation test actually RAN (`discipline.yml:2366-2383`) + the release-graph exclusion of the fault-inject feature.

## Acceptance Criteria (4 — at the Epic-11 story allotment)

**AC1 — Tiered behavioral-oracle equivalence harness: same Spirit, both forms, invariant effects 100% / cosmetic ≥75% (NFR-Test-7 `any-rust ↔ wasm-component`)**
**Given** a deterministic fixture Spirit whose `handle_frame`/`on_start`/`on_shutdown` logic is built from **one shared source** into (a) a real `maos:spirit@1.0` WASM component and (b) a **new native subprocess binary speaking Content-Length + CBOR `IacFrame`** (D2/F2), and a scenario corpus where **each** invariant class (halt, frame sequence, capability denial, region-pin, audit) is exercised by ≥1 scenario over byte-identical CBOR input frames
**When** the harness runs every scenario through **both** forms as real subprocesses (WASM via `maos-wasm-runner`; native via the new twin), capturing invariant-bearing effects at their correct chokepoints — frame sequence from the guest stdout CBOR stream (bridge-preserved fields only, per F3), and halt / capability-denial / region-pin / audit effects **kernel-side** by driving each form's emitted frames through the **in-process `KernelCtx` builder** (`kernel_ctx_round_trip.rs` pattern, D14; `with_home_region(...)` arms region-pin) and reading `HaltReceipt` + `maos_audit::query`/`ranged_recall` (F4) — with per-run nondeterministic `frame_id`/`timestamp_ns` normalized before comparison
**Then** the **invariant tier matches 100%** across forms (any single invariant-bearing mismatch → gate RED), the **cosmetic/latency tier meets ≥75%**, and the equivalence numerator is **derived-and-reconciled per scenario** from the actually-captured effects (never read from a committed summary; §A7.1)
**And** the F3 field exclusions (`intent`/`consent_envelope`/`intent_lineage`/`scope`) are an **enumerated allowlist**, not a silent skip; the corpus honors the **`intent_lineage` constraint** (D13 — avoid cross-Spirit `SpiritAuto` frames, or exclude `intent_lineage` explicitly, so the kernel's `EIntentLineageBroken` reject is not misread as a divergence bug); and a **forged-in-band-consent negative control** proves the kernel-side oracle is independent (D12): a fixture that forges `consent_envelope` in the native twin yields the **same kernel decision** as the WASM form that cannot carry it — meaningful green, because the kernel derives the decision and ignores the field
**And** the harness fails loudly (not vacuously) if a form's subprocess is absent, crashes, or emits zero frames (no silent-skip vacuous pass — the 11.1a `require_runner_binary()` lesson)
**And** NO mock/loopback stands in for either form (real binaries, real pipes; the WASM form transits the real `frame_bridge` with its F3 lossiness while the native twin runs direct — that asymmetry IS the thing under test, per Murat).

**AC2 — Known-divergent component proven-red + anti-canned tripwire (falsifiability IS the risk)**
**Given** a real `maos:spirit@1.0` **divergent** component (echo-spirit template) that mutates exactly one invariant-bearing field in `handle_frame`, and a separate **cosmetic-only** divergence (identical invariant effects, different latency/timestamp)
**When** the gate evaluates them
**Then** the divergent component drives the gate **RED on the invariant tier** (a real observed field mismatch moves the numerator; not a hand-set constant), while the cosmetic-only divergence **stays GREEN** within the 75% slack (the no-vacuous-green control on both sides)
**And** an **anti-canned tripwire** (modeled on `t_10_4c_j4_mutation.rs`): a fault-injection feature that perturbs an **invariant-tier** captured effect MUST move the equivalence number **through the gate's own comparator** (not a test-only copy) — the mutation targets an invariant-tier field (the exact tier that flips the binding), not a cosmetic one; if it cannot move the number, the harness has been re-stubbed to constants and the tripwire test **goes green-when-it-must-be-red** (fails)
**And** CI asserts the tripwire/mutation test **actually ran** (≥1 passed test — the `discipline.yml:2366-2383` grep guard against a 0-test vacuous green) **and** that the fault-injection feature is **ABSENT from the release feature graph** (`cargo tree … --release`), so it can never weaken a shipped build.

**AC3 — NEW `check-wasm-form-equiv` sibling gate + ADR-031 → binding-v2.0 (enveloped) + form-identity reflex (§A7)**
