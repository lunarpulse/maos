Kernel-free. No kernel file, no domain enum variant, no public-surface change (two `pub` helpers in `maos-bin` `admission`, one of them a refactor of the existing one; `check-service-boundary` is the kernel surface and flags nothing).

## Round 1 (first cut) and its review

Round 1 read the predecessor's retained text (`private_ops.admitted_manifest`) and returned `SwapInvariantDropped` **before** the coordinator precheck. The independent GPT review (`review/gpt-review.md`; the security review `review/security-gpt-reviewer.md` agrees on the first point as a P3) found two P2 defects:

- **P2-1.** `zip` over two `Option`s silently skipped the comparison when no retained text existed. An installed component is admitted by `InstalledSpirits::boot` (`installed_spirits.rs`) without populating `admitted_manifests` (`main.rs` records it only for `maos run`, `load`, `load_spawned` and a committed hop), so a schema-7 installed predecessor got `safe: true` for a successor the coordinator refuses; and after `auto_revert` (`scb.replace_runtime`) the retained text still holds the reverted successor's declaration, which produces the opposite, false refusal.
- **P2-2.** `admission::dropped_swap_invariant` reads an unreadable section as "declares nothing", so a malformed successor (`swap_invariants = false`, top level) against a predecessor declaring an invariant was reported `SwapInvariantDropped`, bypassing the coordinator parser (`UpgradeError::ManifestParse` on a real upgrade; `precheck_failed` before round 1).

## Change (round 2)

- `crates/maos-bin/src/operator_door.rs` `precheck_command`: the coordinator precheck now runs first. It parses the successor with the kernel's own `load_bundle_from_file`, so a malformed section is `precheck_failed` (400, the parser's message), never a verdict. Then, under `#[cfg(feature = "network")]`, the predecessor's declaration is read from the **live SCB** — `scheduler.scbs()` → the SCB with this `spirit_id` → `runtime_snapshot().manifest.swap_invariants` — exactly what `HotSwapCoordinator::initiate_swap` compares (`coordinator.rs:192-202`, `pre_swap_runtime.manifest.swap_invariants`). Those are all public kernel APIs the door already uses (`uninstall_command` reads the same map); no kernel file is touched and no accessor is missing. The comparison is `admission::first_unkept_swap_invariant(&live, &successor_text)`; `Some(name)` returns `Completed({verdict: {verdict: "SwapInvariantDropped", cause: name}, safe: false, terminal_code: 2})`. A missing retained text is no longer an input at all.
- `crates/maos-bin/src/admission.rs`: the closure of `dropped_swap_invariant` became the private `declared_swap_invariants`; `dropped_swap_invariant(predecessor_text, successor_text)` (the cold swap's restore-source comparison, unchanged behaviour) is now a thin wrapper over the new `first_unkept_swap_invariant(preserve, successor_text)`.
- Ordering note: the coordinator precheck's own verdicts (`HaltContinuityViolation`, `SchemaIncompatible`, `EMigratorMissing`) are unsafe too; where one of them coincides with a dropped invariant the door reports the invariant (the real swap checks halt continuity first, then the invariant). Both are `safe: false`, terminal 2.
- Not changed: the cold-swap door still compares retained text (`dropped_swap_invariant`, `operator_door.rs` ~1556) and its parse behaviour is as reviewed in landing 2 (a refusal before the unload either way; a missing retained text is refused closed as `cold_swap_predecessor_unknown`, which is the premise the installed witness asserts).
