## Findings

### F-1 — Medium — The cold-swap door verb bypasses the swap-invariant refusal entirely
**Where:** `crates/maos-bin/src/operator_door.rs:1486` (`async fn cold_swap`, body through ~1712); contrast the kernel gate at `crates/maos-kernel-core/src/hot_swap/coordinator.rs:190-216` and the door's other policies at `operator_door.rs:1429-1442`.

The coordinator refuses a successor that drops a predecessor-declared invariant, and `migration_plan.rs:230-240` maps that to typed `409 swap_invariant_dropped` — but only `hot-swap` and `migrator` route through the orchestrator/coordinator. `UpgradePolicyRequest::ColdSwap` returns early into `cold_swap`, which checks (admitted manifest known, plan pending, form match, restorable, forward-only, vetting, ABI triple — all on the target) and then **unloads the predecessor and admits the successor through the plain admission triple** (`admit_and_start` → `load_spawned`/`load_spirit` → `gate_manifest`). There is no comparison of `[swap_invariants]` anywhere in the cold path — `operator_door.rs` contains no occurrence of `swap_invariants` at all; the check exists only in `coordinator.rs`. Admission parses the successor's section (`admission.rs:860-876`) but enforces nothing cross-incarnation.

**Exploit/impact:** a Spirit author ships v2 that drops `preserve = ["review_queue", …]` declared by the running v1 (schema 7). Hot swap/migrator refuse with 409; `maosctl upgrade --policy cold-swap` succeeds silently — the successor is admitted with no invariants, the declaration chain is journaled as the new truth, and every later hot swap enforces nothing (the severing is permanent). Cold swap is a first-class, sometimes *required* verb (components without lifecycle hooks, incompatible state schemas), so "operator picks the wrong verb" is realistic, and nothing in the receipt names the dropped names. The docs (`docs-site/docs/manifest/v7.md:31`) scope enforcement to "hot swap (and `--policy migrator`)" — the limitation is documented but not acknowledged in `deferred-work.md`, and it reduces FR8's guarantee to a per-verb courtesy.

**Fix sketch:** in `cold_swap`, before unload: the predecessor's exact bytes are already retained (`admitted_manifest`) and the target text already parsed (`root`) — parse both `preserve` lists under the same schema-≥7 rule and refuse typed `Conflict { code: "swap_invariant_dropped", … }` on any drop (mirror of `coordinator.rs:192-201`); or minimally, list dropped names in the completion receipt and require an explicit operator override flag.

### F-2 — Low — Precheck dry-run reports a safe verdict for a swap the kernel will refuse
**Where:** `crates/maos-kernel-core/src/hot_swap/coordinator.rs:484-540` (`precheck` loads the successor bundle but computes the verdict only from halt continuity + state schema) surfaced at `crates/maos-bin/src/operator_door.rs:1726` (`precheck_command`, `safe: true`, terminal code 0).

**Impact:** an operator following procedure (`precheck` → upgrade) gets `safe: true` for a successor that `initiate_swap` then refuses with `409 swap_invariant_dropped`. Not a protection bypass (the real swap is refused), but the advisory tool contradicts the enforcement point, which trains operators to distrust/ignore refusals. Already owned: `deferred-work.md:1701` (needs a `PrecheckOutcome` variant + `precheck.rs` change).

**Fix sketch:** add the invariant comparison to `HotSwapPrecheck::check` (it already has both manifests in `precheck`'s scope) and a non-safe `PrecheckOutcome` variant naming the first dropped invariant.

### F-3 — Low — FR8 sections declared below schema 7 are silently ignored (fail-open), with a stderr warning only
**Where:** `crates/maos-bin/src/admission.rs:860-884` (schema < 7 ⇒ section parsed as `None`, `eprintln!("…declared section {name} ignored below schema 7")`) and the successor-side twin at `crates/maos-kernel-core/src/lifecycle/upgrade.rs:388-397`. Schema floor is 1 (`crates/maos-spirit-abi/src/lib.rs:140-143`, window [1,7]).

**Impact:** a Spirit admitted at schema ≤ 6 may carry `[swap_invariants]` that look like a governance commitment (and appear in its source manifest) but are never enforced on any swap — the kernel-side refusal can never trigger for it. The degradation is documented ("below schema 7 these declarations degrade away", `maos-spirit-abi/src/lib.rs:110-112`), and the commit itself fixed the inverse hole (a schema-6 successor's declaration being honored at swap while ignored at admission — story record §measurements), so this is a designed trade-off; still, the only signal is a daemon stderr line, not a typed refusal or a marker in the `governance:manifest-declaration` row.

**Fix sketch:** refuse admission (typed) when an FR8 section is present below schema 7 — the same sections are invalid at schema 6 in every other respect that matters — or record `"degraded": true` in the declaration row so audit can distinguish enforced vs cosmetic invariants.

### N-1 — Hardening note (no exploit path today) — the coordinator is not self-serializing
`initiate_swap` (`coordinator.rs:120-479`) takes no per-spirit or coordinator lock; serialization is entirely the door's process-wide `upgrade_lock` (`operator_door.rs:1428`, held across stage/use/clear for every policy, cold swap included). Every production caller reaches the coordinator through the door, so no interleaving exists today; but any future non-door caller (e.g., an implementation of the unused `maos_domain::hot_swap::HotSwapResolver` trait, `hot_swap.rs:237`) could race two swaps (interleaved hooks/snapshots/`replace_runtime`). Consider an attempt mutex in the coordinator as defense in depth.

## Rejected candidates (traced, no credible path)

1. **Successor presenting a different manifest than the one the check read.** No check/use split: the orchestrator loads the bundle once (`upgrade.rs:88`) and passes *that* bundle to both the check and the successor factory and (on success) into the SCB (`upgrade.rs:131,153-186`; `coordinator.rs` `replace_runtime`). The door reads the operator's file once into bytes and hands everyone its private snapshot — `ManifestSnapshot` is `create_new` (O_EXCL), mode 0600, ULID name, removed on Drop (`operator_door.rs:396-420`); planned hops re-snapshot each hop's text and re-stage the factory slot per hop (`migration_plan.rs:213-227`, `main.rs:10326-10345`). The factory's re-gate (`spawned_successor`) reads the same staged snapshot bytes.
2. **Schema-6 downgrade trick at hot swap.** Fail-closed: a schema-6 successor parses `swap_invariants = None`, so *every* predecessor-declared name is "dropped" ⇒ 409. Witnessed: `swap_invariants_20_8.rs::an_undeclared_or_pre_schema_7_successor_drops_every_invariant`. The remaining schema-6 exposure is F-3 (predecessor side).
3. **Migrator verb skipping the gate.** Both kernel policies dispatch into the same `initiate_swap` (`upgrade.rs:161-186`); `UpgradePolicyRequest` has exactly three variants (`maos-control/src/lib.rs:281-293`, verb-table gate 7/7); `create_plan` is plan-only. Only cold swap bypasses (F-1).
4. **Spirit-controlled artifact path / manifest field influencing the declaration read.** The declaration is parsed from the door's snapshot of the operator's bytes; `class.artifact` cannot alter which manifest the kernel parses, and artifact resolution is containment-checked (absolute, `..`, and symlink escapes refused, `spirit_session.rs:106-133`). The only manifest field gating the declaration parse is `manifest_schema_version` — covered by F-3/F-1.
5. **Swap racing a concurrent swap.** Serialized by the door-level guard (see N-1); the refusal path mutates nothing and spawns no monitor (the check sits before `on_swap_out`, snapshot, `replace_runtime`, and `pending_reverts`/monitor setup at `coordinator.rs:300-360`), so two racing refusals cannot corrupt state.
6. **Refused swap leaving the successor child/pre-warm running or the predecessor fenced.** The refusal fires before any hook and before SCB mutation; `SagaCompensation::RestorePredecessor` is journal+TL-frame only (`saga.rs:101-151`); the preceding halt-continuity gate is read-only carry-not-drain (`halt/mod.rs:465-487`), so nothing is drained or fenced. For spawned successors the pre-warmed child is RAII-owned (`SpawnedBridge` "Drop kills+reaps the child", `cli_wrapper/runtime.rs:293-299`; `LifecycleLink::drop` releases the predecessor's attempt/fence, `spawned_lifecycle.rs:544-556`), and 20-9 spawned tests exercise post-prewarm refusal cleanup. Door witness asserts the predecessor keeps serving at the same pid (`one_daemon_one_door_16_1.rs:2461`). Residual (owned, unwitnessed): a spawned successor's declaration row is journaled before the KS refusal and the `refused` outcome row is inference — `deferred-work.md:1700`.
7. **Error/receipt information leakage.** The 409 detail and the `HotSwapAborted` TL frame name only the dropped invariant; names are bounded at parse (1..=32 entries, 1..=128 bytes, charset `[a-z0-9._:-]`, no duplicates — `maos-manifest/src/manifest.rs:4151-4177`), so no injection/oversized echo. Manifest-parse details embed snippets of the operator's own manifest only. No kernel-held secret crosses a boundary.
8. **unwrap/expect after serde in the touched kernel code.** None introduced: `load_bundle_from_file` propagates via `?`/`transpose` and uses `.ok()` only on the (theoretical) TOML re-serialization — the pre-existing pattern shared by `budget`/`hot_swap`/`on_crash` (`upgrade.rs:359-398`); coordinator/door/admission hunks add no unwraps; the single `check-serde-error-handling` violation is the pre-existing `main.rs:11091` owned by 20-11 (gate JSON confirms).
