## Verdict

**No P0–P2 findings. 3 × P3 (hardening/governance).** The move is a verbatim relocation (verified hunk-by-hunk against the creation diff); the one new logic body (`replay_pending`) *fixes* a director-instruction loss race rather than introducing one; the audit path, fail-stop orderings, and redaction posture of the three `journal_*` writers are byte-identical and hit the same `maos_iac::TransparencyLogAdapter` instance (`crates/maos-kernel-core/src/iac.rs:13` is `pub use maos_iac::*`, so the type is unchanged). The kernel did not lose any enforcement it actually performed: FIFO+capacity were properties of the buffer code, which moved with the code; Spirits (subprocess/wasm) never had in-process access to `maos_kernel_core::orchestrator`, and the only production caller set (maos-bin operator door, scheduler, composition root) is unchanged — only the module path changed.

## Findings

### F1 — P3 — FR54 gateway host with allow-all stubs now lives in an unfrozen leaf; still zero production callers (verified)
- **Where:** `crates/maos-orchestrator-buffer/src/gateway_dispatcher.rs:411-531` (stub block; `StubCapability::verify_outbound` returns `Ok(())` for any token/recipient at :457-465; `StubMailbox`/`StubSecrets`/`StubTransparencyLog` are `Ok(())`/discard sinks), `echo_gateway.rs:81-91`.
- **Exploit path:** none today. Grep over `crates/ spirits/ xtask/ tests/ wit/ schemas/` for `GatewayDispatcher|EchoGatewayFactory|admit_spirit_gateways|unload_spirit_gateways|GatewaySubmoduleRegistry|deliver_inbound` finds **only the leaf's own `tests/`** plus a doc mention in `crates/maos-spirit-abi/src/gateway.rs:14,125` — no maos-bin/kernel production call site (pre-move there was none either; ADR-070 records "still unwired, parked to v2.5"). Exposure is therefore **unchanged** by the commit. The latent hazard: if anyone wires `admit_spirit_gateways` into production Spirit admission, outbound capability verification and TL journaling silently become no-ops (FR54 mediation void), and the code no longer sits behind the kernel surface baseline that would have flagged the wiring (401→380 items).
- **Fix sketch:** add a structural xtask test "no non-test `.rs` under `crates/` names `admit_spirit_gateways`/`GatewayDispatcher::new` outside `maos-orchestrator-buffer`", or `#[cfg(test)]`-gate the stubs so the dispatcher cannot compile into production admission until Task 5's real handles exist.
- **Witness need:** a plant wiring the dispatcher in `maos-bin` must red the new gate.

### F2 — P3 — audit-row writers left every kernel freeze gate; only a maos-bin golden pins their shape
- **Where:** `crates/maos-orchestrator-buffer/src/lib.rs:38,62,82` (`journal_orchestrator_queue`, `journal_director_lifecycle_action`, `journal_token_revocation`); deletions in `docs/ci-baselines/kernel-surface-v0.1-beta.json` (21 triples, verified purged — remaining `orchestrator` hits are the unrelated `WorkingMemoryOrchestrator`), `xtask/kernel-api-classes.toml` (nine rows + banner), `xtask/serde-error-allowlist.toml` (two stale rows).
- **Exploit path:** none at runtime — these are in-process free functions and the callers are unchanged (`maos-bin/src/operator_door.rs:1031,1142,2028,2178`; actor is the `DIRECTOR` constant; the door remains the only external mediation point, unchanged). The regression is governance: director-action audit rows are I2-relevant evidence, and after this commit their format/semantics can drift without tripping `check-service-boundary`/kernel baseline. The one remaining pin is the golden in `crates/maos-bin/tests/orchestrator_equivalence_21_5.rs:169-181`, which does assert the exact row shapes — so drift is caught by a test, not by a freeze gate.
- **Fix sketch:** add a surface-hash row (leaf-scoped baseline, or a `kernel-api-classes`-style registry entry for `maos_orchestrator_buffer::journal_*`) so format changes require an ADR-grade record, matching how the kernel treated them until this commit.
- **Witness need:** a plant changing `journal_orchestrator_queue`'s `reasoning` format must red a gate (today only the equivalence golden reds).

### F3 — P3 — `resume` silently skips replay when the port is `None`
- **Where:** `crates/maos-kernel-core/src/scheduler/scheduler_loop.rs:491-493` (`if let Some(ref port) … else nothing`), field at :89, ctor param at :113.
- **Exploit path:** none today. The only production constructor is `maos-bin/src/main.rs:3029-3036`, which passes `Some(orchestrator_registry.clone())` of the same registry the door enqueues into (`main.rs:2358-2360`); every other constructor call site is test code. And `replay_pending` is an observable identity in sequential use (rotation under one lock), so a skipped call changes nothing observable today. The risk is forward-looking: Story 5.4 frame-level delivery will make this call load-bearing, and a future `None` (or a second arm constructed without the port) would then silently skip instruction delivery with no log, no error, no audit row.
- **Fix sketch:** `debug_assert!(port.is_some(), …)` or a one-line `eprintln!`/telemetry counter on the `None` arm now, and make the field non-optional when Story 5.4 lands.
- **Witness need:** none (assert/log only).

## Assigned questions — answers with evidence

1. **Authority/isolation weakened?** No. The kernel's only remaining touch is `Option<Arc<dyn OrchestratorResumePort>>` + one call before `fire_on_resume` (scheduler_loop.rs:491-495), placed exactly where the old two-lock replay was (creation diff :1312-1322 shows the deleted body). The kernel never mediated *who* could touch the buffer — the operator door (16-1) is and remains the only external entry; in-process reachability is unchanged (leaf is a production dep of maos-bin only; `spirits/orchestrator/Cargo.toml:22` carries it under `[dev-dependencies]`, confirmed by section layout and its `src/lib.rs:43-47` comment). `check-dependency-closure` now forbids the leaf in the kernel/domain closures (`xtask/src/check_dependency_closure.rs:64-66`), so the kernel cannot silently re-absorb it (plant P3 proves the gate trips).
2. **journal_* audit path / I2 fail-stop / journal-before-admit:** identical. Same `TransparencyLogAdapter` type (kernel re-export = `maos_iac`), same `ApprovalDecision` shape, same labels/capability strings, byte-identical bodies (deleted `orchestrator/mod.rs` in creation diff :1091-1188 ≡ leaf `lib.rs:31-100`). Call-site orderings unchanged: enqueue journals **before** enqueue with fail-stop "nothing was enqueued" (operator_door.rs:2028-2045) plus a `queue-refused` row on capacity refusal (:2047-2056); lifecycle journals after the transition and fails the op on row failure (:1031-1040); revocation journals after `capability.revoke()` and fails on row failure with the worker-stop disclosure (:2178-2212). The post-transition journaling on pause/resume/revoke (action already applied when the row fails) is pre-existing design, untouched by this commit.
3. **Resume replay loss/duplication/reordering/capacity/DoS:** the new one-lock rotation (`buffer.rs:90-97`) is correct: `0..q.len()` captured once, each iteration `pop_front`+`push_back` — order preserved, count preserved, no duplication, capacity cannot be exceeded, producers serialize on the same mutex (leaf race test `resume_replay_21_5.rs:66-105`: 2,000 replays vs a spinning producer, 0 accepted enqueues, queue intact). It removes the pre-move loss window (drain under lock 1, re-enqueue under lock 2; tail refused at capacity and dropped — `eprintln!` then gone, creation diff :1312-1321; red 11/11 → green 10/10 per evidence). Unknown Spirit ⇒ `registry.get` returns None, no buffer created (registry.rs:51-56). Poisoned mutex ⇒ silent skip, same as `recall_all_pending` (practically unreachable; `enqueue` uses `into_inner` recovery and never panics). DoS: bounded — ≤32 pointer moves under one guard, no allocation.
4. **`None` resume port:** see F3; production always `Some`; silent skip is a forward-looking hazard only.
5. **Gateway dispatcher / echo host (FR54):** exposure unchanged — zero production callers before and after (grep above); manifests' `[[gateway]]` are parsed into the SCB (`scheduler/control_block.rs:212-213`, `lifecycle/upgrade.rs:414-423`) but nothing admits them, before and after. Latent allow-all stubs: F1.
6. **Dependency additions:** leaf normal deps `maos-capability` + `tokio{rt,time}` (`Cargo.toml:14,18`) are a **strict subset** of what `maos-kernel-core` already depends on (`crates/maos-kernel-core/Cargo.toml:18` maos-capability; `:56` tokio `{sync,rt,time,macros,rt-multi-thread}`; `:46` ring). The leaf's only production consumer is maos-bin, whose closure already contained all of it; `Cargo.lock` gained only the package node and two edges (`Cargo.lock:3124-3136`, maos-bin `:3808`) — **zero new external crates**, so no supply-chain or duplicate-version movement.
7. **cargo-deny / licences:** no impact. No new crates; workspace licence (MIT OR Apache-2.0) is inside `deny.toml` `[licenses] allow`; tokio/dashmap/thiserror unify with existing versions; `multiple-versions = "deny"` cannot trip on this diff.
8. **`check_dependency_closure` FORBIDDEN_CRATES change:** strengthens the gate (one added forbidden crate; checked trees unchanged = kernel-core + domain). Minor gap, folded into F1/F2 posture: the leaf's *own* closure is not a checked tree (wasmtime/postgres/cedar could enter the leaf without tripping this gate) — acceptable for a user-space leaf, worth remembering if the leaf ever grows.
9. **Redaction in moved journal_* functions:** unchanged. Approval rows were never run through the TL frame redactor (`insert_approval_decision` inserts `reasoning` raw, `crates/maos-iac/src/adapter/transparency_log.rs:2605-2629`; only the frame-event path has `payload_redacted`). Token ids keep the colon-hex encoding (`target: "token:{hex}"`, `reasoning: "token={hex}: …"`, lib.rs:88,95) — no raw bytes. `instruction.goal` (director free text) lands raw in `reasoning` — pre-existing, director-tier, explicitly intended ("the row carrying the text", operator_door.rs:2018-2020).
10. **unwrap/expect after serde in moved/new code:** none in production. The leaf `src/` contains no serde calls at all (grep); the only serde+unwrap is the round-trip test `tests/gateway_uninstall_fr65_v05.rs:165-166`, which is outside the serde gate's scope by design (`check_serde_error_handling.rs:105-112` skips `tests/`/`benches`), consistent with the rc-0 gate run and the two deleted stale allowlist rows.

6. "Unbounded `goal` length = memory DoS via 32 × huge strings" — pre-existing validation (non-empty only, maos-domain orchestrator.rs:44-61); director-tier input behind the door; unchanged by this commit; rejected as pre-existing.

10. "Serde unwrap in moved test code violates the gate" — tests are out of gate scope by policy; no production serde in the leaf; rejected.
