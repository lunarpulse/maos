### CR3 — Medium / P2 — Escape literal backslashes in the plain renderer

- **Patch anchor:** `/home/lunarpulse/dev_ws/crates/maos-cli/src/subcommands.rs:5054-5060`.
- **Confidence:** 0.99.
- **Bug / trigger / impact:** The formatter emits controls using backslash-u-brace notation but passes literal backslashes through unchanged. Consequently a principal containing an actual U+0085 and a different principal containing the six ASCII characters backslash-u-brace-8-5-brace render identically. For example, `alice` followed by U+0085 and the literal text `alice` followed by `\u{85}` both display as the latter. These short inputs do not hit the deliberate 256-character cap. MemoryNamespace principal validation rejects ASCII controls, colon and NUL but permits both U+0085 and literal backslash (`crates/maos-domain/src/memory.rs:68-95`), so distinct valid principals can produce indistinguishable human-readable accounting rows. NDJSON remains distinct. This is an encoding collision introduced by the new escaping, not a remaining ANSI byte injection.
- **Exact fix:** Escape literal backslash as two backslashes before the control-character arm; retain the existing control and separator handling, and keep escaping exclusively at the plain rendering boundary. Do not pre-escape report data or NDJSON. If cap truncation is retained, an explicit truncation indicator would make the intentional loss visible, but that is not the defect counted here.
- **Failing-before witness required:** **Yes.** Assert the actual-U+0085 string and the literal escape-spelling string produce different `cost_terminal_field` outputs, then exercise both in separate report rows and confirm NDJSON preserves originals. Include a literal double-backslash input to catch accidental second-pass escaping. The distinction assertion fails on this commit **[INFERENCE]**; the current hostile-control test never includes a literal escape spelling.
