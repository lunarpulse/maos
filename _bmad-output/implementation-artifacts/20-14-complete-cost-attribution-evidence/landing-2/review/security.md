## Findings

**S1 — LOW (availability / dead prune): `cost_scopes` grows without bound; the advertised prune is vacuous in production.**
`crates/maos-capability/src/cap_tokens/mod.rs:118-119` (map), `:273-279` (`bind_cost_scope` does `scopes.retain(|id,_| self.get_scope(id).is_some())`), `:281-284` (`cost_scope`). `get_scope` returns `Some` for any id still in a shard — including expired and revoked tokens — and tokens never leave the ring: `evict_expired` (`crates/maos-capability/src/cap_tokens/shard.rs:76-83`) has **no caller anywhere** (repo-wide grep), a state the 16-1 decisions doc explicitly ratifies ("Tokens never leave the ring (`evict_expired` has no caller)", `_bmad-output/implementation-artifacts/16-1-daemon-post-surface-and-verb-retarget.md:179`). So the retain can only ever drop scopes bound to ids the ring *never held* — exactly the `ghost` case the kernel test exercises (`crates/maos-kernel-core/tests/cost_attribution_20_14.rs:281-296`); its name "stale scopes are pruned" overstates what is proven.
Exploit/impact: one `CostScope` (~0.1–0.2 kB: task_ref ≈ `prefix:`+ULID, optional principal) is retained per bound mint — every shell turn (`shell_host.rs:166-172`), seam pass (`main.rs:4245-4258`), one-shot run (`main.rs:9757-9763`) — for process lifetime; additionally each bind takes the global `RwLock` write and rescans the whole map (O(n) `get_scope` shard lookups per mint → O(n²) cumulative), degrading long-lived daemon boots. Mint rate is root/schedule-bound, not directly Spirit-controlled, so this is slow resource exhaustion / gradual hot-path degradation, not a remote kill.
Fix sketch: store `CostScope` inside `TokenState` (one lifecycle, no second map) or drop the scope in `revoke()`/`revoke_for_spirit()` and on an expiry check in `cost_scope()`; alternatively cap the map. Correct the evidence phrase "scopes of tokens the ring no longer holds are pruned".

**S2 — LOW (input hardening): `parse_session_principal` has no length cap and admits invisible/bidi characters.**
`crates/maos-bin/src/shell_host.rs:132-143`: rejects `:`, `char::is_control()` (Unicode Cc only), and non-UTF-8 — but not Cf/format/bidi/tag characters (U+200B–200F, U+202A–202E, U+2060–206F, U+FEFF, U+E0001…), and any length.
Exploit/impact: an operator-supplied principal containing U+202E/RLO or tags is journaled into every schema-2 cost frame of the boot. The plain report escapes it (`cost_terminal_field`, `crates/maos-cli/src/subcommands.rs:5051-5074`), but the NDJSON path emits it verbatim (serde_json escapes only C0 controls), enabling visual label spoofing in downstream NDJSON viewers; an unbounded length also lands in every frame body — the reader caps `task_ref` at 256 (`subcommands.rs:4869-4875`) but not `principal_id`. Input is root env (operator), hence Low.
Fix sketch: cap length (e.g. ≤128) and reject the Cf/bidi/tag ranges at parse; mirror both caps in the reader's identity check next to the task cap.

**S3 — INFORMATIONAL (surface hygiene): `CapabilityRegistryAdapter::tokens()` is a wide pub handle to the ring.**
`crates/maos-kernel-core/src/capability/mod.rs:283-286` returns `&CapTokensShardRing`, whose pub surface includes `bind_cost_scope`, `issue`, `revoke` (`maos-capability/src/cap_tokens/mod.rs:275`, `:135`, `:286`).
Reachability audit (no exploit today): the WIT host surface exposed to Spirits is frames/recall/context/skills/lifecycle only (`wit/spirit.wit:304-406`) — no inference or capability-registry export; Spirit recall is restricted to kinds 0..=6 and 18 (`maos-iac/src/adapter/log_recall.rs:44-50`, asserted in `maos-iac/tests/log_recall_17_3d.rs:422-425`), so Spirits cannot even read cost frames (kind 29); `maos-wasm-host` references `CapabilityRegistryAdapter` only in its test harness (`tests/equiv_harness.rs:1270-1325`); Spirits receive the root's `mint` closure, never the registry (`main.rs:4225-4260`). All `.tokens()` callers are root-side (`shell_host.rs:120`, kernel emission `inference/mod.rs:409`, kernel test). The kernel's own narrow pattern (`capability_registry() -> &dyn TokenIssuer`, `inference/mod.rs:258-262`) shows the intended shape; `tokens()` abandons it, so any future host function leaking `&adapter` grants root-grade scope minting. Fix sketch: put `bind_cost_scope` on the adapter (or a narrow trait) and gate `tokens()` to `pub(crate)`/test-introspection.

## Asked questions — verified answers

- **Attribution forgery (Spirit minting/choosing scope or principal): none reachable.** `bind_task_scope` is root-only (`shell_host.rs:113-127`; call sites `main.rs:4253`, `:9758`, `shell_host.rs:167`); `MAOS_SESSION_PRINCIPAL` is read exactly once at boot (`main.rs:4207-4209`) and threaded immutably (`with_session_principal`, single caller `main.rs:4660`); emission reads the scope by the *verified* token id and never from `InferenceRequest` (`inference/mod.rs:407-411`, entry verify `check_capability` `:265-281`); worker subprocesses get a constructed env, not inherited host env (`worker_spawn.rs:808-811`, `worker_cli.rs:128-130` returns a curated list), so no nested-boot principal replay.
- **Cross-tenant leakage in `maosctl audit cost-reconcile`: none beyond the by-design operator whole-log view.** Query filters `origin=Kernel`, kind=cost, month bounds (`subcommands.rs:5159-5171`); Ambiguous carries a count only, never member ids (`maos-domain/src/cost.rs:47-54`; emission `inference/mod.rs:435-439`); task ids are root-minted ULIDs; no Spirit-readable kind-29 path exists (recall kinds above). One principal's row never embeds another's identifiers.
- **Stale-scope reuse across revoke/expiry: not exploitable.** Emission happens only after `verify` (revoked/expired fail `check_capability`); token ids never repeat within a boot (`generate_token_id` static counter, `cap_tokens/mod.rs:77-82`); post-call revoke still journaling the old scope is the documented 19-2 fence behavior. Residual memory retention is S1.
- **Kernel error/unwrap/expect after serde in touched code: none.** Emission uses `if let Ok(cost_bytes)` (`inference/mod.rs:474`) and `unwrap_or_default` for clock/proxy errors (`:402-405`, `:422-424`); the reader turns parse failures into warning skips and skips pid-mismatched/oversized-task frames (`subcommands.rs:4853-4875`); all cost math is saturating u128 (`:4885-4900`, `:4950-4975`).
- **SR-3 erasure of principal/task fields: covered.** The kind-29 scrub traverses only identity labels (`LABELS = "principal principal_id task_ref session_principal provider model"`, `maos-iac/src/adapter/transparency_log.rs:2309-2334`), preserving enum tag `kind` and `attribution_source`; non-JSON bodies get the full tombstone (`:2337-2364`); kernel witness `forget_cascade_18_6.rs:195-198`. `task_ref` (ULID-only) carries no principal data, so surviving it is correct.
- **`none (schema 1)` legacy claim: holds.** `task_ref` is `#[serde(default)]` on `CostFrameBody` (`maos-domain/src/cost.rs:117-122`); the reader distinguishes `None`+schema 1 vs schema 2 vs literal spoof strings via the `literal:` prefix (`subcommands.rs:4932-4941`) and cross-checks body pid vs row pid; no Spirit-writable Kernel-origin kind-29 writer exists.
- **TL redactor interplay: no bypass, no mangling.** Kernel kind-29 payloads are stored verbatim at insert (`transparency_log.rs:2557-2561` binds `payload` directly into `payload_redacted`); the only rewrite is the erasure-time scrub above; spirit names embedded in seam task_refs are grammar-bound `[a-z0-9-]` ≤128 (`maos-manifest/src/manifest.rs:392-414`), so no newline/control injection into frames or reports (plain output additionally escapes, NDJSON residual folded into S2).

## Rejected candidates

1. Spirit mints/chooses its own cost scope or principal — no Spirit-reachable path (see S3 audit).
2. `MAOS_SESSION_PRINCIPAL` as shell-turn/request input — single boot read, immutable threading.
3. Forged kind-29 frames / `none (schema 1)` label spoofing — Kernel-origin filter + literal: defusing + pid cross-check.
4. Cross-tenant leakage via cost-reconcile or Spirit recall — operator-only view; recall kinds exclude 29.
5. Stale-scope reuse after revoke/expiry — verify gates emission; ids never reused (memory retention = S1).
6. Log injection via newline/control in principal or task_ref — boot validation + name grammar + JSON/terminal escaping (residual = S2).
7. Kernel panic on hostile serde input in touched code — none found.
8. Worker env replay of the session principal — worker env is constructed (`nonsecret_env` curated), not inherited.
