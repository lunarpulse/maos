## What Was Challenging

### 1. Circular dependency `kernel-core ↔ director-surface` discovered mid-Story 3.3

Story 3.3's spec placed `HaltResolver` trait at `crates/maos-kernel-core/src/halt/resolver.rs`. But Story 3.1 had already landed `NotificationDispatcher` consumers in `kernel-core` (the IAC bus emits notifications). `director-surface::HaltFlow` needs to call `HaltResolver::resolve`. Importing the trait from `kernel-core` into `director-surface` while `director-surface` is already a `kernel-core` dependency creates a cycle.

**Resolution in-story:** trait + `ResolveError` moved to `maos-domain::halt`. `kernel-core::halt` re-exports the trait. Public API surface from a consumer's perspective is preserved (`use maos_kernel_core::halt::HaltResolver` works); only the source crate changed. `MockHaltResolver`, `FailingHaltResolver` ship from `kernel-core::halt` (test doubles stay where the kernel-side machinery lives). Dev record at `crates/maos-domain/src/halt.rs:1-30` documents rationale.

**Why this matters for E4:** Story 4.1 (Halt Protocol Mechanism — SINGLE HALT OWNER) introduces `KernelHaltResolver` and many `invoke_halt` call sites. If Story 4.1's author reads the spec literally (`crates/maos-kernel-core/src/halt/resolver.rs`), they will revert the relocation and reintroduce the cycle. **A1 below makes the Story 4.1 spec amendment explicit.**

### 2. `MockHaltResolver` wired in production `main.rs` with no compile-time guard

Story 3.3 AC closing requires a production-runnable Director's Surface; Story 4.1 owns the real `KernelHaltResolver`. The v0.3-β bootstrap wires `MockHaltResolver` in `crates/maos-bin/src/main.rs` so `halt-resolve` end-to-end smoke tests work today. Dev record cites the swap point explicitly.

Risk: nothing fails the build if Story 4.1 ships and the swap is forgotten. A `#[cfg(test)]` gate on `MockHaltResolver` would catch this at compile time, but `MockHaltResolver` is also used in production-binary `main.rs` (intentionally, as bootstrap) — the `cfg(test)` gate would break the current build. **A2 below scopes a Story 4.1 CI gate that fails if `MockHaltResolver` appears in a `--release` binary post-Story-4.1.**

### 3. `EpistemicHaltPayload` and `NotificationEvent` pub fields bypass constructor validation

Both types use `pub` fields per the crate-wide `frame.rs` convention. The `::new()` / `::anomaly_flagged()` constructors validate NaN, empty strings, and threshold ranges; struct-literal construction (e.g., `EpistemicHaltPayload { tag: "".into(), value: f64::NAN, … }`) bypasses every check.

**In-tree risk today: low** — every in-tree call site uses the constructors. **Risk at E4: medium** — Story 4.1 spawns many `HaltPayload` construction sites in `invoke_halt` and the kernel-side halt state machine. Story 4.2 adds tagged-scalar predicate-firing payload writes. The convention will get tested.

Two paths exist:
- **(a) Seal the validation:** make fields `pub(crate)` + ship `pub` getters + `Builder` for cross-crate construction. ABI-additive (getters are new). Forces every external constructor through the validated path. Cost: API surface grows; pattern diverges from rest of `frame.rs`.
- **(b) Accept and document:** add `#[doc = "Construct via [`::new`] to enforce validation; struct literals bypass NaN/empty checks."]` on each pub field. Pattern-consistent. Cost: relies on author discipline at E4 call sites.

**Charlie leans (b)** per pattern-consistency. **A3 below makes the choice an explicit Story 4.1 decision rather than an inherited default.**

### 4. I12 integration test landed at spec path only after review iteration

Story 3.3 AC5 specified `crates/maos-audit/tests/i12_decision_audit_test.rs`. Initial dev pass placed the test inline in `crates/maos-kernel-core/src/iac/mod.rs` because `IacBusAdapter::deliver_typed` is `pub(crate)`. Review caught it. Resolution (per Review Decision F4 in story 3.3 line 1163): wrote a real `crates/maos-audit/tests/i12_decision_audit_test.rs` exercising the `maos-audit::query` *public read surface* instead of the `pub(crate)` write path. The test now verifies I12 from the consumer side (the `maos-audit` consumer sees `working_memory_digest_refs` populated on 100% of `decision.*` frames) which is arguably stronger than the original spec — it tests through the boundary, not behind it.

Pattern lesson: **specs that name a test file path implicitly commit to the visibility of every API the test consumes**. Story 3.3 spec didn't anticipate the `pub(crate)` constraint. Better pattern: spec the *consumer surface* the test must exercise, leave file location to dev judgment. **A4 below threads this back into the story-spec template via `bmad-create-story`.**

### 5. Test-infrastructure forking in `director-surface::halt_ui.rs::tests`

`halt_ui.rs::tests` defines local `TestResolver`, `FailingResolver`, `CaptureChannel` instead of importing the canonical `MockHaltResolver` from `kernel-core` and the `CaptureChannel` from `approval_prompt_e2e.rs`. **Cause: circular-dep avoidance** — `director-surface` can't depend on `kernel-core` for test-only types because the production crate doesn't depend on `kernel-core` (Story 3.3 inverted the dependency by moving the trait to `maos-domain`).

The Epic 2 retro's "reuse, don't reinvent" principle is violated by architectural constraint, not by author oversight. **No action item** — this is the cost of the circular-dep fix and the right trade-off.

### 6. `shift_posture` TOCTOU race on `ArcSwap<PolicyTableInner>` (pre-existing, surfaced in 3.2 review)

Concurrent `shift_posture` calls on different Spirits can lose updates via the read-clone-modify-store sequence on `ArcSwap`. This is a pre-existing limitation of the CoW pattern shared by all `PolicyTable` mutations including `manifest_scopes`. Not caused by Story 3.2.

**Owner: not E3, not E4.** Would require a CAS loop or mutex. Out of NFR-Perf-4 budget (the CAS loop adds bounded retry overhead — measure first). Deferred without action item; tracked at `_bmad-output/implementation-artifacts/deferred-work.md`.
