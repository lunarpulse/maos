## ⚠️ PREFLIGHT FLAGS (landmines — read first)

### L1 — "Two regions" today is one shared Postgres table; a 3-region *pilot* over one table is theater.
`make_store(region)` (`cross_region_live.rs:65-75`) passes the **same** `pg_conn()` to every store; both regions hit the **same physical `collective_memory` table**, differentiated only by `home_region`. `PG_LOCK` (`:54`) exists precisely because they share a table. A pilot that claims "3 regions converge" over one table proves nothing about cross-region propagation and cannot exhibit a foreign-row-read-fails-closed (F4) — the row is in the region's own table. Real isolation = three connection strings / three tables (F2).

### L2 — Cross-region latency across two machines' `Instant`s is a category error.
`recv_instant − emit_instant` (`harness/j4.rs`) assumes one process, one monotonic clock (`:117`). Region B's `Instant` is not comparable to region A's. Any cross-region "latency" computed as `B.instant − A.instant` is **garbage** (could be negative, could be dominated by clock offset). Use a single-clock round-trip (F5). This is the #1 way a naïve SLO gate ships a meaningless green number.

### L3 — The read-path enforcement will *want* to be a kernel `ReadEntryPoint` variant. It must not be.
11.2a landed the **write**-side `WriteEntryPoint::CrossRegionReadmit` kernel arm (authorized +≤16 LOC). The symmetric temptation for AC3/F4 is a `ReadEntryPoint::CrossRegionRead` arm — but 11.2b is **ZERO kernel delta**. Enforce below the port (F4). If the dev finds enforcement *genuinely impossible* below the port without a kernel touch, that is a **preflight escalation** (a FLAG-Winston re-pin request), not a silent kernel edit — STOP and disclose.

### L4 — The SLO/halt metrics must each red for exactly ONE break (falsifiability).
Murat's rule (from 11.2a AC5): the gate is "ONE registry entry / ONE disposition / N independently-falsifiable legs" — breaking one subsystem reds exactly one leg. Do NOT `AND` the RTT budget, the halt-observability metric, and the read-path-identity verdict into a single `oracle_green` such that a latency regression masks a correctness failure (or vice-versa). This is why the SLO gate is a **separate** gate from `check-cross-region-consensus` (F/gate-infra: different measurement source + different falsifiability domain).
