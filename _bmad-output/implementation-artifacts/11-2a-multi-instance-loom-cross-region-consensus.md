## Story

**As** the MAOS operator running a multi-region Cortex,
**I want** the Loom collective-memory tier to converge across regions via a **TL-anchored CRDT with mediated re-attestation** — never transparent row replication — proven by an **independent per-region convergence oracle**, holding a **region-identity reflex** over every propagated row, and degrading **AP-locally** (Collective→Private/Shared, no global halt) on partition,
**So that** cross-region collective memory becomes **eventually-consistent-by-construction and cryptographically-auditable** while the 9.4b region weld (NFR-Comp-4: cryptographic enforcement against cross-region replication) stays intact — a copied foreign-region row fails closed, a re-attested one carries destination-key provenance, and ADR-049 stops being `Proposed` and becomes a **mechanically-falsifiable, ship-blocking** `binding-v2.0` requirement.

So "reuse as-is" is not actually available — you either add a field to `ReplayApply` (breaks its tests/semantics) or add a new variant. The new variant is cleaner.
- The touch is **provably bounded and compile-gated**: the `WriteEntryPoint` match at `write_entry_point.rs:52` is **exhaustive, no `_ =>` wildcard anywhere** (a deliberate AC-9 type-guard, docs `:11-16,22-24,49-50`). ## ⚠️ PREFLIGHT FLAGS (read first — the landmines that make a naïve gate vacuous or false-RED)

### L1 — Blind LWW is NOT convergent; the store overwrites unconditionally and re-mints the timestamp.
`store.rs:188-191` is `INSERT … ON CONFLICT (spirit_pid, namespace_kind, namespace_detail, key) DO UPDATE SET value_kind=$5, value_data=$6, timestamp_ns=$7` with **no `WHERE EXCLUDED.timestamp_ns > collective_memory.timestamp_ns` guard** — last arrival wins, so final state depends on arrival ORDER (ADR-049 §"Keep current blind LWW" — rejected). And the timestamp at `:181-184` is `SystemTime::now()` **at apply time**, not the caller's/source's. A CRDT LWW-register needs a **conditional** upsert keyed on a **source-preserved** total order. This is the core mechanism change (all in `maos-loom-lite`).

### L2 — The 10.4b oracle canonicalizes TL frames, NOT collective-memory rows. Do not reuse `CanonicalFrame` verbatim.
`canonical.rs::CanonicalFrame` (`:59-77`), `to_canonical_bytes` (`:81`), `compute_payload_oracle` (`:142`), `merkle_root_from_frame_ids` (`:160`), `read_sqlite_frames`/`read_postgres_frames` (`:185/:281`) all speak the **11-column `transparency_log`** shape. The `collective_memory` KV row shape (`schema.rs:33-60`) is different. **Reuse the PATTERN** (pinned engine-independent byte layout, SHA-256 leaf hash, sorted-multiset payload oracle, `maos_audit::erasure::merkle::build_tree_from_frame_ids`) but author a **NEW** canonical-leaf serde for KV rows. The `read_postgres_frames<C: GenericClient + Sync>` **generic-over-`Transaction`** design (`:281`) is the template that lets you re-derive oracles from **uncommitted** rows before commit (verify-/converge-before-commit).

### L3 — The Merkle root is a SET oracle, blind to payload/dedup/order. The payload oracle is what bites.
10.4a §5 (Murat, BLOCKER): the frame-id-only Merkle root depends only on the sorted+deduped id set. A single-byte payload corruption leaves the root MATCHING while the payload oracle mismatches. The convergence claim REQUIRES all three — Merkle **and** payload-multiset **and** exact row-count — each **independently re-derived per region on read-back**, never co-computed once and written both places (the 10.2 self-reported-aggregate trap), never read from a cached metadata table.

### L4 — Copied ≠ replicated. The weld makes transparent replication fail closed — build ON that, not around it.
`verify_bundle` verifies against a **caller-supplied** pubkey (`sealed_export.rs:235-239`); a foreign-region row COPIED into the destination and verified under the destination key fails (Ed25519 mismatch — the region tag is inside the signed digest, R-RG4′ `sealed_export.rs:396-413`). This is the property the design rests on. The proven-red must OBSERVE the copy path go RED **before** the re-attested path goes GREEN (D15d: negative controls proven-red FIRST).

### L5 — Region enforcement on the collective tier does not exist today.
`collective_write/read/scan` (`mod.rs:210/274/317`) do cap-mediation only, no `enforce_region`. The trait-path `enforce_region` chokepoints (`mod.rs:683/770/824/863`) are `DirectWrite`/`DirectRead` on private/shared. So cross-region logic on the Loom path starts from **zero** region enforcement. Whether that enforcement lands in kernel-core (FLAG-Winston) or below the port (loom-lite) is F1.

### L6 — No mediator, no downgrade router, no encryption. All greenfield; all sign-only.
A repo-wide sweep returns ZERO for `mediat|re-attest|re-sign|re-admit|downgrade|readmit|CrossRegion|CRDT|gossip|anti-entropy|Raft`. The `verify→re-admit→re-sign→stamp` mediator and the Collective→Private/Shared downgrade router are entirely new. **AEAD/encryption is confirmed ABSENT** (`aead|encrypt|chacha|aes|cipher` = 0 hits in `maos-audit`; deps are only `ed25519-dalek`+`sha2`+`hkdf`). Sign-only, plaintext rows (ADR-049 §Context correction; ADR-047 D1 waiver). Do NOT introduce an AEAD site — none exists and citing one is inventing code.

### L7 — `RegionSection` exists; `RegionTag` does not.
Correcting a common mis-statement: there is **no per-row `RegionTag`** type, but `RegionSection { home_region: Option<Region> }` DOES exist as the operator.toml `[region]` config (`crates/maos-kernel-core/src/security/operator_config.rs:166-169`, wired at `maos-bin/src/main.rs:1802,6761`). Region binding is **governance-only** (operator `RegionSection` home_region + entry-point chokepoints), not a tag on the row. `Region::canonicalize(&str)` (`region.rs:56`) is the only constructor — all `Region` values are `ascii-v1` canonical by construction, so two spellings derive the identical key.

## Acceptance Criteria (6 — at the §A5 ≤6 ceiling; AC5→AC5+AC6 split ratified at preflight)

**AC1 — Timestamp-aware CRDT LWW merge replaces blind overwrite; convergent regardless of arrival order (ADR-049 §1)**
**Given** the `collective_memory` grow-only target-tuple set whose write today is an **unconditional** `ON CONFLICT … DO UPDATE` with a re-minted apply-time timestamp (`store.rs:188-191, 181-184` — final state depends on arrival order)
**When** cross-region and concurrent same-region writes to the **same target tuple** arrive in **any order**
**Then** the merge resolves by a deterministic total order **`(timestamp_ns, region, frame_id)` lexicographic** — a **conditional** upsert that overwrites **only** when the incoming order-key strictly dominates the stored one — so the converged value is **identical regardless of arrival order** (the CRDT LWW-register-over-grow-only-set property), all in `maos-loom-lite` (`store.rs` merge; no kernel edit)
**And** the ordering key is **carried from the source write** and **preserved across re-attestation apply** (NOT re-minted on apply — re-minting destroys convergence), and the tiebreak columns the total order requires (a region/origin column + the source frame_id — **neither exists on `collective_memory` today**, `schema.rs:33-60`) are added via a `maos-loom-lite` schema migration with the **UNIQUE target tuple unchanged**
**And** a **reorder-independence proven-red**: applying the same write-set to two instances in different orders yields **identical converged state** (the AC3 oracle triple matches); a regression to blind unconditional overwrite (arrival-order-dependent final state) drives the gate **RED** — the convergence is **derived from the actual merged rows**, not asserted
**And** the merge is **byte-exact and deterministic** — no `HashMap`/hand-ordered map enters the canonical row bytes (the `canonical.rs` determinism-by-field-order discipline).

**AC2 — Mediated re-attestation across a region boundary; transparent replication is proven-impossible (ADR-049 §2, NFR-Comp-4)**
**Given** a source-region collective bundle signed under the source region's TL-derived key (`derive_region_signing_seed(base_seed, source)`, `sealed_export.rs:26`) with the 9.4b weld (region tag covered by the Ed25519 signature, R-RG4′ `sealed_export.rs:396-413`)
**When** a row crosses into the destination region
**Then** it transits a **mediator** (orchestration in `maos-loom-lite`, verification/signing in `maos-audit`) that (1) **verifies** the source bundle via `verify_bundle(&bundle, &derive_region_pubkey(base_seed, source))` (`sealed_export.rs:235,40`); (2) **re-admits** it through the destination region chokepoint (F1: kernel `CrossRegionReadmit` arm OR below-port loom-lite enforcement); (3) **re-signs** under the destination key via `sign_bundle(rebuilt.with_region(dest), base_seed)` (`sealed_export.rs:196,121`); (4) **stamps** cross-region `source_log_ref` provenance naming the source region + its TL frame_id (extending the intra-region single-region field, `schema.rs:47`), plus a home/control-plane-key-signed **region-neutral `ReAttestationReceipt`** naming {source_region, dest_region, source digest} (imitating `regional_teardown.rs:192`)
**And** transparent row replication is **proven-red-impossible** (the negative control observed **RED FIRST**, D15d): a foreign-region row **COPIED** (not re-attested) into the destination and verified under the destination key **fails closed** (`verify_bundle` Ed25519 mismatch under the wrong region key) **before** the **re-attested** path is accepted GREEN (carries destination-key signature + cross-region provenance) — there is **no** transparent-replication code path anywhere
**And** **NO mock/loopback** stands in for the crypto (real HKDF-derived keys, real Ed25519 sign/verify; §A7.2 real-subsystem reflex), and **no AEAD/encryption** is introduced (sign-only; the `maos-audit` crypto-dep closure stays `{ed25519-dalek, sha2, hkdf}`)
**And** the crossing UNIT is a **`CrossRegionReplicationBundle`** (`maos-loom-lite/src/replication/`) — `{schema_version, source_region, root:[u8;32] over build_tree_from_leaves, leaves:Vec<CollectiveKvLeaf>, region_sig}` — signed with `derive_region_signing_seed(source_region)` (the 9.4b TL-derived key; NO new key), over `SIG_DOMAIN || schema_version || source_region || root`; **`AuditBundle` is NOT reused** (KV shape ≠ audit shape); `verify_bundle`'s pubkey is ALWAYS `derive_region_pubkey(claimed_source_region)`, NEVER a pubkey carried inside the bundle (else forgery is a one-liner)
**And** the **dropped-audit-orphan tripwire** (ADR-049 §7; SHIP-BLOCKER if unhandled): because `verify_and_audit` fires a **droppable** fire-and-forget `CapAuditEvent::Verify` (`record_drop()` under backpressure) while `port.write` persists, a re-attested+converged row can exist with its **authorization**-audit frame never landed — the bundle establishes **origin** provenance (which region signed the bytes), NOT **authorization** provenance. Resolution (Option B): reconciliation **counts "row present, authorization-audit absent" as an observable state**, never rolled into a clean "converged" total; **proven-red**: fire `record_drop()` on a converging row → assert it is reported as origin-attested-but-audit-orphaned (if the code cannot distinguish an audited from an orphaned row post-convergence → SHIP-BLOCKER). No AC or doc may claim the bundle establishes authorization provenance (origin ≠ authorization).

**AC3 — Independent per-region convergence oracle over collective-memory rows + region-identity reflex (ADR-049 §4, §Gate)**
**Given** two regions' converged `collective_memory` state
**When** convergence is asserted
**Then** it is **MEASURED** by re-deriving the 10.4b oracle **triple** — `canonical_kv_leaf` serde + Merkle root (`maos-audit`'s `build_tree_from_leaves(&[[u8;32]])`, generalized from `build_tree_from_frame_ids` which becomes a 2-line wrapper — preserving 9.x `AuditBundle` byte-identity) + payload oracle (sorted multiset of per-row SHA-256 leaf hashes) + **exact row-count** — **INDEPENDENTLY per region on read-back, over a re-derivation genuinely INDEPENDENT of the write codec** (no encode-then-decode-with-the-same-buggy-codec tautology); two regions are converged **iff ALL** oracles match; the empty-set case is reported **N/A, not a meaningful pass** (the D5 vacuous-green trap)
**And** because the shipped 10.4b oracle canonicalizes the 11-column `transparency_log` frame shape (`canonical.rs:59-165`), **NOT** the `collective_memory` KV-row shape, a **NEW `canonical_kv_leaf`** (`maos-loom-lite/src/replication/leaf.rs`) is authored — domain-separated (`KV_LEAF_DOMAIN`), **u32-BE length-prefix on EVERY field**, fixed order `(source_region, source_ts, spirit_pid, namespace, key, value)`, hashing the **source-authoritative `source_ts`/`source_region`** (the F3-preserved columns), **never** store-minted ts (`CanonicalFrame` NOT reused, L2); the **payload oracle catches a single-byte divergence** the frame-id-only Merkle root is blind to (L3)
**And** a **canonicalizer field-coverage proven-red** (Murat, SHIP-BLOCKER on a silent gap): for EVERY persisted crossing column, a row-pair differing ONLY in that field yields DISTINCT leaves — at minimum `region-only-diff`, `ts-only-diff`, `value-only-diff`, and `boundary_shift_no_collision` (`region="ab" key="c"` vs `region="a" key="bc"` must NOT collide — the length prefix is load-bearing, not decoration); a silently-excluded column is a SHIP-BLOCKER, an intentionally-excluded local surrogate is asserted-excluded + documented; reds assert inequality of non-empty digests (a stub returning `[]` cannot pass)
**And** a **region-identity reflex** (ADR-049:86): the count gate over propagated rows **cryptographically verifies each row's source-region identity** (Ed25519 under `derive_region_pubkey(source_region)`, from the AC2 re-attestation provenance) — **not merely counts** — and ships its **own proven-red**: a propagated row carrying a **forged/mismatched source-region** → gate **ERRORS** ("unverified source-region", never counted as converged); a same-region self-comparison masquerading as cross-region is rejected (the vacuous-tautology guard, analogue of `same_form_pair_rejected` `equiv_harness.rs:1145`)
**And** the region-identity forge negative-control **moves a real number** (one variable flipped — sign region B's rows with A's/attacker's key → rejected AND the converged count changes), and a **single-region loopback config** (one region writes+attests+verifies itself) **MUST NOT count as cross-region provenance** (produces a failing/N-A result ≠ the genuine two-region cross — "loopback is theater")
**And** a **planted single-byte divergence** proven-red: one region's row mutated by one byte → **payload-oracle mismatch → RED while the Merkle root still matches** (proves Merkle insufficiency, 10.4a §5); PLUS a **set-vs-sequence red** guarding `source_log_ref`'s merkle-root — two histories with the **same leaf set but different arrival order** (a lower-`source_ts` write arriving last) must NOT be conflated by a root-keyed dedup (the root is a SET oracle, not a sequence oracle); the numerator (matched-row / source-region-verified count) is **derived-and-reconciled per row** from the actually-read rows, **never** from a committed summary (§A7.1).
