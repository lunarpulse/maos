## Story

As **Lunarpulse (founder-operator)**,
I want **one command that runs the J1 founder-loop on my machine and narrates every journey beat with its evidence state**,
so that **I can watch, show, and (optionally) sign what J1 actually proves today — and the same command lights up new beats as the crosshost rungs (1a → 1b → crosshost-2) land, until it becomes the J1 journey closer**.

## Context — why this story exists (2026-08-14 rehearsal findings)

A D0 rehearsal (`./target/debug/maos run spirits/topologies/j1-founder-loop.toml --once`, local build, 5.2s wall) proved the local leg live: 3 class spirits loaded, fixture worker admitted under T3 host grant, real subprocess (`child_pid`), `worker_completion completed=true` with `completion_tl_ref`, clean `--once` exit. It also surfaced three defects/warts this story must handle:

1. **Journal corruption noise** — the operator's shared `~/.local/share/maos` state carried 2 corrupted lifecycle-journal lines (`journal: WARNING — skipping corrupted line 115/116 … Consider rotating the journal`; emitter `crates/maos-kernel-core/src/journal/mod.rs:113-138`). Verdict: **PROVISION-AROUND** (isolated state home per demo run; no rotation CLI exists today).
2. **Cap-token mediation fallback** — `cli_wrapper cap-token mediation not granted … proceeding under AC5 host-grant authority (operator policy proc.exec grant is Epic 9 surface)`. The fallback is **by design** pending the Epic-9 operator policy surface: the wrapper path performs host-grant resolution but never registers the manifest with SecurityManager, and `PolicyTable.evaluate` denies unknown pid/scope — so even a Cedar permit via `MAOS_PDP_POLICY_FILE`/`_INLINE` cannot green this path by itself (`crates/maos-bin/src/main.rs:949-1020,1132-1166,199-242`; `crates/maos-kernel-core/src/capability/cap_policy/mod.rs:127-149`; `crates/maos-kernel-core/src/security/mod.rs:338-360`; `deferred-work.md:39-40`). The `CapabilityInvocation` exit row IS journaled synchronously (`runtime.rs:635-684`). Verdict: **NARRATE** honestly.
3. **Audit-writer drain timeout (5.0s of the 5.2s wall)** — `maos run: audit writer topology drain timed out after 5s`. Root cause traced: the `--once` branch drops `audit_tx`/inference/capability/orchestrator/scheduler/lifecycle senders but **not** the memory adapter; `MemoryManagerAdapter` retains `Arc<CapabilityRegistryAdapter>` which owns an `audit_tx` clone, so the writer channel never closes and queued rows can be **lost at process exit**. A later `maosctl audit sealed-export` can therefore miss rows. Verdict: **FIX-IN-STORY** (evidence-integrity defect, proven-red).

### Review Findings — code review 2026-08-15

Four parallel layers over `6827dc87..HEAD` (1799-line diff): Blind Hunter, Edge Case Hunter, Acceptance Auditor, Test Infrastructure Auditor. The Test-Infra layer was added even though the `persistent_facts` rule does not require it for a Claude dev model, because this story's deliverable **is** claim-making machinery. All four independently rated the change set incorrect. Severities below are this workflow's, not the subagents'.

**The pattern behind almost every finding: the free path was verified and the paid path was not reachable by any test, so every defect clustered exactly where verification could not go.** `--live-codex` would have failed — or worse, signed something false — on its first real use.

- [x] [Review][Patch] **`verify-bundle` was invoked without its required `--pubkey`, so every paid take would die at argument parsing AFTER the money was spent** [`xtask/src/demo_j1.rs`] — `maos-cli/src/cli.rs` declares `pubkey: String` with no default. Found by the Acceptance Auditor and Blind Hunter independently, both at confidence 1.0. Fixed: `run_checked` now returns the command's combined output, `pubkey_hex` extracts the 64-hex key that `sealed-export` prints, and it is passed to `verify-bundle`; a missing pubkey is a refusal, never a guess. Unit test `the_sealed_export_pubkey_is_carried_into_verification` pins the parse and rejects short, long, and non-hex tokens.
- [x] [Review][Patch] **`--live` was passed without `--once`, so a SUCCESSFUL paid take would hang forever** [`xtask/src/demo_j1.rs`] — `maos run` falls through to the continuous serving loop unless `once` is set (`maos-bin/src/main.rs:5232`), and `.output()` waits for exit. The worker would complete, the operator would pay, and the scene would never reach capture, sealing, or verification. Fixed: `--once` added.
- [x] [Review][Patch] **The daemon path was repo-relative while the child's cwd was changed, so the live take could never spawn** [`xtask/src/demo_j1.rs`] — `preflight` stored `target/debug/maos` and the live take set `current_dir` to `<home>/demo-workspace`, where that relative path does not resolve. Fixed: `preflight` canonicalizes `target/debug` once, which also fixes the `PATH` prepend and the `maosctl` sibling lookup.
- [x] [Review][Patch] **A fixture take could have earned `PROVEN_LIVE_SIGNED`** [`xtask/src/demo_j1.rs`] — the code accepted the first `worker_completion` with `completed: true` and never checked the daemon's exit status or the worker identity. Since the topology is operator-authored, pointing it at the hermetic fixture reached capture, sealing, and the Tier-2 label. Named by three of four layers. Fixed: nonzero daemon exit is a refusal, `identity != "codex"` is a refusal, and a drain timeout or `audit writer task failed` on stderr is a refusal — refuse, never downgrade.
- [x] [Review][Patch] **`redaction_result: "verified"` was a hard-coded literal inside a SIGNED capture** [`xtask/src/demo_j1.rs`] — `record-capture` only validates that the field reads `"verified"`, so nothing ever checked for the secret. An unearned control claim was going under an Ed25519 signature. Fixed: the real `CODEX_API_KEY` value is now searched for in the daemon's stdout/stderr **and** in the sealed bundle's own bytes, and a hit is a refusal. The secret is never printed.
- [x] [Review][Patch] **A stale local evidence ledger could promote a beat that FAILED in this run** [`xtask/src/demo_j1.rs`] — `apply_published_ledgers` overwrote every matching beat unconditionally, and outside GitHub Actions `load_published_ledgers` has no build binding to compare, so a green `tests/reports/evidence-ledger-*.json` left by an older checkout could bury a live gate failure and exit 0. This defeated the demo's entire reason for existing. Fixed: a ledger may still LIGHT a beat this run never executed, but it can never PROMOTE one this run watched fail; the ignored claim is printed instead.
- [x] [Review][Patch] **The `audit-drain-clean` beat read green when the audit writer's join FAILED** [`xtask/src/demo_j1.rs`] — the daemon prints `audit writer task failed during topology drain` and still exits 0 (`maos-bin/src/main.rs:4314`); the beat only looked for the timeout string. Queued rows are not proven persisted in that case. Fixed, plus test `a_writer_task_failure_fails_the_drain_beat`.
- [x] [Review][Patch] **My own F2 gate repair was bypassable** [`xtask/src/check_j1_loopback_delegation.rs`] — `absent_router_branch_fails_closed` normalized the WHOLE file, so replacing the production fail-closed closure with a local-delivery fallback kept the Blocking leg green as long as an identically-shaped expression survived inside a `#[cfg(test)]` module. The function's own doc comment already claimed it excluded test code; the code did not. Fixed by applying the existing `production_before_tests` helper and requiring the error to be the closure's first expression. New 11th planted regression `route_locally_anyway_but_keep_a_matching_expression_in_a_test_module`; all **11** still RED.
- [x] [Review][Patch] **AC1's `cli_wrapper_exit` and `on_idle_fired` ×3 were never parsed** [`xtask/src/demo_j1.rs`] — AC1 names both as evidence and the scene read neither, so a run whose worker never reported an exit, or whose Spirits never went idle, still narrated success. The "full post-1a stream" fixture omitted both events and asserted all beats passed. Fixed: new `worker-exited-and-loop-went-idle` beat (non-crash exit + exactly three idle callbacks, measured 3/3 against a real run), fixture extended with the real event shapes, and three negative tests.
- [x] [Review][Patch] **The claim table was titled "execution order" without verifying order** [`xtask/src/demo_j1.rs`] — each beat independently took the FIRST event with a matching name, so a stream whose completion preceded its own delegation, or which repeated a stage, satisfied every beat. Fixed: new `lifecycle-stages-in-order` beat requires the five lifecycle stages exactly once each and in sequence, with two negative tests.
- [x] [Review][Patch] **A non-empty `--keep-home` silently mixed runs** [`xtask/src/demo_j1.rs`] — a retained journal and transparency log from a previous take were read by the new run, and on the signed path `sealed-export --range 1d` would have covered the previous run's rows. Fixed: a retained home must be empty or absent, and the path is canonicalized so the live child's `current_dir` change cannot reinterpret it.
- [x] [Review][Patch] **The state home leaked on every error path, and the scene claimed removal it had not checked** [`xtask/src/demo_j1.rs`] — cleanup sat near the end of `run`, after roughly a dozen `?` returns, and its `remove_dir_all` result was discarded while still printing success. Fixed: an `EphemeralHome` guard removes it on every return; the normal path still removes explicitly and now reports a failure truthfully.
- [x] [Review][Patch] **`--keep-home` echoed an absolute workstation path, violating AC5** [`xtask/src/demo_j1.rs`] — AC5 forbids absolute workstation paths in scene output. Fixed: only the path's leaf is rendered.
- [x] [Review][Patch] **The ceiling record's arithmetic did not reproduce** [`xtask/kloc.toml`, this file] — see the measurement note in Completion Notes. Corrected against a per-commit measurement.
- [ ] [Review][Known limitation] **The scene waits on its subprocess with no deadline** [`xtask/src/demo_j1.rs`] — both `run_scene` and the live take use `Command::output()`, so a daemon that never exits (documented stale-binary failure mode under `--skip-build`) hangs the command. Left as a recorded limitation rather than a fix nobody asked for; if it ever bites, it belongs to whoever next touches `run_scene`.
