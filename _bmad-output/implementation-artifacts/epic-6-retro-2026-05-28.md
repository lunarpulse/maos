## What Was Challenging

### 1. Story 6.3 shipped `done` with 22 OPEN patches — Story-5.5d-class regression at a different injection point

Story 6.3 (A2A peer mesh — loopback v0.8 + cross-Host v1.0 + mTLS rotation chaos) received formal `bmad-code-review` on 2026-05-26. The review surfaced:
- **3 `decision-needed` rows OPEN**: D1 (IntentClass projection to allowlist strings uses `format!("{:?}", ...)` — Debug-derived unstable enum discriminant); D2 (`A2AError → IacBusError::CrossHostRouteFailure(String)` loses all typed error discrimination — ADR-010 layering constraint cited); D3 (cross-host route failure aborts same-host delivery — partial delivery semantics undefined).
- **22 `patch` rows OPEN**: P1 [Critical] TOFU pin verification never invoked in `handle_intake` or `route_outbound` — entire security surface scaffold-only; P2 [Critical] Consent envelope expiry check is a stub — `valid_until_ns` never validated, any frame with expired consent silently admitted; P3 [High] Duplicate `A2ARouter` trait with same name + different signatures in `maos-a2a` vs `maos-domain`; P4 [High] CI `a2a-loopback-corpus-v0` job references non-existent `--test` targets — guaranteed CI failure if not soft-fail; P5 [High] `handle_intake` falls back to first configured peer on `lookup_peer` failure — security bypass (forged host_id admitted against random peer's allowlists); P6 [High] `boot_nonce` missing from JSON-RPC request wire — `SpiritRestartDetected` error variant is dead code, NFR-Rel-6 unreachable; P7 [High] `CODE_PARSE_ERROR (-32700)` defined but never emitted — JSON parse errors propagate as raw serde errors; P8–P22 [Medium/Low] covering re-pin `boot_nonce: 0` hardcode (P8 — breaks restart detection after re-pin), `LoopbackTlsConfig` `'static` lifetime impossible-to-load-from-disk (P9), `pinned_at_ns` wall-clock vs monotonic mismatch (P10), `verify_pinned` NotPinned conflation (P11), NACK timestamp loss (P12), PinMismatch fingerprint details flattened (P13), duplicate peer_id silent overwrite (P14), `pin_first_contact` silent overwrite (P15), `clone_key` `unreachable!()` panic on future rustls variants (P16), `#[serde(untagged)]` ambiguity on JSON-RPC response (P17), endpoint validation accepts malformed `"tls://"` (P18), no mixed same-host + cross-host test (P19), JSON-RPC error code -32600 vs spec -32601 (P20), `CrossHostNotConfigured` only reports first unconfigured host (P21), `A2AConsentEnvelope` dead code (P22).

**What the 2 Critical-OPEN findings mean substantively**:
- **P1**: `Arc<dyn TofuPinStore>` is stored as a field but the routing path never calls `verify_pinned`. **NFR-Sec-12 (TOFU pin-mismatch 100% detect/block/alert) is structurally false at HEAD.** The substrate's "TOFU pinning prevents MITM on second connection" architectural commitment is unverifiable in the production data path; tests pass because they call `verify_pinned` directly via test helpers.
- **P2**: `frame.consent_envelope` is read at intake (`let _ = envelope; // present-but-unused at v0.5 base shape`). `A2AError::ConsentExpired` and `CODE_CONSENT_EXPIRED (-32003)` exist but are unreachable from the intake path. **An attacker submitting a frame with a consent envelope expired hours ago gets the same admission decision as a fresh envelope.** ADR-012's "every frame carries typed-intent consent" reduces to "every frame carries a consent envelope that is never validated".

**Why it matters now:** Story 7.1 (cargo generate + SDK) does NOT depend on the A2A surface. **Story 7.2 (registry over MCP-Streamable-HTTP with `org-internal` tier)** depends on cross-host trust posture. **Story 7.4 (skill-revision proposals from Spirit telemetry within principal namespace)** depends on consent-envelope verification for any cross-Spirit proposal routing. **Story 6.3 as-is cannot safely back Epic 7's cross-host work.** Furthermore, Story 6.3's 22-finding density (when review WAS run) is comparable to Story 5.5d's 27 OPEN findings — the discipline that worked for Stories 6.1 / 6.2 / 6.4 / 6.5 (apply patches inline) was NOT applied for 6.3. **The cause is structural: Story 6.3 spans a massive surface (~2,286 LOC `maos-a2a` crate + cross-host kernel-core wiring), and the dev model — claude-opus-4-7 — produced the expected review-patch density but the patches were deferred rather than applied inline.** Story 6.4 demonstrates that even at 35-patch density, inline application is achievable.

**Action item §A1 closes this:** reopen Story 6.3 as `in-review` (NOT `done`); resolve the 2 Critical + 5 High OPEN patches in-PR before Story 7.2 opens. The 15 Medium/Low can carry forward as documented v0.5-α calibration debt (with explicit closure-target stories for each).

## Closing Note

Epic 6 delivers five stories of full IAC bus + retract + DRR + Orchestrator distillates + CliWrapperSpirit + A2A peer mesh + scheduled invocations + ConsentRupture + provider rate-limit isolation + gateway sub-modules in roughly four wall-clock days. **The substrate-extension pattern compounded — Story 6.1's `retract` consumed by 6.2's `IacBusAdapter::retract` lineage path; Story 6.2's `intent_lineage` corpus extended by 6.3 (A2A scenarios) and 6.4 (consent-rupture + rate-limited + on-schedule scenarios); Story 6.4's per-(provider, credential) `TokenBucket` consumed by Story 6.5's gateway dispatcher principal namespacing.** The substrate works on every story.

**Epic 6 is the first epic in MAOS history where review discipline structurally restored without backfilling Epic 5.** Story 6.4 (35 patches applied inline) is the new exemplar. Story 6.1, 6.2, 6.4, 6.5 all received formal `bmad-code-review`; only Story 6.3 shipped substantive open-review-debt (22 OPEN patches including 2 Critical security gaps). The 4/5 review rate (vs Epic 5's 2/9) represents a material improvement at the new-story-creation layer — **the practice that Epic 5 retro §A2 intended to restore took hold, but at the forward-looking layer rather than the backfill layer.** Behavioral change beat catch-up debt.

**But Epic 6 also exposed two structural patterns that need closure**:

1. **Story 6.3 demonstrates that "ship + defer" patterns can produce Story-5.5d-class outcomes even with formal review applied.** The review pass surfaced 22 patches; only 2 were rated `dismissed` and 6 were `defer` (calibration phase scaffolding). The 22 `patch` rows were OPEN at commit — the dev applied the review's `decision-needed` (3 rows) and `defer` (3 rows) inline but left the patch rows open. The structural cause is surface-area: Story 6.3's `maos-a2a` crate ships ~2,286 LOC including mTLS, JSON-RPC, TOFU, consent, rotation chaos, churn — the densest single-story surface in Epic 6 by 2× margin. Story 6.4, by contrast, shipped ~450 LOC of new production code (ScheduleWatchdog + Phase 1.5 consent gate + payload module) and applied 35 patches inline. **The hypothesis: review-patch-inline-rate is inversely correlated with story surface area; above ~1000 LOC of new production code, the per-patch cost compounds beyond the inline budget.** §A1 closes the 2 Critical + 5 High; §A6 documents the v0.7 / v1.0 closure plan for the 15 Medium/Low.

2. **The §A2 / §A5 / §A6 promise-decay pattern is in its 5th consecutive story.** The xtask binaries shipped; the discipline.yml wiring did not. The Epic 5 §A2 backfill did not happen. **The carry-forward state is unstable; eventually the verify-only `[FAIL]` rows will become blocking and the unwind will be expensive.** §A2 closes both halves in a single bridge window (wire + backfill).

The pattern across three consecutive retros — Epic 4 → Epic 5 → Epic 6 — is now empirically validated:

- **Gates shipped+wired in-epic compound.** Epic 4 §A1/§A4/§A5, Epic 5 §A3 → 4/4 closed.
- **Gates with binary but no wiring decay.** Epic 5 §A5/§A6 → 0/2 closed in 5 stories.
- **Gates depending on author backfill decay completely.** Epic 5 §A2 → 1/5 closed (Story 5.4 only).
- **Reviews applied inline produce clean substrate; reviews with deferred patches produce open debt at next-story boundary.** Stories 6.1 / 6.2 / 6.4 / 6.5 = inline-applied → clean; Story 5.5d / Story 6.3 = deferred-applied → open at boundary.

`[[feedback_lunarpulse_observability_preference]]` ("when can I observe actual behavior beats coverage%") was honored at every layer in Epic 6: 14+ smoke arms, mechanical bridge gate compound across 5 stories, runnable demos with deliberate sad paths. The substrate's observability discipline is at its strongest point in MAOS history.
