## Patch findings

### P1 — Preserve Gemini's stop reason when blocked candidates have no content

- **Severity:** medium. **Sources:** blind + edge. **Constraint:** AC1.1's `ProviderStop(<value>)` mapping, including SAFETY.
- **Evidence:** `crates/maos-providers/src/gemini.rs:116-133`: a candidate exists, but the mandatory `content.parts` lookup at 121–125 returns `Serde` before `finishReason` is examined at 129. Thus `{"candidates":[{"finishReason":"SAFETY"}]}` cannot produce the specified `ProviderStop("SAFETY")`. The response parser is reached from the real 2xx transport path at 94–96.
- **Missed witness:** `crates/maos-providers/tests/gemini_round_trip_test.rs:14-39` uses a safety fixture containing ordinary text and asserts `Hello Gemini` for every case. It tests enum substitution, not absent blocked content. Contrary to the blind report's wording, the current safety fixture does **not** omit content.
- **Exact fix:** determine the candidate's finish reason independently of content extraction. For an explicit provider-stop reason such as SAFETY/RECITATION and absent generated content/parts, return an empty text response with that `ProviderStop`, preserving usage and attribution. Keep existing STOP/MAX_TOKENS and multipart-text behavior; do not silently accept unrelated malformed successful responses by globally defaulting every missing content field.
- **Failing-before witness requirement:** recording-transport test returning HTTP 200 with a candidate containing `finishReason: "SAFETY"` and no content; assert successful response, empty text, exact `ProviderStop("SAFETY")`, usage and Gemini attribution. It must fail against the current parser with `missing candidates[0].content.parts`, then pass after the fix. Retain a malformed normal-success response rejection control.
- **Wire context:** Google's [GenerateContent response/Candidate schema](https://ai.google.dev/api/generate-content) describes candidate-level filtering via finishReason and safetyRatings. The missing-content failure above is established directly from code; no paid vendor exchange was performed.

### P2 — Do not fabricate a clean Gemini stop when finishReason is absent

- **Severity:** medium. **Sources:** blind + edge.
- **Evidence:** `crates/maos-providers/src/gemini.rs:129-133` maps `Some("STOP") | None` to `StopSequence`. A candidate with valid text but no finish reason is therefore indistinguishable from a completed reply. Google's [Candidate schema](https://ai.google.dev/api/generate-content#Resource:Candidate) explicitly says an empty finishReason means the model has not stopped generating tokens. This driver is the non-streaming completed-response surface, not a streaming partial accumulator.
- **Exact fix:** reserve `StopSequence` for explicit STOP. Treat missing or empty finishReason as a descriptive `ProviderError::Serde` (no secret data), preserving the explicitly named mappings for all nonempty reasons. Do not invent a provider stop value such as `missing`.
- **Failing-before witness requirement:** pass HTTP 200 candidate content with no finishReason through `GeminiProvider::complete`; assert a decode/Serde error rather than a successful StopSequence response. Add the empty-string counterpart and preserve explicit STOP/MAX_TOKENS/SAFETY controls. The absent-reason assertion fails against current code because it returns success.

### P3 — Make new-key registration tests observe real registration rather than replay substitution

- **Severity:** medium. **Source:** test infrastructure. **Constraint:** AC3.2 and the L1 evidence claim of registration/order coverage.
- **Evidence:** `crates/maos-bin/tests/provider_selection_20_4.rs:120-143` is named `new_keys_register_and_preserve_default_order_in_replay` but only checks an `infer:{id}->` result. Its helper forces explicit replay (`tests/support/provider204.rs:9-23`), and `main.rs:4115-4119` installs every provider id independently of real keyed registration. Removing `providers_map.insert("gemini", ...)` at `main.rs:4007` while leaving the following default selection intact is masked by replay re-inserting Gemini. Kimi has the same structure at 4027–4029. The current production insertions are present; this is a false proof surface, not a claim that current registration is broken.
- **Exact fix:** add isolated **non-replay**, no-inference boot checks that exercise the real map/selector. With Ollama skipped and only a valid Gemini key, selecting Gemini must boot successfully; selecting an absent keyed provider must fail. Repeat for Kimi. Keep replay tests for routing. Add default-order conflicts with pre-existing Anthropic/OpenAI keys and verify the chosen provider, so the test's order claim is real. This can use a boot-only/EOF command path and must not make paid requests; do not assert only the registration log line.
- **Failing-before witness requirement:** plant omission of the real Gemini map insertion only, retaining default selection. The new non-replay registration test must fail while the old replay registration test would remain green. Repeat or equivalently cover Kimi's insertion; verify missing-key refusal and the existing-provider precedence controls. Record actual red/green evidence, not the structural argument as a runtime failure.
