# Blind adversarial review: commit 2752e750 (parent 8c809f9c)

Scope: `crates xtask spirits docs docs-site tests`. Diff-only, read-only. No builds or tests were run. Line numbers marked `diff:N` refer to the `git show` patch; the rest refer to the file as changed.

- Provider credential validation returns the wrong error class for format failures. `crates/maos-providers/src/provider.rs:49-60` (`validate_api_key`) returns `ProviderError::Transport` for invalid credential bytes, so an operator sees `transport: <KEY>: invalid credential bytes`. Severity medium-low. Trigger: any header-unsafe or whitespace-containing key. Fix: return `ProviderError::Unconfigured` (or a dedicated variant) for format failures. Failing-before witness: the function body as read at `provider.rs:49-60` always yields `Transport` on the `else` branch.

- Whitespace-only API keys change boot behavior from `Unconfigured` to a hard failure. `anthropic.rs` (diff:1613) and `openai.rs` (diff:1921) replace `.filter(|key| !key.trim().is_empty())` with `.filter(|key| !key.is_empty())`. A whitespace-only key now reaches `validate_api_key`, which returns `Transport`, and `main.rs` exits 78 on any non-`Unconfigured` error. Severity medium. Fix: restore `key.trim().is_empty()` in both filters. Failing-before witness: before the patch, a whitespace-only `MAOS_ANTHROPIC_API_KEY` was filtered to `Unconfigured` and the daemon degraded; after the patch the same input exits 78.

- Gemini and Kimi registration exit the whole daemon on a malformed key. `crates/maos-bin/src/main.rs` ~4000 (diff:317, diff:337) call `std::process::exit(78)` for any non-`Unconfigured` construction error. A malformed `MAOS_GEMINI_API_KEY` or `MAOS_KIMI_API_KEY` kills the daemon instead of leaving that provider unregistered. Severity medium. Fix: treat non-`Unconfigured` errors for these two providers the same way as the existing provider branch, or log and skip. Failing-before witness: there was no Gemini or Kimi branch before the patch, so a malformed key could not reach this exit.

- Gemini `parse_response` reports a serialization error for SAFETY-blocked candidates. `crates/maos-providers/src/gemini.rs` `parse_response` (diff:1780-1801) returns `Serde("missing candidates[0].content.parts")` before it reads `finishReason`. A candidate with `finishReason: "SAFETY"` and no `content` (fixture `gemini_safety_response.json`) therefore reports a serialization failure, not `ProviderStop("SAFETY")`. Severity medium. Fix: read `finishReason` first and return `ProviderStop` when it is present and non-`STOP`. Failing-before witness: the safety fixture fails the `content` lookup at the early `return` before any `finishReason` check.

- Missing Gemini `finishReason` is reported as a normal stop. `gemini.rs` `parse_response` (~line 1799) maps `Some("STOP") | None => StopReason::StopSequence`. An absent finish reason is indistinguishable from a clean stop. Severity low-medium. Fix: map `None` to an explicit error or a distinct variant. Failing-before witness: a candidate with `content` and no `finishReason` yields `StopSequence` with no error.

- Gemini multi-part responses silently drop non-text parts. `gemini.rs` `parse_response` (~line 1796) uses `filter_map(|part| part.get("text")…)`, which discards `inlineData` and other parts with no error and no test. The fixture `gemini_multi_part_response.json` contains an `inlineData` part. Severity low-medium. Fix: count or refuse non-text parts, and add a test asserting the chosen behavior. Failing-before witness: the fixture's `inlineData` part is absent from `response.text` with no diagnostic.

- Gemini usage counts are truncated and zeroed silently. `gemini.rs` `count` closure does `as_u64().unwrap_or(0) as u32`, so a missing or oversized `usageMetadata` field becomes 0 or wraps. Severity low. Fix: use `u32::try_from(...)` and surface a `Serde` error on overflow or absence. Failing-before witness: a `promptTokenCount` of `4294967296` wraps to `0` with no error.

- `declared_providers` narrows to the primary provider only. `crates/maos-bin/src/main.rs` ~896-899 returns `vec![providers.primary.id]` whenever `gated.providers` is set, ignoring every other declared `ProviderInfer` scope. Callers include researcher wiring (~1077, ~1133), the orchestrator (~5816, ~6651, ~6706), and `first_declared_provider` (~1188, ~6412). Severity medium-low. Fix: return the full declared set, or document and test why the narrowing is intended. Failing-before witness: a manifest declaring two providers yields a one-element list, so the second provider is never wired.

- `check_provider_pins` passes id-only pins. `crates/maos-bin/src/admission.rs` `check_provider_pins` skips the model check when `model_id` is `None`, and passes when both `provider_endpoint_pin` and `endpoint_url` are `None`. A `[providers.primary]` with only `id` is admitted with no assertion beyond registration. Severity low-medium. Fix: refuse id-only pins at admission, or document the permissive case with a test. Failing-before witness: an id-only pin for a registered provider returns `Ok` from `check_provider_pins`.

- Endpoint and model literals are duplicated with no assertion linking them. `configured_providers` in `main.rs` (diff:268-281) and the constructor literals (~4000, and `"kimi-k3.1-pro"` at diff:325) carry the same values. No test in the diff asserts they match, so the catalog pin and the constructed model can drift. Severity medium. Fix: derive the constructor arguments from the catalog entry, or add an assertion test. Failing-before witness: editing one literal leaves the other unchanged and every test still passes.

- `MAOS_DEFAULT_PROVIDER` validation exits with the wrong code. The env check (`main.rs` diff:363-371) runs after `providers_map` is built and returns `Box<dyn Error>` (exit 1), not 78. `docs/maos.dev/run-maos.md` says the boot is refused, without naming the code. Severity low. Fix: move the check before map construction and exit 78 to match the other configuration refusals. Failing-before witness: an unknown `MAOS_DEFAULT_PROVIDER` returns exit 1 through the `Box<dyn Error>` path.

- Ceiling values in `xtask/kloc.toml` disagree with their own history notes. The `maos-providers` line changes from `2000` to `1608` (diff:2750-2751), and its note says `ceiling1898`. The `xtask` line is `44420` while its note says `ceiling44466`. A reader cannot tell which number is enforced. Severity low-medium (process). Fix: make each note's stated ceiling equal the value written, or reword the note as measured-only. Failing-before witness: before the patch the `maos-providers` value and its notes were consistent at `2000`.

- The uninstall test no longer checks the credential count against an independent value. `crates/maos-bin/tests/maos_uninstall_16_4.rs` (diff:994-998) replaces the literal `10` with `SecretKey::ALL.len()`. `known_secret_keys()` is built from `SecretKey::ALL.map(...)` (purge.rs diff:915-917), so the two sides are equal by construction and the assertion is tautological. Severity low. Fix: restore a literal count, or assert the set of keys matches an explicit list. Failing-before witness: before the patch, dropping a key from `ALL` made the literal `10` fail; after the patch the same drop passes.

- `ProviderUnavailable` covers three distinct causes with one message. `admission.rs` Display (`"provider_unavailable: '{provider}' is undeclared, unregistered, or its model assertion differs"`) is shared by the undeclared branch in `gate_manifest`, the unregistered branch, and the model-mismatch branch of `check_provider_pins`. Operators cannot tell which applies. Severity low. Fix: split into three variants or three messages. Failing-before witness: the same string is produced for an undeclared id and for a model mismatch.

- `FallbackUnsupported` is shadowed by `ProviderUnavailable`. `gate_manifest` checks declared providers in the loop before it checks fallback, so a fallback with an undeclared id returns `ProviderUnavailable`, not `fallback_unsupported`, which contradicts the docs. Severity low-medium. Fix: check the fallback condition before the declared-provider loop, or update the docs. Failing-before witness: a fallback naming an undeclared provider returns `provider_unavailable`.

- `hello-spirit` now requires two more providers at token issuance. `spirits/hello-spirit/manifest.toml` (diff:2701-2716) changes `provider.complete` to add `gemini.gemini-3.5-flash-lite` and `kimi.kimi-k3.1-pro`. Failing-before witness: before the patch, an OpenAI-only host issued the token (per the removed comment); after the patch, the same host is refused at issuance.
