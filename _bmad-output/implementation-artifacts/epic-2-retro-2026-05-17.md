## What Went Well

1. **4/4 stories shipped in one wall-clock day with the bridge work landing the day before.** The 1b.6 bridge (D9 SandboxTier reconciliation + D10 architecture doc catch-up + Doc3 unsafe-code ADR) cleared the runway, and 2.1 → 2.4 chained without inter-story blockers. First time since Epic 0 that an epic closed without a same-week bridge commit.

2. **The 1b.6 D9 adapter pattern was applied cleanly to a second boundary in 2.1.** `CancellationSignal` is a `no_std` trait in `maos-spirit-abi` with a `TokioCancellationSignal` adapter in the SDK — the same shape as `SandboxTier`'s ABI enum + domain newtype split. The pattern is now legitimately "the way" rather than a one-off, and Epic 5's subprocess wire-protocol work can build on it without reimplementation.

3. **Architecture doc updates landed in the same PR as the workspace change** (2.1 §4.0.2 layout + member count, §5.3 lifecycle-hook firing-implemented-at column). This directly applies the Epic 1b retro lesson that produced D10 — the workspace doc rotted across 1b.1 + 1b.3 because nobody updated it in-PR. 2.1 broke the pattern. 2.3's architecture addendum (§4.0.2 member count corrected from 22 → 21 during review) shows the discipline still has rough edges, but the loop tightened.

4. **The `xtask check-service-boundary` stub from Story 1a.3 was closed with the v0.1-β interpretation** (P1–P4 checks run against `maos-kernel-core/src/<module>/` layout, not v0.5+ `crates/services/<name>/`). The architecture-doc addendum at §4.0.8 documents the re-interpretation and the promotion path. P3 cross-references `check-empty-kernel` output rather than duplicating ~200 LOC — eliminates divergence risk.

5. **The "production code surfaces during xtask work" tension in 2.2 was handled correctly.** Two real violations surfaced (`SecurityManagerAdapter` constructed twice; `CryptoProvider` not re-exported via `api::*`) and were **intentionally deferred** to a bridge slot rather than silently fixed inside the xtask story. 2.3 AC1 picked them up and closed them, matching the 1a.5 + 1b.6 discipline.

6. **Forward-anchor contracts from 2.4 ship without breaching E4/E5 ownership.** `HaltResolutionKind` (3 variants), `IsolationHookPoint` + `IsolationAttackCategory` (8 variants), and `MockBusFrame` are shipped as test-SDK types — none promoted to ABI. Story 4.1's halt-protocol mechanism consumes `HaltResolutionKind` verbatim; Story 4.5's 200-scenario isolation corpus plugs into `IsolationHookPoint`. The memory rule "halt owned by E4" is upheld: Epic 2 ships test-side shapes only.

7. **Forbid-unsafe discipline survived three new crates.** `maos-spirit-derive` (proc-macro), the template scaffold, and `example-spirit` all carry `#![forbid(unsafe_code)]` at crate root. ADR-039 from 1b.6 codified the per-module relaxation for sandbox syscalls; nothing in Epic 2 needed to invoke it.

8. **The end-to-end acceptance demo from the epic spec is now provable.** Clone template (2.3) → author `on_idle` (2.1 `#[spirit]`) → `cargo test --features spirit_test` invokes harness (2.4) → `assert_hook_fired!` passes. Author never reads kernel internals. This is the NFR-Onb-1 v0.3 prerequisite path; execution of the 30-min gate itself lands at Story 7.5b against the Butler reference Spirit (Story 8.1).

## What Was Challenging

### 1. Story 2.4 review surfaced five capture-surface bugs — all fixed inline

Code-review on 2.4 raised five Patch-tier findings against the spirit-test SDK harness. Post-merge verification against on-disk code confirms **every patch was applied during the same dev cycle**:

| Finding | Resolution location |
|---|---|
| `captured_frames` not wired in `SpiritTest::run()` | Wired at `crates/maos-spirit-sdk/src/spirit_test/harness.rs:59` (`self.report.captured_frames = base.mock_bus_frames.clone()`) |
| `frames_emitted` hardcoded to `0` in isolation reports | Real data at `isolation.rs:166, 177` (`report_a.mock_bus_frames.len() as u32`, `report_b.mock_bus_frames.len() as u32`) |
| SHA-256 verification using substring match | Exact-byte comparison at `tests/lcas_smoke.rs:60-63` (split on `=`, trim quotes, `assert_eq!`) |
| UTF-8 BOM produces confusing TOML parse error | Explicit BOM strip at `manifest.rs:65` (`.strip_prefix("\u{feff}")`) |
| Empty strings in `required_fields` + `class.forms` accepted silently | Warning path at `manifest.rs:73-78` for `class.forms`; hard error at `:81-87` for `output_shape.required_fields` |

The retro's initial draft assumed these patches were carried over as bridge work because the dev-record retrospective section enumerated them as raw review output. That was a misread — the dev cycle closed them inline before commit. **A1 is therefore demoted from "open bridge work" to "verified closed pre-bridge"**, and bridge 2.5 retains only A4/A5/A6/A7/A8 (process + IAC bus spec + D11 + xtask guard).

This is itself a lesson: review-patch enumeration in dev-record retrospectives needs an explicit `Status:` field (closed / open / deferred). Becomes **A6**.

### 2. LCAS corpus authored by Python script, not by hand

Story 2.4 AC2 specified hand-authored corpus items so that each scenario reflected explicit human judgment about halt-tag boundaries. The 70-item v0.3 corpus is structurally correct (37 halt + 33 continue, ≥6 halt-tag categories, valid JSONL schema) but was generated mechanically. The structural validator passes; the discipline letter does not. This matters for Story 4.5's 200-scenario cross-Spirit isolation corpus — if we accept script-generation now, we set a precedent that erodes the calibration foundation the adversarial reviewer is supposed to provide. Becomes **A2**.

### 3. Story 2.3 review found four critical patches — all fixed inline

Same correction pattern as §1. Initial retro draft assumed these were open bridge work; post-merge verification:

| Finding | Resolution |
|---|---|
| Missing `xtask/tests/example_spirit_regen_integration.rs` | File present on disk (3275 bytes; 103 lines per commit `baecfea`) |
| Dead `SecurityManagerAdapter` import at `main.rs:41` | `main.rs:41` imports `MemoryManagerAdapter, RingCryptoProvider,`; `SecurityManagerAdapter` used at `:316` via fully-qualified path (`maos_kernel_core::security::SecurityManagerAdapter::new`) — no dead import |
| Fragile `str::replace` for git→path substitution | Replaced with line-by-line key matching at `xtask/src/example_spirit_regen.rs:141-164`; comment explicitly says *"Uses line-by-line key matching so the replacement survives whitespace or field-order changes."* |
| `local_runner` smoke tests not in CI | Runs at `.github/workflows/discipline.yml:452-453` (`cargo test -p maos-spirit-sdk --features local_runner --locked`) |

Same root cause as §1: dev-record retrospective sections enumerate review findings as raw output rather than tracking their close/defer state. **Fixed by A6** (dev-record discipline addition).

### 4. Variance in adversarial-review depth across stories

2.1 had 12 patches + 5 deferrals applied in-PR with regressions caught (abi-baseline version, `trust_tier` default, empty-provider guard). 2.2 had 9 decisions resolved cleanly with intentional deferrals documented as spec gaps. 2.3 and 2.4 surfaced patches that were not applied. The pattern correlates with model identity: 2.4 ran on `deepseek-v4-pro` for the dev pass, and the review found shape but not correctness. Recommendation in §A4.

### 5. E3.2 `[epistemic_policy]` manifest section was not explicitly frozen in 2.1's ACs

Story 2.1 froze the manifest schema for capabilities, `output_shape`, and lifecycle-hook declarations, but the `[epistemic_policy]` table that Story 3.2's halt-policy schema (per-Spirit per-tag recall vs precision trade-off) needs is not enumerated in 2.1's AC list. The shape is implied by the architecture doc but not pinned by a structural validator or fixture. Becomes **A3** (verification spike before 3.2 opens).

### 6. IAC bus routing model underdocumented for 3.1

Story 3.1 cites "codex's `Mailbox` pattern" for the bounded-queue routing model but the architecture doc does not link the reference implementation or specify the adapter contract (capacity, fairness, backpressure semantics). 3.1 needs a research spike before AC authoring. Becomes **A5**.
