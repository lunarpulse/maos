# Security review — commit `cdf3937d` (20-9 L1: WIT 2.4.0 lifecycle hooks, session pump, `[[schedule]]`, telemetry explicit listing, state-preserving hot swap + cold-swap restore)

**Scope reviewed (read-only; working tree at `cdf3937d`, verified via `.git/logs/HEAD` + `COMMIT_EDITMSG`).** Commit message confirms the surface: "kernel-free: WIT spirit@2.4.0 lifecycle hooks, host bridge + session pump, [[schedule]], telemetry explicit listing, state-preserving hot swap + cold-swap restore".

## Findings

### F1 — MEDIUM (availability/DoS) — One slow telemetry subscriber stalls the root's entire telemetry pipeline for up to its full hook budget; quarantine never triggers
- **Where:** `crates/maos-bin/src/hook_pump.rs:423-490` (`Shared::deliver`), `:1024-1073` (`delivery_loop`), `:936-961` (`register`); budget source `crates/maos-kernel-core/src/scheduler/hook_dispatch.rs:374-381` (`effective_cap_seconds`, manifest `[budget].time_cap_seconds`, validated only to ≤ 86 400 s at `crates/maos-manifest/src/manifest.rs:1184-1189`).
- **Exploit/impact:** The pump is exactly one delivery task; `deliver` awaits each subscriber's `fire_on_telemetry_event` **sequentially and to completion** (`hook_pump.rs:464`). For a spawned subscriber the hook blocks on the session drain bounded only by the subscriber's own link cap (`supervision.rs:2735-2751` → `spawned_lifecycle.rs:166-246`, cap = its `turn_budget`). A guest that sleeps `time_cap − ε` inside `on_telemetry_event` on every event is **never quarantined** (`BudgetExceeded` is the only budget strike, `hook_pump.rs:415-428`) yet blocks every other subscriber and all later events for (budget × events). With `time_cap_seconds = 86400` one admitted component listing `on_telemetry_event` can pin the pump for ~24 h per event; events then lag and are dropped (`lagged`, `:547-553`) and `HookPump::flush` (`:981-991`) stalls equally. New in this commit: the registered/subscriber set widened from first-party Observer classes to **any admitted wasm component** (`admission.rs:1343-1348` registers every spawned form; eligibility `hook_pump.rs:245-258`). Secondary effect: because the pump and the ConsolidationWatchdog are separate tasks firing hooks on the same spirit through a `sync_channel(1)` link (`spawned_lifecycle.rs:125`, `call` at `:204-231`), a forced overlap makes the losing hook miss its deadline and panic (`supervision.rs:2716-2721` `Err(code) => panic!`), accruing quarantine strikes — a flooding emitter can push a slow competitor subscriber toward quarantine/revocation of its telemetry grant.
- **Fix sketch:** per-subscriber dispatch queues with a per-hook wall budget strictly smaller than the fire cap (e.g. min(turn_budget, pump_deadline)) enforced around the whole event, and/or strike on repeated `BudgetWarning80`; charge strikes only to the hook that missed, not to a concurrent loser (answer the second caller `Deadline` without panic by testing the link's own deadline before panicking in `WorkerSpirit::lifecycle`).

### F2 — LOW (hardening / sandbox read-grant confusion) — Artifact resolution is `origin.join(artifact).canonicalize()` with no containment check (traversal and absolute paths accepted)
- **Where:** `crates/maos-bin/src/spirit_session.rs:110-116` (`manifest_launch_in` — used by every spawned launch, hot-swap pre-warm at `spawned_lifecycle.rs:528-534`, and cold-swap admit at `spawned_lifecycle.rs:421-424`); `crates/maos-bin/src/main.rs:10459-10468` (`prepare_spawned_restore` — canonicalize only, "must still be where the Spirit was launched from" is checked by existence, not location).
- **Exploit/impact:** A manifest `artifact = "../../home/victim/x.wasm"` (or an absolute path — `Path::join` yields it verbatim) resolves and executes outside the operator-named directory; `spawn_runner` additionally pushes `Scope::FsRead { subtree: artifact }` into the child's scopes (`spirit_session.rs:285-289`), granting the runner a read scope on the escaped path. Blast radius is bounded by the T2 sandbox and by who authors the manifest (operator file, or a signature-verified registry package via `installed_upgrade_target`/`verify_installed` — `installed_spirits.rs:34-52`, `operator_door.rs:1320-1326`), so this is author-trust leakage rather than a guest-exploitable traversal — but the codebase's sibling surfaces (FR11 archive `is_path_component`, `admission.rs:1538-1543`; uninstall custody roots) do enforce containment and this one silently does not. Note the swap path also runs the resolved artifact under the **predecessor's** sandbox (`spawned_lifecycle.rs:537-542`, `context.sandbox.clone()`), so the code-to-authority binding rests entirely on the artifact path being the operator-intended file.
- **Fix sketch:** after canonicalize, require `starts_with(origin.canonicalize()?)` (or an explicitly allow-listed package root) for relative artifacts, and refuse absolute artifacts unless they resolve inside the recorded install/origin root; log the resolved path in the declaration event.

### F3 — LOW (information disclosure; ruled design, residual risk stated) — A component that lists `on_telemetry_event` receives every other Spirit's scalar stream — no tenant scoping, no per-event redaction; erasure notices fan out to every registered component
- **Where:** eligibility `hook_pump.rs:245-258` (`receives_telemetry`); payload `hook_pump.rs:428-433` (`serde_json::to_vec(&ScalarTapEvent)` — `seq, spirit_id, tag, value: f64, timestamp_ms`, `maos-domain/src/invariants/i7.rs:44-58`); registration+grant row `hook_pump.rs:936-961`; forget-notice fan-out `hook_pump.rs` `complete_forget` (~`:663-860`, fires `on_consolidate` with `ForgetNotice { scrubbed_frame_ids, .. }` to **all** registered pids, spawned ones included since this commit registers them).
- **Exploit/impact:** Any operator-admitted wasm component self-subscribes (one string in its own manifest) to the root-wide `scalar.tap` firehose of all Spirits — emitter identity, tag and value, with no topic/tenant filter and no value redaction (D-20-9-07 A explicitly chose the root stream over self-events-only, with `governance:telemetry-subscription:*` rows as the audit trail). Unlike the compiled-in Observer (right conferred by the operator admitting that class), here the *manifest author* confers the right and the operator consents only implicitly by admitting the manifest. The 20-9 registration widening also means redacted erasure metadata (scrubbed frame-id lists) now reaches every guest component via `on_consolidate`.
- **Fix sketch:** at minimum surface `enabled_hooks: ["on_telemetry_event"]` loudly at admission (its own declaration/TL field or refusal without an explicit `scalar.tap.*` capability), and scope forget-notice fan-out to writers that actually hold affected frames.

### F4 — LOW (availability, accepted-gap confirmation) — Post-swap revert after retire leaves the Spirit absent; a second swap inside the adoption window fails via a hook panic
- **Where:** `crates/maos-bin/src/spirit_session.rs:333-334` (`REVERT_WATCH` 35 s), `:511-517` (`swap_reverted_after_retire` → `SessionError::SwapReverted`), `:475-509` (handover: predecessor child retired *before* the 30 s monitor window closes; kernel revert source `crates/maos-kernel-core/src/hot_swap/coordinator.rs:402-405` `pending_reverts`); second-swap window: `spawned_lifecycle.rs:497-506` (`wait_supported`) vs session adoption at `spirit_session.rs:475`.
- **Exploit/impact:** If the PostSwapMonitor reverts within its window after the session already retired the predecessor child (kill path `spirit_session.rs:305-325`), the Spirit is absent while the SCB momentarily held a restored predecessor runtime whose child is dead — typed, journaled (`spirit.swap.reverted_after_retire`), and the operator remedy is the cold-swap restore / reload. This is the acknowledged D-19-5-02 A residual, now realized for spawned forms; not attacker-amplifiable beyond forcing swap timing (operator-initiated). Related: a second door upgrade arriving before the session adopts the handover dispatches `snapshot` to the successor object whose link has no session yet → `Unsupported` → `WorkerSpirit::snapshot` panics `spawned_swap_unsupported` (`supervision.rs:2777-2781`) → swap refused (fail-closed, noisy).
- **Fix sketch:** gate a second upgrade on "handover adopted" (e.g. `spawned_target` skipping cores whose link still holds a pending handover), and have the monitor consult the session's adoption state before reverting.

### F5 — LOW (process/bookkeeping) — `MAOS_ARCHIVE_DIR` is not in the env contract and outside its scan; hot-swapped spawned successors skip the FR11 archive record entirely
- **Where:** read site `crates/maos-audit/src/lib.rs:1610-1624` (`default_archive_dir`); env contract `crates/maos-bin/src/env_contract.rs` (no `MAOS_ARCHIVE_DIR` entry; `MAOS_IDLE_FAST` etc. are registered); scan scope `xtask/src/check_env_contract.rs:109-115` (maos-bin `src` only, so the maos-audit read is invisible to the gate); admission gate/write `crates/maos-bin/src/admission.rs:1177-1182` (`refuse_without_migrator`) and `:1290` (`archive_admitted`) — reached by `load_admit_start` but **not** by the hot-swap factory `spawned_lifecycle.rs:495-497` (only `gate_manifest` + declaration event/outcome `:549-560`).
- **Exploit/impact:** Not new to this commit (env var landed with 19-5), but this landing leaned on it for test isolation and the evidence file records real test pollution of the user archive (`_bmad-output/.../20-9...evidence/landing-1/evidence.md:23`). Residual bookkeeping gap: after a hot swap the FR11 archive still names the predecessor version only; a later *fresh* load of the successor across majors can be refused `migrator_missing` against a stale record (fail-closed, availability only). No guest-controlled input reaches the path (`version` is `is_path_component`-validated, `admission.rs:1538-1543`).
- **Fix sketch:** register `MAOS_ARCHIVE_DIR` in `env_contract.rs` and widen the check to maos-audit reads (or centralize the read behind a maos-bin wrapper); write the FR11 record (or a swap marker) from the committed hot-swap outcome closure.

### F6 — INFO (declared-vs-enforced narrowing) — The successor's declared scopes are an exact-match subset check, but runtime authority is the predecessor's sandbox wholesale
- **Where:** check `crates/maos-bin/src/spawned_lifecycle.rs:508-517` (`context.declared().contains(scope)` — `Scope` structural equality); runtime `:537-542` (`spawn_runner(context.sandbox.clone(), …)`), session keeps predecessor-derived `declared_sends` (`spirit_session.rs:377-381`), tokens/pid/memory carried per D-20-9-10 A (`spirit_session.rs:304-325`, no `revoke_all_for_pid` at retire).
- **Impact:** Two consequences, both design-accepted but worth recording: (a) a successor *narrowing* a scope (e.g. deeper `FsRead` subtree, fewer `iac.send` peers) is **refused** as `swap_capability_widened` (exact-match false positive), and (b) a successor that declares fewer scopes still executes with the predecessor's full admitted sandbox and live pid-scoped tokens until they expire naturally — the manifest subset check constrains text, not the running code's authority. Combined with F2 (artifact not bound to the manifest beyond path resolution), the effective control on "what code gets the predecessor's authority" is the vetted/artifact path, not the declared caps.
- **Fix sketch:** make the subset check hierarchical per `Scope` kind (containment, not equality), and re-derive the session's `declared_sends` from the successor manifest at handover.

## Rejected candidates (investigated, not exploitable as framed)

1. **Hot-swap artifact resolving against the staged temp dir (`/tmp`).** The door pre-stages origin-less at `operator_door.rs:1434`, but `migration_plan::upgrade_hop` **always** calls `before_hop` before `orchestrator.upgrade` (`migration_plan.rs:74-81, 196-204`), which re-stages `stage_at(path, original_target.parent())` (`main.rs:10246-10264`) — the operator's target dir for the final hop, the hop file's dir for intermediate hops. Cold swap passes `target_path.parent()` explicitly (`operator_door.rs:1419`); restore uses the recorded `SwapContext.origin` (`main.rs:10470-10477`). The origin plumbing is correct; the initial `stage()` at `:1434` is merely dead-before-use.
2. **Zombie successor registration shadowing `spawned_target` after a refused swap.** `prepare_spawned` does not register the core (`supervision.rs:1760-1792`); registration happens only at session adoption `adopt_spawned` (`:1800-1812`), i.e. on commit. On refusal the core/link drop → child killed, predecessor unfenced (`spawned_lifecycle.rs:327-336`), declaration journaled `refused`.
3. **Budget/`Instant` overflow from a guest-authored manifest.** `time_cap_seconds` is `u32` and validated `1..=86400` (`maos-manifest/src/manifest.rs:1178-1189`); no `Instant + Duration` panic path.
4. **Guest forging lifecycle replies over stdout.** A guest writing raw bytes to fd 1 corrupts only its own length-prefixed frame stream → its own session dies with a typed protocol error; no cross-Spirit effect, replies are matched to pending requests in order (`spirit_session.rs:640-655`).
5. **Hook-triggered capability use with the Spirit's tokens.** Ruled D-20-9-05 A: during `idle/consolidate/telemetry/schedule` exports only mediated `recall/context/skills` imports are allowed (`lifecycle_wire.rs:44-52`, runner `in_export` gating `runner.rs:556`, session `in_export` + `MAX_RECALLS_PER_TURN` `spirit_session.rs:657-669`); frame emission outside an active turn is a protocol violation (`:690-692`); in-process hook dispatch hands the guest `CapabilityHandle(0)` (`hook_dispatch.rs:397-412`).
6. **Guest starving the session/IAC mailbox with hook floods.** The session loop drains the mailbox **before** lifecycle exports (`spirit_session.rs:517-555` before `:556-575`, comment "a busy trigger caller must not starve the mailbox"); the link channel is bounded at 1 with hook-side deadlines (`spawned_lifecycle.rs:204-231`). Residual is F1's pump-side stall, reported above.
7. **`unwrap`/`expect` after serde in the new surface.** None found in production paths: `decode_reply`/`decode_request` are `map_err`'d (`lifecycle_wire.rs:60-72`), guest detail is clipped to 256 chars (`runner.rs:517-524`), frames capped at `MAX_FRAME_BYTES` (`cli_wrapper/runtime.rs:362-384`), `serde_json::from_slice` in `WorkerSpirit::on_telemetry_event` is matched (`supervision.rs:2736`), and the remaining `expect`s are lock-poison/setup invariants. The only serde-adjacent panic (`lifecycle_telemetry_undecodable`) is fed by the pump's own `to_vec`.
8. **`SwapSlot` Weak use-after-free.** `get()` upgrades a `Weak` owned by the supervisor (`supervision.rs:1814-1817`, set once at `main.rs:4928-4930`); every consumer re-checks (`spawned_successor` refuses `the root is shutting down`, `admit_spawned` refuses `SpawnedSurfaceUnsupported`), and teardown waits out hosted sessions (`main.rs:6927-6929`, `HostedSessions::wait_idle` `spawned_lifecycle.rs:358-366`). Fail-closed throughout; the `OnceLock` single-fill only matters if supervision ever re-arms in-process (it does not).
9. **Cold-swap TOCTOU (unload → admit) and refused-restore partial state.** Everything refusable runs before unload (CR-1, `operator_door.rs:1477-1567`); the restore path re-runs the full gate (`prepare_spawned_restore` → `load_admit_start` with FR11 + provider pins), identity mismatch unwinds via unload (`admit_and_start`, `:1663-1720`), and the double-refusal is the typed, journaled `cold_swap_failed` of D-19-5-02 A. `ManifestSnapshot` staging is `create_new` 0o0600 with ULID names (`:370-386`), so no temp-file squatting on the restore path.
10. **Pre-warmed child leak on a stalled `migrate`/`swap-in`.** The dispatcher timeout and the inline-exchange deadline use the *same* successor budget (`run_migrator` builds the temp SCB from the successor manifest, `migrator.rs:61-71`; link cap set from `prewarm.turn_budget`, `spawned_lifecycle.rs:317-329`), so the abandoned blocking thread and child end at the same bound; kill-on-drop holds for real refusals. Only F1-style budget length (≤24 h per export) is sanctioned by the manifest.
