# Security review — commit fba6af2a (`20-9 L1 correction round 4`)

Reviewed at HEAD `fba6af2a` (confirmed `refs/heads/main`); untouched by Dev205L1's concurrent edits (those live in `maos-exec-deps`, `xtask`, `docs-site`). Since `read` cannot inflate git objects, I verified the committed feature set in the tree at the exact files this commit's features occupy (all last modified by this commit chain); every cite below was read in those files.

## Findings

### F1 — HIGH — Attempt-blind fence release: a late successor-link drop steals and kills a *newer* swap attempt's token and unfences its predecessor mid-swap
`crates/maos-bin/src/spawned_lifecycle.rs:494-502` (`release_predecessor`), `:516-533` (`attach_successor`), `:505-512` (`Drop for LifecycleLink`), pin vehicle `crates/maos-bin/src/hook_pump.rs:224-240` (`Subscriber::dispatch_target` cached SCB) and `:355-369` (`sync`).

`release_predecessor` takes **whatever** attempt is currently installed on the predecessor (`attempt.take()` → `store(false)` → `set_fenced(false)`), with none of the `Arc::ptr_eq` identity care that `fence_for_snapshot` (`spawned_lifecycle.rs:449-456`) has on the set side. It runs from `Drop for LifecycleLink`, i.e. whenever the successor `WorkerSpirit` object's last `Arc` dies — and that can be far past the failed upgrade that owned it:

1. Attempt 1 fails at `swap-in` with a *guest refusal* (`Declined`/`Failed`). The inline-error fast path (`spawned_lifecycle.rs:281-291`) only fires on transport/decode errors, so `prewarm` (live child), `predecessor`, and `attempt` stay wired on the successor link. The kernel compensates (`hot_swap/coordinator.rs:334-360` restores the predecessor runtime) and `UpgradeOrchestrator::upgrade` returns, dropping its local — but not necessarily the last — `Arc` (`lifecycle/upgrade.rs:119-160`).
2. The successor object stays pinned by (a) the pump's cached dispatch-only SCB: any hook dispatch in the [step-8 install, compensation] window — telemetry for a successor listing `on_telemetry_event` (`receives_telemetry`, `hook_pump.rs:252-265`; spawned pids are registered at `admission.rs:1375-1377`) or an `on_idle` from the watchdog — makes `dispatch_target` build `entry.target` pinning the successor `spirit_obj`, and that cache is only dropped at the *next* object-change `sync` (`hook_pump.rs:224-240, 355-369`), i.e. at the next telemetry event for that pid; or (b) any in-flight hook dispatch (dispatcher holds the object for up to its cap / 60 s inline wall).
3. Operator retries (the door reports `swap-in failed`, inviting retry). Attempt 2 passes the door's `upgrade_lock` (`operator_door.rs:1405-1409`) — attempt 1's *pin*, not the lock, is what survives — and `attach_successor` overwrites `predecessor.attempt` with a fresh live token. Attempt 2's `snapshot` fences the predecessor (`spirit_session.rs:677-678`).
4. The stale pin now drops (attacker-timed: any Spirit's `scalar.tap` emission drives the pump's next `sync` for that pid; or the ≤60 s idle/telemetry dispatch simply ends). Stale `Drop` → `release_predecessor` takes **attempt 2's** token, marks it dead, and **unfences the predecessor** while attempt 2's migrate/swap-in is still in flight.

Impact: the fence is the AC8 state-freeze between snapshot and handover. With it lifted mid-attempt, the predecessor keeps taking frame turns (`spirit_session.rs:551` gate opens), so attempt 2's `swap-in` commits a successor onto state captured before those mutations — the exact invariant 20-9 r3/r4's `fence_for_snapshot`/attempt-owner work exists to uphold; additionally a second sandboxed child (attempt 1's un-killed `prewarm`) keeps running under the pid's admitted sandbox while the predecessor serves, until the pin drops. Cross-tenant trigger surface: the pin-release timing is driven by pump `sync`, i.e. by *any* emitter's telemetry events.

Fix sketch: store the successor's own attempt `Arc<AtomicBool>` on the successor link in `attach_successor`; in `release_predecessor`, only `store(false)` + `set_fenced(false)` when `Arc::ptr_eq(own, installed)`; have `attach_successor` end (store `false` into) any attempt it replaces; and on the pump side, drop `entry.target` when the registry entry's object no longer matches instead of caching across runtime cutovers.

### F2 — MEDIUM — 60 s wall is per stage, not per attempt: a silent successor holds the process-global upgrade lock ~N×240 s and fences the predecessor ~120 s per attempt
`crates/maos-bin/src/spawned_lifecycle.rs:32` (`PREWARM_WALL`), applied independently at `Prewarm::await_ready` and `Prewarm::exchange` (`cap.min(PREWARM_WALL)`, `spawned_lifecycle.rs:156-176`), used by `spawned_successor`'s ready-wait and `Probe` exchange (`:696-790`) and then again for `Migrate`/`SwapIn` inline exchanges; the whole chain runs under the door's single global `upgrade_lock` (`operator_door.rs:524, 593, 1405-1409`; factory → `spawned_successor` at `main.rs:3334-3380`; coordinator stages at `hot_swap/coordinator.rs:215-360`).

Each wall is 60 s but there is no total budget for one attempt: pre-warm `Ready` (≤60 s) + `Probe` (≤60 s) + predecessor `snapshot` (its own cap) + `migrate` (≤60 s, migrator policy) + `swap-in` (≤60 s) ≈ up to ~240 s of the *global* lock per attempt. Every other tenant's `upgrade`/cold-swap (`load_spawned` shares the lock, `operator_door.rs:1405-1408`) queues on that one `tokio::Mutex` with an unbounded `lock().await`. Meanwhile the predecessor is fenced (no frame turns or triggers) for the snapshot→resolution window, ≤120 s per attempt. Operator retries (or automation) chain attempts: N×~240 s global lock denial + N×120 s predecessor outage, driven entirely by a staged-but-malicious (supply-chain) or merely wedged successor staying silent inside each stage. Note the successor's *own* manifest cannot widen this (`min` with the wall), only repeat it.

Fix sketch: one per-attempt deadline (e.g. 90 s) from which every stage's wall is derived (`attempt_deadline.saturating_duration_since(now)` instead of `cap.min(PREWARM_WALL)` per stage); optionally bound the wait on `upgrade_lock` and/or make it per-spirit with a global try-acquire, and add a per-spirit failed-attempt backoff so retries cannot re-fence indefinitely.

### F3 — LOW — Per-invocation registry: duplicate keys misattribute busy/started between concurrent same-pid dispatches
`crates/maos-bin/src/invocation.rs:69-77` (`Registered::open` pushes without duplicate check), `:96-101` (`claim` returns the *first* record for a key), `:40-54` (unconditional last-write-wins phase stores), key at `:30`.

Two live dispatches with the same `(pid, kind, tag)` both `claim` the first record. Cross-*tenant* forgery is impossible (pid is in the key; pids are unique among loaded spirits; a record dies with its dispatch, which pins the object). But same-pid duplicates are reachable: `CONSOLIDATE` tags are `digest(payload)` (`hook_pump.rs:1465-1467`) and the forget-completion late-ids path (`hook_pump.rs:996-1028`) can emit byte-identical `ForgetNotice` payloads for two concurrent forgets of the same frames. Then one side's `cancel_queued` → `dropped()` marks the *shared* record `DROPPED`, so the other side's genuinely `Fired` dispatch is classified `busy` (`hook_pump.rs:1499`) and skips accounting entirely — no strike reset, no `last_consolidate_ns` update (slightly accelerating re-fires). No quarantine evasion: `busy` requires `Fired`, so `BudgetExceeded` overruns still quarantine (`hook_pump.rs:461-478`).

Fix sketch: key by a unique per-dispatch id handed from the pump to the link (or make `open` return/`claim` prefer the record registered by *this* dispatch via a token passed through the request).

## Rejected candidates (with reasons)

1. **Cross-tenant invocation-registry collision (assignment hypothesis)** — rejected: key includes the kernel pid (`invocation.rs:30`); telemetry tags are root-unique seqs (`maos-domain/src/invariants/i7.rs:46-48`) delivered by a single serialized delivery loop (`hook_pump.rs:1204-1233`), so equal telemetry keys can never overlap; watchdog (empty batch) vs forget (JSON) payloads never hash equal. Residual is F3.
2. **Parked-overrun unbounded accumulation DoS** — rejected: first overrun → `BudgetExceeded` → immediate quarantine of that runtime object (`hook_pump.rs:461-478`, `quarantine` :389-400), and spawned-form hooks self-terminate at `queue_share+limit+WALL_SLACK` ≤ ~47 s (`spawned_lifecycle.rs:317-325`), so parked `JoinSet` entries are transient and drain at shutdown (`hook_pump.rs:276-299`). Residual: shutdown can wait out a *compiled-in* (first-party, non-attacker) hook's full manifest cap.
3. **Cut-loose spawned hooks leaking children** — rejected as stated: children are owned only by `SpawnedBridge`s, whose `Drop` closes stdin and kills+reaps (`cli_wrapper/runtime.rs:1184-1187`); pump dispatch tasks never own a bridge. The true defect hiding here is F1 (pinned object ⇒ un-killed successor child + late fence steal), not an orphaned process.
4. **unwrap/expect after serde** — rejected: all production decodes are `Result`-typed with budgets — `Prewarm::exchange` maps decode errors (`spawned_lifecycle.rs:165-171`), the session maps to `SessionError::Codec` (`spirit_session.rs:715-717`), `decode_cbor` enforces expansion/nesting budgets (`maos-wasm-host/src/codec.rs:33-35`). Every `unwrap()` near serde lives in `#[cfg(test)]` modules (`codec.rs:116-128`, `lifecycle_wire.rs:130-155`, `recall_wire.rs:270-332`); `coordinator.rs`'s `.expect("spirits lock poisoned")` are std-lock poisoning, pre-existing, not serde.
5. **Direct fence release on failed inline *exchange* leaving the predecessor serving while the successor child lives** — rejected on the error path itself: ordering is correct (`drop(prewarm)` → bridge kill+reap → *then* `release_predecessor`, `spawned_lifecycle.rs:281-291`), and scopes never widen (`spawned_successor` refusal at `:734-741`). The exploitable variant is the *Declined* path, where release is deferred to a late `Drop` — that is F1.

Adjacent observation (not counted): `IdleWatchdog::check_and_fire` awaits each `fire_on_idle` sequentially (`maos-kernel-core/src/scheduler/idle_watchdog.rs:100-118`), so one spawned Spirit whose silent guest stretches `on_idle` to its admitted `cap` stalls idle triggers for *all* spirits for that long — the consolidation watchdog got concurrent passes (`hook_pump.rs:1300-1315`); idle/schedule did not.
