Scope reviewed read-only at the working tree (`HEAD` = `8c669a21`), against the L1 baseline in `landing-1/review/security.md` (commit `cdf3937d`) and the corrections evidence under `landing-1/review-corrections/`. All ten assigned areas traced; earlier findings' dispositions verified (F1 → D-20-9-17, F2 → D-20-9-19, F5 → `env_contract.rs:206-210` now registers `MAOS_ARCHIVE_DIR` as HarnessOnly; F3/F4-second-half/F6 remain deferred rows in the dev record, unchanged code).

## Findings

### R1 — MEDIUM (availability; erasure/privacy pipeline) — `on_consolidate` fan-out is still sequential and bounded only by each subscriber's full manifest budget (≤ 24 h); a quarantined subscriber is still dispatched here
- **Where:** `crates/maos-bin/src/hook_pump.rs:1204-1252` (`consolidate_once` — `dispatcher.fire_on_consolidate(&target, &[])` awaited per pid, sequentially, no wall); `:771-830` (`complete_forget` — per-pid sequential `fire_on_consolidate(&target, &bytes)`, `dispatch_target` called with **no eligibility/quarantine filter** — the deliberate privacy bypass); `:921-934` (late-notice sweep fan-out, same shape). Budget source: `hook_dispatch.rs:548-641` — dispatcher timeout is `effective_cap_seconds` = the subscriber's `[budget].time_cap_seconds`, validated ≤ 86 400 (`maos-manifest/src/manifest.rs`).
- **Exploit/impact:** D-20-9-17 fixed the *telemetry* half of F1 but left the consolidate/privacy half sequential and wall-less. (a) A subscriber listing `on_consolidate` whose session never answers stalls `consolidate_once` — hence every other subscriber's consolidation and the watchdog's next tick — for up to its full budget once (≤ 24 h), then quarantines. (b) Worse, `complete_forget` deliberately bypasses quarantine ("privacy notice must bypass telemetry quarantine", test at `hook_pump_17_4.rs:1812`), so an already-quarantined malicious subscriber still receives each forget notice and can stall the GDPR erasure-completion path (`finish_forget` → TL certification tail) by up to its budget **per forget request, repeatably, forever**; undelivered pids are only marked `forget.purge.undelivered`. Amplifier: `sync()`/`account()` call `subscription_row` → `tl.insert_frame_event` (SQLite write) **while holding the registry mutex** (`hook_pump.rs:345-357`, `466-499`), so a stalled TL write also blocks every concurrent delivery task at the lock.
- **Fix sketch:** apply the same per-subscriber wall (`min(95% cap, 5 s)` or a dedicated consolidate wall) around both `fire_on_consolidate` fan-outs and run them in a `JoinSet` like `deliver`; move `subscription_row` writes out of the registry critical section (queue rows, flush unlocked).

### R2 — MEDIUM (wrongful quarantine / false audit rows; D-20-9-18 × D-20-9-17 interaction) — a spawned subscriber that is merely *busy* is quarantined as a budget overrun, because the pump's 5 s wall fires before the hook's own `busy` give-up
- **Where:** `crates/maos-bin/src/hook_pump.rs:503-516` (wall = `min(0.95·cap, 5 s)`; wall timeout fabricates `HookOutcome::BudgetExceeded`); `:437-441` (a single `BudgetExceeded` → immediate quarantine + revoke row, message "exceeded its {cap} s budget"); `crates/maos-bin/src/spawned_lifecycle.rs:260-269` (a trigger blocked on the 1-slot channel retries for `queue_share = cap/2` before returning `BUSY`); session takes lifecycle calls only between turns (`spirit_session.rs:644-660`, gated by `!active && pending.is_none()`), and turns run up to `turn_budget` (default 30 s, `spirit_session.rs:196-200`).
- **Exploit/impact:** for every budget > ~9.5 s — including the **default 30 s** — `TELEMETRY_WALL` (5 s) < `cap/2`, so a telemetry event arriving while the component is mid-turn (or mid-export, or awaiting adoption under D-20-9-18's queue-until-session) never reaches the `BUSY` give-up: the pump wall fires first, the subscriber is quarantined on first offense, its `governance:telemetry-subscription` grant revoked, and a TL row claims "on_telemetry_event exceeded its 30 s budget" when 5 s elapsed and the hook never started. D-20-9-18's own protection ("dropped, never a strike") is dead for telemetry at default budgets. No attacker needed — normal 5–30 s turns trigger it; quarantine is permanent for the runtime object (`resume` doesn't lift it, `hook_pump.rs` sync resets only on a new object).
- **Fix sketch:** make the pump wall and the link's start-deadline consistent — either charge wall-timeout-while-queued as the `BUSY` non-strike (surface "never started" from the link, e.g. answer `Busy` immediately once `queue_deadline < wall`), or apply the wall only to the *dispatch* phase after the call started, or raise the wall above `cap/2` for small caps.

### R3 — MEDIUM (availability; fairness-rule evasion) — the 3-consecutive-80% rule is evadable by alternating, and one unquarantined slow subscriber floors the whole root's telemetry throughput at ~1 event per wall, blacking out the stream via broadcast lag
- **Where:** `crates/maos-bin/src/hook_pump.rs:400-416` — `Fired` resets **both** counters; `BudgetWarning80` also resets `strikes`; a `BUSY` return is mapped to `Unsupported` by `WorkerSpirit::lifecycle` (`supervision.rs:2720-2725`) and thus accounts as `Fired` (reset). `:529` — `deliver` joins **all** tasks of one event before `delivery_loop` takes the next (`:1105-1112`), so per-event cost = the slowest subscriber's wall. Ring: 2048 (`telemetry/mod.rs:69-71`, `main.rs:2198` `TelemetryStreamAdapter::default()`).
- **Exploit/impact:** a subscriber with e.g. `time_cap_seconds = 6` (80% = 4.8 s < 5 s wall) alternates a 4.9 s delivery (`BudgetWarning80`, slow=1) with a fast one or a busy turn (`Fired`, slow=0): never 3 consecutive, never quarantined, ~4.9 s per event forever. Since `deliver` is event-sequential, the entire pipeline drains ≤ ~0.2 events/s; any emission above that overflows the 2048 ring in minutes and every event is `Lagged`-skipped **for all subscribers** — a bounded-but-unbounded-in-duration blackout of the audit stream by one admitted component. Same trust premise as L1 F1 (manifest-admitted code), now bounded per event (5 s, not 24 h). No test covers alternation (`hook_pump_17_4.rs:314` only sends consecutive warnings; `f1-slow-strikes-reset.log` plants the increment, not the reset-on-Fired evasion).
- **Fix sketch:** make `slow` decay instead of reset (e.g. strike on 3-of-last-N slow deliveries), don't count `Unsupported`-from-`BUSY` as a clean `Fired`, and detach per-subscriber pacing from the event loop (per-subscriber queues with the wall, per D-20-9-17 option C) so one subscriber cannot set the global rate.

### R4 — LOW (availability; audit pipeline) — the fixed 5 s wall silently overrides the manifest budget contract for compiled-in Observers and evicts them on a single slow delivery
- **Where:** `crates/maos-bin/src/hook_pump.rs:82-84` (`TELEMETRY_WALL` doc: "however large its manifest budget"), `:503` (wall `min(0.95·cap, 5 s)` over the subscriber's own SCB snapshot), `:437-441` (single `BudgetExceeded` → quarantine + grant revoke), manifest validation still sanctions `time_cap_seconds` 1..=86 400.
- **Exploit/impact:** a compiled-in Observer (the operator-conferred audit surface) legitimately configured with e.g. 60 s that spends > 5 s on one event (burst analysis, GC pause, slow sink upstream) is quarantined **once**, permanently for that runtime object (compiled-in classes have no hot-swap reset), silently dropping it from the audit stream — the revoke row and one stderr line are the only notice, and the row misreports ("exceeded its 60 s budget" at 5.01 s). Not attacker-amplifiable beyond load; it is a policy inconsistency between the sanctioned budget range and the enforced wall, with single-strike (not 3-strike) severity.
- **Fix sketch:** either validate observer budgets to ≤ wall at admission (reject > 5 s declarations for telemetry-listing classes, making the contract honest), or make the wall configurable and give wall overruns the same 3-strike grace as panics, and word the quarantine row with the actual wall.

### R5 — LOW (containment is resolve-time only) — `resolve_artifact` TOCTOU: the child opens the artifact by path after the check; hardlinks pass by construction
- **Where:** `crates/maos-bin/src/spirit_session.rs:106-133` — refuses absolute/`..`, canonicalizes root and target, `starts_with` (component-wise — correct); but the resolved path is handed to `maos-wasm-host/src/adapter.rs:60-68` as `--component <path>` argv and opened by the **child** later (`resolve_launch` itself only `metadata()`s), with `FsRead { subtree: artifact }` pushed at `spirit_session.rs:285-289`.
- **Exploit/impact:** between canonicalize (launch, `spawned_lifecycle.rs:528-542` pre-warm; restore preflight `main.rs:10487-10512`; re-resolved at `admit_spawned` → `manifest_launch_in`) and the child's open, any writer of the origin directory can `unlink`+symlink the artifact to load **unvetted code under the predecessor's admitted sandbox with a read grant on the resolved path**. The credible in-model writer is a **predecessor Spirit holding an `FsWrite` scope covering origin** during an operator-initiated (or daemon-scheduled) hot swap — it defeats the operator's artifact vetting while every textual gate passes. Hardlinks (same fs, path inside origin) pass containment by construction — bounded: a hardlink creator can already read the target; the residual is the child's read grant. `/proc` self-links and case folding are handled correctly (symlinks to `/proc/self/exe|fd/N` canonicalize to their real targets and are refused unless genuinely inside origin; both sides canonicalized; Linux paths are case-sensitive and `starts_with` is component-wise, so no prefix tricks); mount tricks need `CAP_SYS_ADMIN`, out of model.
- **Fix sketch:** open the artifact once with `O_NOFOLLOW`/`openat2(RESOLVE_BENEATH)` at resolve time and pass the fd (or a `/proc/self/fd/N` path with the fd held) to the child; verify inode identity (dev+ino) between resolve and spawn.

### R6 — INFO (bookkeeping; no escalation) — `authorize_principal_writes` is never released on unwind/unload
- **Where:** `crates/maos-bin/src/admission.rs:1387` (insert on every `load_admit_start`, including paths later unwound by `unwind_admitted` `:1431-1440`); `maos-kernel-core/src/memory/mod.rs:407-413` (insert-only `HashSet<u32>`, no removal anywhere); pid source `scheduler_loop.rs:31-33` (`NEXT_SPIRIT_PID.fetch_add` — **monotonic, never reused**).
- **Impact:** no privilege escalation (a stale pid can never name a future Spirit); residual is unbounded set growth (4 B-entry ceiling, negligible) and an authorization set that outlives its Spirit. Contrast: tokens/promotion set/pid-map/context-budget *are* cleaned (`spirit_session.rs:745-758`, `rollback`). Fix sketch: `deauthorize_principal_writes(pid)` in `rollback`/session teardown.

### R7 — INFO (audit asymmetry) — a `spawned_start_failed` unwind leaves the pump registration and its grant row outstanding until the next telemetry event
- **Where:** `crates/maos-bin/src/admission.rs:1346-1348` (`hooks.register` inside `load_admit_start` — reached by `admit_spawned` via `AdmissionDeps.hooks: Some(&self.hooks)`, `main.rs:10448`); `unwind_admitted` (`admission.rs:1431-1440`) never unregisters; cleanup happens only lazily at `hook_pump.rs:469-472` (`unregister(pid, "unloaded")` on the next delivery finding no SCB) or root shutdown.
- **Impact:** after a refused cold swap, a `governance:telemetry-subscription:granted` row can persist with no matching revoke if no `scalar.tap` event follows — an audit-trail asymmetry, not a live grant (the SCB is gone; `sync` would revoke on next event). Fix sketch: pass the pump handle into `unwind_admitted` (or return the pid for the caller to unregister with reason `spawned_start_failed`).

## Rejected candidates (investigated, not exploitable as framed)

1. **Force-quarantine of a competitor.** Strikes charge the dispatched pid+object only: `account` (`hook_pump.rs:379-398`) re-checks `same_object` before charging; the dispatcher has no serializing lock — each hook runs in its own `spawn_blocking` under an RwLock *read* (`hook_dispatch.rs:557-641`), and pump dispatches for one pid are event-sequential. Concurrent consolidate+telemetry on one pid degrade to `BUSY` (no strike). No path found to make another subscriber exceed *its* wall.
2. **Hook queue growth during handover (memory DoS).** The lifecycle channel is `sync_channel(1)` (`spawned_lifecycle.rs:194`); at most one queued `Call` (small, fixed) per link; waiters are bounded by `queue_share`/`cap` (`:260-295`) and give up `BUSY`/`DEADLINE`. No unbounded structure exists.
3. **`CallState` race fencing a predecessor wrongly.** The CAS machine (`:35-71`) makes hook-cancel and session-answer mutually exclusive: a late snapshot reply with `answer()==false` sets **no** fence and drops the reply (`spirit_session.rs:672-681`); if the session wins, the hook receives the in-flight reply (`call` keeps recv-ing after a failed cancel). `Drop` unfences only the still-recorded predecessor (`:406-413`).
4. **Successor serving without admission.** Registration happens only at session adoption (`adopt_spawned`, `supervision.rs:1800-1812`); `prepare_spawned` never registers; `swap_hook_disabled` refuses before anything is fenced (`spawned_lifecycle.rs:631-636`); scope-subset + declaration gates precede every coordinator step.
5. **Session death before adopting a committed handover → child/process leak.** Session teardown runs `binding.finish` → `registry.retire` → core/link drop → `Handover` (with the pre-warmed child) drops → kill-on-drop (`supervision.rs:1466-1487`; `spirit_session.rs:735-758`). Residual is the *acknowledged* F4-class "spirit absent" (D-19-5-02 A; dev record marks F4's second half open) — known, not new.
6. **Pre-warmed `migrate`/`swap-in` stall.** Inline exchanges are bounded by the successor's own manifest budget (≤ 24 h, operator-sanctioned, journaled) — same accepted bound as L1 rejected #10; p6/p7 added per-turn deadline checks and late-frame refusal.
7. **`unwrap`/`expect` after serde in the new surface.** `subscription_row` uses let-else; `complete_forget` maps all serde errors; wire decodes are `map_err`'d (`lifecycle_wire.rs`); the remaining unwraps are annotated-infallible (`main.rs:9068`) or test code. The one panic (`lifecycle_telemetry_undecodable`, `supervision.rs:2746-2757`) is fed by the pump's own `serde_json::to_vec` output.
8. **`swap_hook_disabled`/`spawned_start_failed` info leaks.** Both strings carry manifest class names and *typed* session error text (paths, exit causes) to the operator door caller and the TL (`spawned_lifecycle.rs:580-581, 631-636`); guest stderr is never inlined (it is separately journaled under a diagnostic budget). Operator-facing only; no cross-tenant disclosure path found.
9. **Cold-swap restore weaknesses.** Restore uses retained manifest bytes (`ManifestSnapshot`, `create_new` 0o0600), re-runs the full gate + provider pins + `resolve_artifact` against the live predecessor's recorded origin (`operator_door.rs:1467-1610`, `main.rs:10487-10512`), refuses `cold_swap_unrestorable` before unload, and `admit_spawned` now returns only after the lifecycle probe (p3), unwinding fully on failure. Only the R5 open-time TOCTOU is shared.
10. **Guest stdout forgery on the pre-warm child.** `exchange` demands an `is_reply` frame (non-reply → typed `child_protocol` refusal), late frames are refused by per-turn deadline checks (`spawned_lifecycle.rs:110-160`), and a stderr flood cannot outlast the cap (each drain is a loop turn).
