## What this run taught (and changed in the recipe)

1. `IdleWatchdog` fires `idle` once per quiescence: `crates/maos-kernel-core/src/scheduler/idle_watchdog.rs:93-95` (`last_fire >= last_inbound && last_fire > 0` → not due). Nothing delivers a frame to a `maos run` Spirit, so the example's `idle` ran once, before the swap, and never again (`MAOS-209 idle 1` is the only line; no idle for the 2+ minutes the job waited). The "N+1 after the swap" proof therefore cannot come from `idle` alone.
2. The successor's `swap-in` `console.log` is dropped by the product by design: `crates/maos-bin/src/spawned_lifecycle.rs:160-162` (`Prewarm::next_stdout`: "Stderr is drained and dropped" for a child nobody is serving yet), and the `swap-in` exchange runs on that pre-warmed child before adoption. So `swap-in` output of the TS example is never journaled. (The example's README promises `console.log` is routed to the host as `spirit.diagnostic`; true for a serving session, not for the pre-warm exchanges.)
3. Hence run 2's variant: the recipe-local `logged` variant also bumps and logs the same counter in `consolidate` (the kernel's periodic caller, which does fire repeatedly), so the counter keeps being observable after the swap.
