## F4 ratification record (operator, 2026-07-17)

**Ratified: Option A+.** Preserve one operator-signed cohort manifest and accept read schemas `{1,2}`. The Rust field remains `teams: Option<Vec<TeamEntry>>` so strict serde can represent both schemas, but the semantic invariant is exact: **v1 ⇔ `teams == None`; v2 ⇔ `teams == Some(non-empty)`**. Tenant-enabled composition requires verified v2; v1 is accepted only for non-tenant cohorts and is never an operational fallback.

**Signature contract:** v1 keeps its current canonical bytes and `SIG_DOMAIN_V1 = b"maos.cohort-manifest.v1"` byte-for-byte. v2 uses `SIG_DOMAIN_V2 = b"maos.cohort-manifest.v2"` and appends canonical teams after the unchanged common fields. Encoding/signing/verifying dispatches explicitly by schema. No ambiguous `SCHEMA_VERSION` or `SIG_DOMAIN` alias remains.

**Identity/placement contract:** `TeamId` is one shared pure domain type used by cohort and Loom; `TeamEntry.region` is itself the operator-authoritative placement declaration and must be in the shipped `Region::canonicalize` form—there is no separate region registry to reference. `datname` is canonical lowercase Postgres identifier form `^[a-z_][a-z0-9_]{0,62}$`. Team IDs and datnames are unique; one stable `SpiritId` belongs to exactly one team.

**Rollout/downgrade contract:** deploy the dual reader to every cohort host while still issuing v1; only then issue signed v2 and activate tenant stores after each local node has verified and journaled v2 adoption. Old v1 binaries fail closed on v2, so premature issuance is an availability split, never an accepted rollout. Once a state has accepted tenant v2, a higher-revision v1 reissue is rejected and audited; after restart, configured tenant mode also refuses boot on v1. Recovery is a higher manifest revision under schema v2, never schema downgrade.

## Story

As a **MAOS operator running Reza's 400-person fintech as one governed Cortex (three teams: security, support, data)**,
I want **each team's Loom-lite collective rows to live in a physically separate Postgres database (distinct `datname`) that another team's connection cannot name, with a single store-internal `team_guard` chokepoint below `CollectiveMemoryPort` that refuses fail-closed when the caller's manifest-declared team is not this store's team (`ETenantConnectionMismatch`) or when its cached tenant map has gone stale (`ETenantMapStale`)**,
so that **cross-team leakage is not one `WHERE` clause away — it is physically impossible to express — and NFR-Tenancy-1's boundary stays loud: multi-tenancy arrives at v2.2 as an explicit, mechanically-proven capability, never a silent assumption.**

**This story exists in the shape below because the preflight disproved five of the epic's six sketched ACs against the code at HEAD `83f21ad6`.** Four parallel code-verification scouts grounded every premise FIRST, then an independent adversarial validator re-checked the result (the standing 12.x/13.x discipline). Headline disproofs: (1) **there is no SQLite collective store** — `maos-loom-lite` is Postgres-only (`store.rs:9` `deadpool_postgres`; `rusqlite` is a *migration source reader* only, `canonical.rs:185`), so the epic's "hermetic 2-team SQLite smoke as the BLOCKING leg" would test code that does not ship — the exact "claim standing in for a control" failure E12-B6 names; (2) **`ADR-054` explicitly disclaims owning the mapping** (`ADR-054:35` — *"that belongs to ADR-055/§15.3, not here"*), and **ADR-055 does not exist**; (3) **there is no "announced current version"** anywhere in `crates/` — the shipped staleness primitive is a **time lease** (`state.rs:369-377` `is_fresh()`, `t_stale_secs`); (4) **`spirit_pid` is a kernel-set ephemeral `u32`**, not signable manifest identity — an operator cannot know pids at signing time; (5) **the collective tier has ZERO production callers** (`collective_write/read/scan` are called only from `xtask/tests/story_10_4a_ac1_proven_red.rs:897,930`), **and no erasure reach at all** (F16). 13.1 is therefore an honest **MECHANISM** story (the 12.3/12.4a precedent), proven at the real store seam. It builds the **physical** wall and the **chokepoint**. It does **NOT** build the cryptographic boundary (13.2), cross-team writes (13.3), or the Reza scene (13.6). It does **NOT** touch `maos-kernel-core`.

### Traps (each one has already bitten this codebase)
1. **A skipped leg is *unmeasured*, not green** (`check_cross_region_consensus.rs:127`). `LegResult::skipped()` ⇒ `ran:false, green:false` `:135-144`.

3. **Blocking is decided in Rust, not YAML.** No `continue-on-error` on these jobs; a gate returning `Ok` + banner is **green in CI** (`main.rs:1231-1234`).
4. **`check-kernel-baseline` is exact equality** (`check_kernel_baseline.rs:65`) — even a `cargo fmt` reflow reds it (re-pin 23147 was literally that).

6. **An empty result is not a refusal — and it can destroy your own control.** `ETenantConnectionMismatch` must be typed and surfaced; and the absence witness must read through the **unguarded** path or it proves nothing (F19).
