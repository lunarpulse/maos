# 17-1 — Worker egress allowlist and scoped credential ◆ FLAG-Winston

Status: ready-for-dev — operator rulings 2026-10-06 (Lunarpulse): kernel grant variant **B** ratified as the ceiling (`src_lines` 25293 → ≤ 25353, kloc 19529 → ≤ 19564, `maos-domain` 9270 → 9274; `_aggregate_hardfail` and the `maos-bin`/`maos-egress`/`xtask` rows exact at landing, aggregate raise ≤ +1182); ADR-061 M3 amendment ratified and written (`## Amendment — Story 17-1`, body-anchored in `decision_adrs_and_provisioning.rs`); Q1–Q7 ruled (§Operator rulings). > **The capability:** *A `[cli_wrapper]` Worker runs inside a rootless-podman T3 container with `--network=none`, a read-only root and no host mounts but its own binary; the only thing it can reach is a daemon-owned Unix socket whose far end is a proxy that holds the vendor key, forwards only the destinations the manifest asks for and the host grants, and writes a durable kind-8 row for every refusal before it answers. The Worker's environment is its own `--env` list — a per-spawn proxy bearer and a base URL, never the raw key and never the daemon's environment — and a granted T3 is applied or refused, never spawned bare.*

**Closes:** S2 (sandbox never applied) for Workers · FR4/FR5 for Workers (FR47 only as narrowed by ADR-061: the proxy is the Worker's sole egress, not the kernel Inference Port) · R17-32/-33 (mechanism, journal-before-return) · R17-34/-35/-86 (the published isolation claims, en + ko, incl. the cookbook's nonexistent `hardened` tier) · R17-36 (the T3 jobs cannot fail) · R17-45 (M3 built) · R17-8 (kind-8 for a container-internal refusal, corrected by R17-83) · the two 17-3c deferred rows `deferred-work.md:1072` (`env_clear`) and `:1076` (unbounded stdout reader) · `deferred-work.md:40`, `:48`, `:822`, `:959`, `:960`, `:1038` (rows whose owner is this story) · epic-17 exit lines 1, 1b and the creation of the `epic-17-exit` job that also carries lines 2 and 3.

**Does NOT close, and says so:** cgroups for Workers (`17-2`: `resolved_caps` stays `Default`, so podman's `--cpus=1 --memory=256m --pids-limit=64` defaults apply); a live vendor-CLI Worker (operator lane `ops-live-worker-under-17-1-profile`: it needs a signed image containing the CLI, an entry shim and a vendor key — **this story ships a static fixture and the proxy, not a vendor image**); `deny_unknown_fields` on `[cli_wrapper]` (a named cut line, §Declared cut lines); the twenty non-network scenarios of `t3-escape-corpus-v0` (the five `--network=none` scenarios get an executor); executing the operator-named binary on the host at admission time (the probes lose the environment, not the execution — D-9); `emit_t3_escape_block` / `quarantine_spirit` (zero callers, named not fixed).

## Story

As **the operator who lets a vendor CLI act as a Worker on my machine**,
I want **the Worker to run in a T3 container whose only door is an allowlisted, journaled, credential-holding proxy, with an environment I can enumerate and a spawn path that never silently runs it bare**,
so that **the key never reaches the child, a misbehaving Worker's refusals are in the Transparency Log rather than in its own stdout, and the published words "sandboxed" and "container" describe a process that is in fact in one.**

### Guardrails

- **Never self-grant** (see §Operator grant requested). The prototype diffs are evidence, not a patch: re-derive test-first.
- **ADR order is part of the decision:** proxy + bearer wired and exercised → T3 route → `env_clear` + guard inversion in the **same commit** as the route. `env_clear` must never land alone (it would knowingly red a shipped control, ADR-061 `:75-85`).
- **Never a bare fallback** for a granted T3: no runtime, no lock, no image, no `t3` launch data ⇒ a typed refusal that names the cause (17-6 AC5; D2 = a). Search the final tree for any path from `SandboxTier::T3` to a plain `Command::spawn`.
- **No value on argv.** `--env=NAME` only; the test reads `/proc/<podman pid>/cmdline`. The bearer and the raw key never reach a journal row, a log line, an error string or a panic message.
- **kind-8 truth:** the network row comes from the proxy's confirmed write; the filesystem rows are a labelled self-report; none from stdout; a Worker can only produce rows about itself, T3, stderr.
- **Kernel is `#![forbid(unsafe_code)]`** in `runtime.rs`; the kernel gets no HTTP, TLS, DNS or tokio dependency from this story; `maos-egress` has no `maos-kernel-core` edge (`check-dependency-closure`, ADR-061 `:87-89`).
- **Tests that count:** kernel unit tests under `src/` cost physical lines; new kernel tests go to `crates/maos-kernel-core/tests/`.
- **Skips:** a skip is legal locally with a named reason and **never** on a runner the job declares capable (rule 11(b)); `continue-on-error` and `|| echo` are forbidden on every job this story touches.
- **Plant, observe, record (rule 11(c)):** every control gets a planted fault seen red (CI run id or committed local output); a planted diff must come with a warning-free build (RT-10).
- **Do not redo** what 17-3b/17-3c/17-6 fixed (P17). **Do not add** `deny_unknown_fields`, a probe-in-T3, or a vendor image (cut lines).
- The fixture is **static** (`RUSTFLAGS='-C target-feature=+crt-static'` with an explicit `--target` for the fixture build, or a musl target if the toolchain already has one — do not add a rustup step the job does not already have without saying so); `inspect_container_host_pid` needs the container alive ≈2.25 s.

### Latest technical facts

- **podman:** `--env NAME` (no value) copies the value from the *client's* environment and only if set; `--http-proxy` defaults to true and copies the client's `HTTP(S)_PROXY`/`NO_PROXY` into the container — hence `--http-proxy=false`. CI images: ubuntu-24.04 podman **4.9.3** (netavark), ubuntu-26.04 podman **5.7.0**; `ubuntu-latest` moves 24.04 → 26.04 (kernel 6.17 → 7.0) between 2026-10-19 and 2026-11-19 (actions/runner-images#14748), so pin both images, never `-latest`.
- **Rootless userns:** a 0600 host Unix socket is refused to the remapped container uid; 0666 inside a 0700 daemon-owned directory connects (measured, 17-3a Q6). That the 0700 directory is the host-side custody boundary is [INFERENCE] in R17-45; it is **not** a boundary against a same-uid process (it traverses the directory as the daemon's own uid), so the **bearer** is the authentication and the directory only keeps other uids out — this story measures both (AC3 proof: a same-uid process without the bearer is refused by the proxy) and states exactly that in the docs.
- **Container argv[1]:** the Worker program is mounted as `/maos/spirit` and called with `--` as its first argument (`argv.rs:84-85`); a real vendor CLI's treatment of `--` is operator-lane.
