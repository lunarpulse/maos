# 17-1 — Worker egress allowlist and scoped credential ◆ FLAG-Winston

Status: done — Tasks 0–11 complete (2026-10-09); §A6 review closed 2026-10-10 (8 patches applied, 1 corrected-dismissed, 5 dismissed; re-pin 25267/19553/1769/173383; RT-10 supplement recorded). All ACs are implemented and proven: exit-job run `37988000230`, capable sweep `37983335101`, docs-site `37995772747`, proven-red `37999039580`. Governance is re-pinned at the exact measured landing figures. The §A6 binding review (all layers, non-author) is owned by the `review` phase per the operator's 2026-10-09 ruling.

> **The capability:** *A `[cli_wrapper]` Worker runs inside a rootless-podman T3 container with `--network=none`, a read-only root and no host mounts but its own binary; the only thing it can reach is a daemon-owned Unix socket whose far end is a proxy that holds the vendor key, forwards only the destinations the manifest asks for and the host grants, and writes a durable kind-8 row for every refusal before it answers. The Worker's environment is its own `--env` list — a per-spawn proxy bearer and a base URL, never the raw key and never the daemon's environment — and a granted T3 is applied or refused, never spawned bare.*

**Closes:** S2 (sandbox never applied) for Workers · FR4/FR5 for Workers (FR47 only as narrowed by ADR-061: the proxy is the Worker's sole egress, not the kernel Inference Port) · R17-32/-33 (mechanism, journal-before-return) · R17-34/-35/-86 (the published isolation claims, en + ko, incl. the cookbook's nonexistent `hardened` tier) · R17-36 (the T3 jobs cannot fail) · R17-45 (M3 built) · R17-8 (kind-8 for a container-internal refusal, corrected by R17-83) · the two 17-3c deferred rows `deferred-work.md:1072` (`env_clear`) and `:1076` (unbounded stdout reader) · `deferred-work.md:959`, `:960`, `:1038` (rows that name 17-1 as owner) · `deferred-work.md:40`, `:48`, `:822` (rows that name **no** owner; this story claims them by subject — S2, egress enforcement, the clean-home TOCTOU) · epic-17 exit lines 1, 1b and the creation of the `epic-17-exit` job that also carries lines 2 and 3.

**Does NOT close, and says so:** cgroups for Workers (`17-2`: `resolved_caps` stays `Default`, so podman's `--cpus=1 --memory=256m --pids-limit=64` defaults apply); a live vendor-CLI Worker (operator lane `ops-live-worker-under-17-1-profile`: it needs a signed image containing the CLI, an entry shim and a vendor key — **this story ships a static fixture and the proxy, not a vendor image**); `deny_unknown_fields` on `[cli_wrapper]` (a named cut line, §Declared cut lines); the twenty non-network scenarios of `t3-escape-corpus-v0` (the five `--network=none` scenarios get an executor); executing the operator-named binary on the host at admission time (the probes lose the environment, not the execution — D-9); `emit_t3_escape_block` / `quarantine_spirit` (zero callers, named not fixed).

## Story

As **the operator who lets a vendor CLI act as a Worker on my machine**,
I want **the Worker to run in a T3 container whose only door is an allowlisted, journaled, credential-holding proxy, with an environment I can enumerate and a spawn path that never silently runs it bare**,
so that **the key never reaches the child, a misbehaving Worker's refusals are in the Transparency Log rather than in its own stdout, and the published words "sandboxed" and "container" describe a process that is in fact in one.**
