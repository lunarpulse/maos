F2 (review round 1, both reviewers; lane Fix232Scope): the assertion turn scope is bound to the CLAIMED TASK FRAME, not to the caller's wait.

Change: `run_turn` no longer enters a scope. The assertion travels with the queued request (`ShellPort::arm_labelled(.., assertion)` -> `ShellSlot.assertion`). The session gives it force in `ShellPort::claim`, i.e. only when it dequeues THAT exact frame (`assertion_supply::enter` -> `ShellBinding.scope`), and the session ends it when the export completes (the `drop(scope)` before `done.send`) or aborts (`bound` is now declared outside the loop closure and dropped only after the child is stopped and reaped). A claim while another scope holds the pid refuses the frame ("assertion scope already active for this spirit"); `enter` never replaces. `MiraRunner::run` takes a per-runner serial lock before it enters Mira's scope (F2c).
 (a) an ordinary mailbox turn running or queued ahead of the task frame resolves the environment: the assertion is not in force until the claim.
 (b) after a deadline overrun the caller's `ShellTurn` is gone but the export is not: the scope stays Alice's until the session ends the export; the next task armed on the same pid (Bob) is refused at claim while Alice's export holds the pid and takes force only on its own claim afterwards. Alice's late mints are never Bob's and never the environment's.
 (c) Mira's turns are serialised.

Limits (not closed here):
 1. The seam still sees a pid, not a caller: a lifecycle hook, or Mira's own background work, that mints for the same pid while the pid's export is running uses that task's assertion (module doc of `assertion_supply.rs`, RELEASE-HOLDS 23-2.c).
 2. There is no daemon-reachable ordinary (non-door) mailbox turn on a probe Host (the only frame ingress is the door), so the "ordinary turn ahead of the task keeps the environment" case is proven at the layer that owns it (ShellPort claim, unit test), not end to end. A Host at rest mints nothing for the probe, so there is no daemon-observable mint outside a door turn either; the attribution test asserts the at-rest rows (if any) are the environment's.
 3. `ShellPort::arm_labelled` still does not refuse a new request while a CLAIMED turn is running (the Busy check sees the slot only); the new request waits in the mailbox and its claim is refused while the earlier export holds the pid. A session whose overrun export keeps going is stopped by the session's own wall (the export wall equals the shell deadline), so the window is the poll tick.
