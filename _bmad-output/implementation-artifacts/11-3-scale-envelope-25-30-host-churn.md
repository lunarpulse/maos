## Story

As the **operator of a growing Cortex** (Reza / Journey-12) who cannot personally vet every host that joins my institution's peer mesh,
I want **the platform to detect a hostile or misconfigured host under realistic membership churn, bound its blast radius, and recover within objective time — proven on a real 25/30-host mTLS mesh whose numbers are DERIVED from actual trust-rejection events, not asserted constants**,
so that **I can trust the v2.0 scale envelope (NFR-Scale-2 / NFR-Rel-7) is a measured property of the system, not a green-by-construction scaffold — and a regression that blinds a detector or widens the blast radius reddens CI instead of shipping silently.**

### Explicitly NOT in 11.3 (defend at review)
- **100-host churn** — v2.5 (Epic-11 §Cut; NFR-Scale-2 second half). This story is the **cost-compressed 25/30-host** envelope only.
- **A real 4-week soak / real geo-distributed hosts.** The 4-week × 10–20%/week window is modeled as a **compressed churn-event schedule** on a **loopback co-located** mesh; the sustained 30-day soak (NFR-Scale-1) and any absolute geo/production-scale timing are **release-gate artifacts this AC set *enables*, evicted from the AC set** (the 11.2b soak/geo-SLO eviction precedent). Loopback churn events are sub-second → the floors pass trivially on the clean path; **the teeth are the falsifier, not the clean pass** (loopback-floor-not-geo discipline).
- **Any new cross-host trust *mechanism*.** The detectors already exist (`A2ARouterCore::handle_intake`); this story **observes and times** them, it does not add detection logic to the router or kernel.
- **A new ADR / an ADR flip.** Unlike 11.1b (ADR-031), 11.2a/11.2b (ADR-049), this is a validation/test-infra story binding an existing NFR gate — **no ADR is authored or flipped.** (Confirm at preflight.)
- **OS-level process/container isolation per host.** See F1 — the landed real-mesh precedent (10.4b) is in-process `tokio::spawn` tasks over **real** `127.0.0.1` sockets + **real** rustls mTLS handshakes; 25–30 real OS processes/containers is CI-infeasible and adds no trust-realism over real-socket-real-mTLS. (Confirm at preflight.)

## ✅ PREFLIGHT RESOLVED — UNANIMOUS (party-mode 2026-07-03, Winston · Murat · John · Amelia, +Mary walk-on)

- **F-new (spec defect, FIXED) — detection is TWO-SURFACE.** The as-drafted AC2 ("detection = first router NACK − join") is **wrong for 2 of 3 adversary classes**: pin-spoof and cert-rotation-race are rejected at the **mTLS handshake layer** (`maos-a2a-tcp/src/verifier.rs` — "WebPKI validity FIRST, TOFU pin only on success," *before* `handle_intake` runs → a dial `TcpTransportError`, no router frame); only consent-bypass (`CODE_INTENT_DENIED`) and boot-nonce restart (`CODE_SPIRIT_RESTART_DETECTED`, `router.rs:743-779`) produce a router NACK. **RESOLVED:** detection = **first rejection event of ANY kind** — handshake-layer `TcpTransportError` OR router-layer NACK — captured harness-side at whichever surface the class fires; read from the **same `directed_dial_sweep`** the blast-radius derivation already consumes (a failed dial is already an unreachable pair in `pair_ok`). AC2 reworded.
- **F1 — RESOLVED: in-process real-socket real-mTLS mesh** (the landed 10.4b precedent), NOT OS processes/containers. The epic's "kernel-process/container" prose is aspirational wording (Winston's ADR-049 "sealed-export" analogue), reconciled to `t_10_4b_rotation_real_timing.rs`.
