## Story

As a **MAOS operator upgrading one member of Marcus's 8-host cohort (J3) without tearing the mesh down**,
I want **to hot-swap a single cohort member through a `drain → in-place swap` — draining its in-flight halts (I14, boot_nonce preserved, mesh links live), migrating its Spirit across versions via an operator-declared migrator chain that is provably linear (one outgoing migrator per source version over the operator's candidate set, else a chain-validation error) and walked hop-by-hop (refusing `EMigratorMissing` that names the exact missing hop), under a `--plan` that hashes the resolved chain so the swap-admission layer refuses a chain that drifted from the plan (`EMigrationPlanDrift`) — and, only when the member re-keys its host cert, a signed manifest re-issue so peers re-pin the new fingerprint before it rejoins**,
so that **a live cohort survives per-member version upgrades with zero dropped halts, no ambiguous migration path, and no silent divergence between the plan an operator approved and the chain the swap ran — the lifecycle-hardening half of J3, on the real N=8 mesh.**

**This story is the Epic-12 closer, and preflight PROVED it ZERO kernel-Δ @23082 (the "possibly ZERO" hedge is resolved — the layering forces it).** It owns exactly what 12.1–12.4b each explicitly deferred: "does NOT implement cohort hot-swap / migration (12.5)" (`12-1-...md:19`, `12-3-...md:19`). Scout-verified at HEAD `bec4bb16`: (1) the per-Spirit **single-hop** swap+migrator engine already exists and works — `HotSwapCoordinator::initiate_swap` (12-step ADR-017 protocol, `crates/maos-kernel-core/src/hot_swap/coordinator.rs:120`), `run_migrator` (single cross-major hop, `crates/maos-kernel-core/src/hot_swap/migrator.rs:21`), `EMigratorMissing` already carrying the four hop-naming fields (`crates/maos-domain/src/hot_swap.rs:105`), I14 gate `validate_swap_halt_continuity` (`crates/maos-kernel-core/src/halt/mod.rs:430`); (2) **no chain AND no version catalog exist** — the coordinator does exactly ONE hop (`coordinator.rs:285-286`), `state_codec::decode` HARD-REJECTS a ≥2-major jump (`state_codec.rs:153`), and nothing enumerates a class's versions (`SpiritArchive` is per-instance + test-only + zero prod callers; `maos-registry` is never consulted at swap time) — so the chain is **operator-DECLARED (a candidate set), not discovered**, and multi-version upgrades are the missing capability a linear chain provides; (3) **`EMigrationPlanDrift`, a fork error, `MigrationPlan`, chain-hash, `--plan` do NOT exist anywhere** (grep-confirmed across `crates/`) — net-new, out-of-kernel; (4) both new error codes need FR63 registration (`xtask/error-catalog.toml`, only `EMigratorMissing` at `:83` today). This story **composes and extends** existing kernel primitives with an **out-of-kernel** chain resolver (over the operator's set) + plan-hash + drift guard (wrapping the `UpgradeOrchestrator::upgrade` chokepoint) + a `--plan` mode on the EXISTING `upgrade`/`hot-swap-precheck` surface + new `check-cohort-mesh` legs. It does **NOT** rewrite the swap engine, the halt protocol, the cohort manifest schema, the kernel, or add a version registry / a new `swap` verb / a boot_nonce restart path.

   - **Non-linear set → a distinct chain-validation error, over CONCRETE-version overlap, with TWO independent checks (Round-3, Boundary/Splinter — a diamond is a *surplus*, a cycle is *unterminating*; do NOT overload `EMigratorMissing`, and do NOT fold cycle into fork).** Linearity is a property of the SET and lives in the resolver (not `MigratesFromSection::from_toml_str`, single-manifest, `crates/maos-manifest/src/manifest.rs:3398`), and it needs **both**: **(1) fork/fan-out** — for each *concrete* source version, count candidates whose `migrates_from` matches it via `matches_version_pattern` (`crates/maos-kernel-core/src/hot_swap/migrator.rs:105`); `>1` = fork. **CRITICAL: check CONCRETE-version overlap, NOT declared-string uniqueness** — `migrates_from=["1.0"]` and `migrates_from=["1.x"]` are *different strings* that BOTH match source `1.0` (the wildcard-fork the scout confirmed), so a resolver that dedups on the literal string MISSES the fork. **(2) acyclicity** — a visited-set on the `--from → --to` walk; a **2-cycle passes the fork rule** (each node has exactly one outgoing migrator) yet never terminates, and a **self-loop** (`matches_version_pattern("2.x","2.0")` is true → a manifest migrating from itself) is its length-1 case. **Fan-IN is LEGAL** — one successor with `migrates_from=["1.0","1.1"]` is a merge, not a fork (each source still has one outgoing migrator); the resolver must NOT flag it. ### Round-3 (hard round, 2026-07-13, 2 more scouts — the drift guard was CIRCULAR + linearity certified cycles). NO user fork — the code dictated both answers.

### Architecture basis
- **ADV-054-4 (verbatim, `15-full-spectrum-v2-2.md:39`):** "Per-member `drain → swap → re-pin`, honoring I14 and NFR-Rel-6 pin invalidation, using the 11.3 re-pin playbook. ### §A7 reflexes per leg (name each in the gate + tests)
- **non-linearity reflex (two checks)** — a `ForkAtSource` via a **wildcard overlap** (`["1.0"]`+`["1.x"]` on source `1.0`) reds through concrete-overlap detection (a string-uniqueness resolver misses it → RED); a `Cycle`/`SelfLoop` reds through the acyclicity check (a fork-only resolver certifies a 2-cycle as linear → RED); a legal **fan-in** (`["1.0","1.1"]`) that gets flagged is RED (negative control). Each leg asserts the exact `reason`, never a catch-all.
- **missing-hop reflex** — `EMigratorMissing` names the SPECIFIC absent hop at run time, derived from the real chain walk (distinct from `ECohortNoMigrationPath`, the plan-time reachability miss, and from the fork — absence, not surplus, not unreachable).
- **plan-drift reflex** — the drift refusal comes from a REAL hash comparison of the **persisted plan file's** `plan_hash` vs the re-derived-live hash (NOT an operator-retyped hash — that's circular); a swap that executes a drifted chain, or a hash read from a stored constant, is RED. The guard reads the plan from the file, never the operator.
- **cert-rotation re-pin + coherence reflex (AC1b)** — the re-pin is enforced at TOFU by the transport rebuild (old cert REFUSED / new admitted, real handshake), AND the re-issued `CohortMember.fingerprint` equals the newly-pinned fp; a still-accepted old cert (cosmetic re-pin) or a gate-vs-TOFU fingerprint divergence is RED. The manifest gate does NOT enforce fingerprints — do not assert re-pin "via the gate."
- **halt-continuity reflex (AC1a/AC6)** — the surviving `agents_halted` count is DERIVED from the persistent TL receipts (`derive_team_digest`), reconciled `before_count == drained_count` at ≥1 hop with real pending halts (a `SafeDrained{0}` hop is vacuous); halts are DRAINED-resolved, not carried in the SCB. A dropped halt, a vacuous zero-hop, a canned narrative, or a count read from the (drained) live registry is RED. The in-place swap keeps `boot_nonce` — a rolled nonce auto-reverts and is RED by construction.
