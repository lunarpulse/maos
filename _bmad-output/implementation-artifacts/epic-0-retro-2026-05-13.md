## What Went Well

1. **Substrate-first velocity.** Shipping 13 CI gates BEFORE kernel code worked exactly as Epic 0's mandate prescribed — gates are green on an empty workspace and ready to validate Story 1a.1 from the first PR.

2. **Fixture-tree pattern replication.** `violation-X/` + `clean-X/` paired trees from Story 0.1 became the canonical adversarial-proof shape across 0.2, 0.3, 0.4, 0.5. Replicated, not innovated.

3. **Generator beats hand-authoring.** Story 0.5's 200 + 80 seeds → 10,000 + 640 items deterministically. Hand-authoring 2,249 corpus items across v1.0/v1.5 ship gates would have dominated the critical path; the generator collapses that to ~280 seeds + versioned expansion rules.

4. **Schema review pre-freeze.** ComplianceClaim adversarially reviewed BEFORE E1b freezes it. Mary + Winston joint-demand honored; `_bmad-output/planning-artifacts/compliance-claim-schema-review.md` signed off 2026-05-12. Story 1b.4's first AC is now mechanically resolvable.

5. **`OfflineMode::judge` shim pattern.** Story 0.3 built the judge channel without a live judge; Story 0.4 plugged the calibration corpus in; Story 1b.4 will plug the real `InferencePortJudge` in *without restructuring the gate*. Substrate composition working as designed.

6. **Wilson-score CI math.** Epic-0 prose said `CI-width ≈ 0.124` (Wald approximation); we shipped the textbook-tighter Wilson form, more honest than the contract demanded, documented the delta in `calibrate.rs`.

7. **Tightening-vs-loosening discipline as habit.** Every blocklist/denylist/allowlist file carries a TOML-comment header documenting "extension is a tightening (mechanical); narrowing requires invariant-lock review." Future authors inherit the discipline without rediscovering it.

## What Was Challenging

### 1. Review-finding density (process gap)
First-draft quality leaves too much for reviewers — 17 patches on Story 0.1, double-digit patches each on 0.2–0.5. Reviewer caught the issues, but some were stuff a self-review should have caught (round-trip JSON tests missing, kloc-threshold edge tests absent, `ALLOWED` constant unreferenced, JSON format stability tests missing).

### 2. Dependency-introduction blast radius (process gap)
DF4: Adding `tempfile = "3"` to xtask transitively pulled `getrandom 0.4.2` and ~25 WASI/WebAssembly ecosystem crates. Discovered post-merge during a `Cargo.lock` audit. No dep-vetting discipline existed; `cargo add tempfile` ran, tests passed, code review focused on logic, the bloat surfaced after the fact.

### 3. Corpus-quality debt in Story 0.5 (spec vs implementation drift)
- DF11: 200 secret-redaction seed entries, but only **11 unique patterns** — all 20 `api_key_anthropic` seeds share the same `pattern_regex`; only `id` differs. AC2 said "200 seed patterns covering all named secret classes"; we shipped 200 *seed entries* with 11 *patterns*.
- DF12: `oauth_token` regex cannot match real-format Slack tokens (char class missing hyphen).
- DF13: `api_key_openai` regex collides with `api_key_anthropic`.
- DF14: `azure_credentials` `sig=` pattern excessively broad (matches non-Azure URLs).

The corpus shipped as **scaffolding for the gate**, not data for production redaction (NFR-Sec-4 doesn't ship until v0.5). But the AC-vs-implementation reading was loose enough that the dev agent's interpretation was technically defensible while not honoring the spirit.

### 4. (Surfaced during readiness check) `journal.jsonl` merge-append is a structural gap, not a one-line bug

Initial framing: "`journal.jsonl` is 0 bytes despite Story 0.2 AC5 requiring a merge-append." Investigation on 2026-05-13 (critical-prep #3) revealed this is **structural, not a missed call**:

1. No merge-queue job exists in `discipline.yml` — Story 0.1 AC5 explicitly called for one.
2. The existing `append_journal` writes to the runner's ephemeral filesystem; no commit-back to the repo exists.
3. The code path only fires on `pull_request` events (not `push: main`), and even then the write vanishes.
4. Verified empty in all history: only the initial-creation commit touched the file.

**Tracked as DF16** in `_bmad-output/implementation-artifacts/deferred-work.md`. Three resolution options enumerated in `docs/dev-discipline/1a1-adr-landing.md` (merge-queue + commit-back / out-of-repo store / per-merge artifact). **Story 1a.1 cannot open its PR until one is implemented and verified end-to-end on a synthetic test PR** — shipping 1a.1 without a journal entry for the 14 touched invariants violates AC5's tri-requirement.

### 5. (Surfaced during readiness check) `invariant-lock` only exercised on 1-invariant diff
Story 0.2 was the first dogfood — touched I9 only and we found bugs in `parse_cadence`. Touching 14 invariants in one PR (Story 1a.1's plan) will exercise the gate in ways we haven't tested. Captured in the ADR-landing strategy.

## Patterns Across Stories (Deep Analysis)

### Recurring positive patterns
- `#[cfg(test)]` skip on AST walks — pattern from `check_unsafe` replicated cleanly.
- JSON round-trip stability tests for every `Report` shape — schema-drift caught at unit-test time.
- Explicit `empty_X_passes` tests — every gate green on empty inputs at v0.1-α.
- TOML-header tightening-vs-loosening documentation discipline.
- "Mechanism complete vs mechanism stub" honesty — no fake-green, clear hand-off labels.

### Recurring concerning patterns
- **String-grep instinct surfaces 3+ times.** Reviewer escalated `DefaultHasher` → SHA-256 (P9), `contains()` → structured matching (P1, P2), exact-indentation parse → `trim()` + key-validation (parse_cadence). Habit not internalized.
- **Tests-for-the-test missing.** kloc-check alarm/hard-fail threshold tests added only after reviewer flag (P13). Pattern: implementing-the-thing is fast; testing-the-thing's edge cases is undertested.
- **Spec-prose-vs-implementation drift.** 0.5 AC2 prose was ambiguous; implementation honored the letter ("200 entries") not the spirit ("200 distinct patterns"). Worked-examples convention needed.
- **PR-comment bloat unmonitored.** Each story adds 3–5 aggregate-table rows; no one tracking readability ceiling.
