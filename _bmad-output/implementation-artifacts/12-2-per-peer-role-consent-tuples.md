## Story

As a **MAOS operator running Marcus's 8-host Team Nexus (J3)**,
I want **each cross-member A2A frame to be admitted only when the counterparty's manifest-declared role — matched exactly, never OR'd across a member's other roles — appears in the correct send/accept table of the signed cohort manifest, and only when sender and receiver are within one manifest version of each other**,
so that **a member acting under one role cannot launder an intent it is forbidden from under that role through another role it happens to hold (the confused-deputy class, ADR-012 extended), and a mid-flight manifest re-issue cannot silently admit frames under a stale consent matrix.**

This story turns the consent matrix that Story 12.1 **declares, parses, and validates** into a matrix that is **evaluated at the live A2A seam**. 12.1 landed `ConsentTuple { peer, role, intent }` in the signed manifest and the `CohortManifestGate` port; the `role` field is signed into the canonical bytes but is **dropped at projection** (`peer_configs_for` filters on `peer` only) and is **absent from the runtime allowlist** (`ConsentAllowlists` is role-blind). 12.2 threads the role dimension through evaluation, adds the version-skew guard (`ECohortManifestSkew`), and proves the consent corpus red on the live mesh. It does **NOT** implement halt receipts (12.3), the team digest / J3 day-30 scene (12.4), or cohort hot-swap / migration (12.5).

## Acceptance Criteria

1. **Two-seam evaluation, separate tables, gate is authoritative for role+version (ADV-054-3; P1/P3/P5 RESOLVED).** Cross-member admission is evaluated at **both** A2A seams against the **signed** manifest's **separate** send/accept tables (`ConsentMatrix.send` / `.accept` — no transposition): the **accept** seam (the **binding** confused-deputy control, P5) checks `(sender_peer, sender_role, intent)` against the receiver's **accept**-allowlist; the **send** seam is a **lighter local fail-closed outbound pre-check** (P5 — the sender refuses to emit an intent it has no send-tuple for to that peer; NOT the security boundary, may consider the receiver's manifest-declared roles). All role/version evaluation lives **out of kernel** in `maos-cohort` behind the existing `CohortManifestGate` port (the 12.1 dependency-inversion seam — the router in `maos-a2a-core` never names `maos-cohort` types). **The gate reads the LIVE, versioned `CohortManifestState` per frame (P3), NOT the static `peer_cfg.allowlists` snapshot** (`lookup_peer`, `router.rs:756`) — that snapshot is version-less and decoupled from the gate, so sourcing the role/version decision from it would make AC3's skew check meaningless. The role-blind `ConsentAllowlists` projection stays the **legacy/bilateral path** for non-cohort peers, unchanged; for cohort members the live gate decision is **authoritative** and composed **fail-closed** with (never weaker than) the existing per-peer admission. **Per-peer referential integrity (P2 — reopens a 12.1 gap):** `maos-cohort`'s `validate_consent_table` (`manifest.rs:494-520`) currently checks each tuple's `role` against the **union** of ALL members' roles (`declared_roles` built by `flat_map` at `manifest.rs:331-336`) — so `(host-b, reviewer, intent)` **passes** even when only host-c declares `reviewer`. **12.2 tightens this to per-peer binding: `(peerX, roleY, intent)` requires `roleY ∈ members[peerX].roles`** (a state read, not the union), rejecting the mis-scoped tuple at parse. This is a zero-kernel correctness fix to a 12.1-`done` validator, disclosed against 12.1 in the change log — a constraint on this AC, not a new AC. **`role` is the counterparty's manifest-declared role as seen from the evaluating seam** — a signed, versioned state read (AC4), never negotiated.

2. **Acting-role exact-match, never any-role OR + entitlement (ADR-012 confused-deputy, extended; P2/P5/P6 RESOLVED).** A member may declare multiple roles (`CohortMember.roles: Vec<String>`). Each cross-member frame carries the sender's **single acting role** (one cohort role on the wire — P5). The **accept** seam matches that role **exactly** against the accept-allowlist tuple — a member acting as `reviewer` is refused an intent whose only tuple is `(peer, architect, intent)`, even though the member also declares `architect`. **Never** admit by OR-ing across the member's declared roles (this never-OR rule is a property of the **accept** seam — the confused-deputy vector is a member laundering an intent across *its own* roles at the receiver). **Entitlement is REQUIRED, not defense-in-depth (P2 — the story's earlier "implicit via referential integrity" claim was FALSE; 12.1's check is union-scoped, see AC1):** the accept seam MUST reject an acting role the sender does not declare in `members[sender].roles` — a typed refusal **before** tuple-matching, with a reason distinct from "no grant." With AC1's per-peer parse-time tightening this is defense-in-depth; without it, it is the only thing standing between a mis-scoped tuple and a confused-deputy admit — build **both**. **Fail-closed on absent role (P6):** a cohort frame carrying **no** acting role (`None`) is **refused**, never default-admitted (reserved intents bypass, AC5). **Type trap (code-verified):** cohort roles are arbitrary strings; the existing `FrameAddress.role` is a fixed `SpiritRole` enum (`Director|Observer|Worker|Orchestrator`, `identity.rs:207`) and **cannot** carry a cohort role — the acting-role carrier is a **new String field on `A2AJsonRpcRequest`** (P1, the `boot_nonce` idiom).

3. **Version skew, fail-closed-wins; drain-by-construction (ADV-054-3; P3/P6 RESOLVED).** Each cross-member frame carries the **sender's** manifest version (on `A2AJsonRpcRequest`, P1). The receiver evaluates under its **own** accepted version, **read live from `CohortManifestState` per frame** (AC1/P3 — not the connection-time snapshot); the stricter side wins. A version delta `> 1` (i.e. `|sender_v − receiver_v| > 1`) → typed **`ECohortManifestSkew`** (new variant on `CohortError`, **distinct** from `EIntentDenied` and from `EConsentPeerNotMember`); a delta `≤ 1` admits (subject to AC1/AC2). **In-flight drain is a NEGATIVE requirement (P3, do-not-break):** admission is synchronous per frame — the verdict cannot straddle an `.await` (code-verified: `is_current`/`consent_decision`/`accept_admits` are sync `fn`s, the first yield is *after* admit). So each frame is decided under exactly one cached version and no frame straddles a re-issue — the only version-change window is *between* `handle_intake` calls. **DO NOT** memoize the version at connection setup or introduce an `.await` between the version read and the verdict — that reintroduces the straddle the sync path prevents. **Fail-closed on absent version (P6):** a cohort frame with **no** manifest version → **refuse** (cannot skew-check a null; reserved intents bypass). Fail-closed on any evaluation error — an `Err` in the role/version path is a **deny**, never a silent admit (11.4b error-swallow lesson).

4. **Role queries are a signed-state read, not discovery.** The receiver's role (send seam) and the sender's declared roles (accept-seam entitlement, AC2/F4) are **read from the signed, versioned manifest** held by `CohortManifestState`/the gate — never a runtime probe, negotiation, or peer-query protocol. Reuse the 12.1 `CohortManifestState` accessors; any new role lookup is a `maos-cohort` method behind the port.

5. **Consent corpus proven-red, real derive-and-reconcile, added to `check-cohort-mesh` (P4/P6/P7 RESOLVED).** New always-binding legs on the existing gate (append `Leg` entries — each MUST resolve to exactly one `--exact` test per the `:29-34` vacuous guard; test style is plain `#[test]`/`#[tokio::test]`, no rstest — code-verified, one-test-per-leg holds), each with its **own** falsifier wired to its **own** leg (11.4b — a falsifier no leg runs is not a falsifier): **(a) role-mismatch-on-allowed-peer** — a peer that IS in the roster and whose channel is otherwise consented is **refused** an intent it may only send/accept under a different role (the headline confused-deputy leg, ACCEPT seam, the binding one); **(b) acting-role exact-match** — a positive (frame acting as the permitted role admitted) paired with the negative (the same frame relabeled to another declared role refused — proves no any-role OR); **(c) entitlement** — a frame claiming an acting role the sender does **not** declare in `members[sender].roles` is refused with the typed entitlement reason (P2), paired with a **parse-time** leg proving the tightened per-peer validator rejects `(host-b, reviewer, …)` when host-b lacks `reviewer` (`EConsentRoleUndeclared` or the per-peer variant); **(d) skew** — `|Δv| > 1` → `ECohortManifestSkew` **specifically** (the leg asserts the distinct cause, not "some deny"), paired with `|Δv| ≤ 1` → admit; **(e) fail-closed defaults (P6)** — a cohort frame with `None` acting role AND one with `None` version each **refused**; **(f) reserved-intent still passes (P4)** — a `cohort:manifest-reissue` / `cohort:halt-receipt` frame from a member with an empty/absent role is **admitted** (proves the role gate sits *after* the `is_reserved_cohort_intent` short-circuit, not before — else 12.3 halt receipts break). The role-mismatch and skew negatives run on the **live N-host mesh over real TCP** (`t_12_2_*` in `maos-a2a-tcp`, 12.1's substrate — extend `signed_cohort_manifest` at `:256` with a non-default `ConsentMatrix`, fields are `pub`), not synthetic rows — the decision must drive the router's **own** admission comparator (the `EIntentDenied`/`ECohortManifestSkew` NACK the peer actually receives), not a side flag. A **second static chokepoint test** (`cohort_consent_chokepoint_12_2.rs`, mirroring `cohort_manifest_chokepoint_12_1.rs`) pins the consent-eval call sites so the seam can't be silently duplicated/bypassed. **§A7 reflexes per leg (P7):** role-identity (admitted acting role = manifest-bound-to-peer ∧ frame-carried, reconciled — a planted role-swap reds through the real NACK); skew-cause (asserts `ECohortManifestSkew` distinctly, the 12.1 `ConcurrentFork`-vs-`VersionRegression` discipline); entitlement (two legs, two falsifiers — parse + accept).

### Architecture basis
- **ADR-054 §5** (`docs/adr/ADR-054-cohort-mesh.md:59-61`): "the role in a tuple is the counterparty's manifest-declared role as seen from the evaluating seam … the frame's consent envelope carries the single acting role; match is exact, never any-role OR … mismatch beyond ±1 → typed `ECohortManifestSkew`, distinct from `EIntentDenied` … *Story 12.2 implements the two-seam evaluation and `ECohortManifestSkew`.*"
- **ADR-012** (`.../12-architecture-decision-records.md:204`): consent is `(peer-identity, intent-class)`, not `(peer-identity)` — the confused-deputy control. 12.2 extends it to `(peer-identity, role, intent-class)` with exact role match. "A read-only Spirit cannot pass a payload to a writeable Spirit that … causes a write the read-only Spirit was forbidden from" — the role dimension makes this per-role.
- **Architecture §15.2** (`architecture-maos-minimal-opus/15-full-spectrum-v2-2.md:37`): the ratified ADV-054-3 semantics (verbatim source for the two-seam + skew + drain rules).

### §A7 reflexes to name per new gate leg (Epic 12 gate discipline)
- **role-identity reflex:** the admitted frame's acting role is BOTH what the manifest declares for that peer AND what the frame actually carried, reconciled — not a label. A planted role-swap (frame carries role X; a bug admits it as role Y) must RED through the router's own comparator.
- **skew-cause reflex:** the skew leg asserts `ECohortManifestSkew` **specifically**, never a generic deny — the distinct-cause discipline that 12.1 used for `reason==ConcurrentFork` vs `VersionRegression`.
- **derive-and-reconcile:** the admit/deny is derived from the signed manifest + the actual frame and reconciled against the real router result — never a self-reported flag, never a literal "admitted N".
- **planted-lie-turns-it-red:** a forged acting role, or a frame whose intent is only permitted under another declared role, flips the leg red through the actual `EIntentDenied`/`ECohortManifestSkew` the peer receives — not a side assertion.

### Prior-story traps to avoid (12.1 Dev Notes + retros)
- **Tautological falsifier (11.2b P2 / 11.4b D1).** A blind that `+=0`, or filters a set it then re-counts, is theater. The role-mismatch falsifier MUST drive the real admission a downstream contract consumes (an actual NACK), not a side flag. **Every named falsifier gets its OWN per-leg-independent gate leg.**
- **Vacuous-count (11.2a P1).** Never assert admit/deny from a literal — derive from the actual signed manifest + frame and reconcile. 11.2a shipped this P1 even under §A6 on a weaker model → the non-degradable Test-Infra + runtime layers are pre-booked regardless of model.
- **Origin ≠ authorization (11.2a orphan).** A TLS-verified peer identity (origin — `handle_intake_verified` binds `frame.from.host_id` to the verified `PeerId`, `router.rs:1021`) is NOT authorization to act as role X. Authorization is the signed accept-allowlist tuple, matched exactly. F4's explicit entitlement check closes this loudly.
- **Error-swallow (11.4b P1).** A role/version-eval `Err` mapped to "admit" is a false-green. Return `Result`; a broken check is a deny, distinguished from a clean admit.
- **Fail-closed-wins on skew (ADR-054).** When sender/receiver versions differ, the stricter (receiver's own) governs; never adopt the sender's claimed version to admit.
- **Advisory ≠ silent-green.** The new legs are always-binding-per-commit (12.1's whole-set hard-fail loop). Do not introduce an advisory tier here without porting the `check_scale_churn.rs` LegResult machinery (a larger refactor, out of scope) — and note the gate-binding-decay finding (`gate-binding-decay-findings-2026-07-10.md`): `check-cohort-mesh` is the first/only gate that actually binds at HEAD; keep it that way.
- **Expect a second adversarial pass.** First dev pass materially incomplete is the norm (11.1a/11.1b ~22 patches each; 12.1 had 3 review patches). Budget it. §A6 net is non-degradable here.
