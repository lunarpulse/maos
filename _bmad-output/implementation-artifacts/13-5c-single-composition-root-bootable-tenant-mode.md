## What this story is, in one paragraph

13.1 built the **physical** tenant wall. 13.2 built the **cryptographic** one. Both are shipped, both are proven at a seam, and **both are inert in every bootable configuration** — because `main.rs:2286` calls `tenant_map_for_store(&home_team, None)`, so setting `MAOS_LOOM_HOME_TEAM` is an unconditional boot failure. 13.5c is the story that supplies the missing `Some(…)`.

**It is much smaller than its billing, and exactly one fact makes it so:** there are **not** two composition roots. `run_cohort_a2a_daemon_from_env` is dispatched at `main.rs:6933-6935` from *inside* `async fn main` (`:1955`–`:7374`), and **`main` contains zero top-level `return` statements** — verified mechanically. A `cohort-a2a-daemon` process therefore **already runs the entire primary root** (`:2077`–`:4296`), builds the Transparency Log, the `LoomLiteStore`, the `MemoryManagerAdapter` and the `CapabilityRegistryAdapter`, and *then* calls a zero-argument function that ignores all of it and opens a second Transparency Log. **The work is "give an existing function its arguments," not "join two roots."** ADR-055 §5 says the opposite in its own words (*"a parallel composition root"*) — correcting that sentence is an AC deliverable.

The story does **not** build the Spirit→collective route (13.5d), tenant audit isolation (13.5e), collective erasure (13.5b), or cross-wall recall (13.3b). Keeping it that small was the explicit ratification condition of the scoping pass.

## Story

As a **MAOS operator running Reza's 400-person fintech as one governed Cortex**,
I want **the cohort daemon to be one composition root — one process, one Transparency Log, one boot nonce, with the verified cohort manifest state constructed early enough to satisfy the tenant map**,
so that **`MAOS_LOOM_HOME_TEAM` boots for the first time instead of hard-failing, the physical and cryptographic tenant walls 13.1 and 13.2 already shipped stop being inert, and the `cohort-a2a-daemon` mode is executed by a machine at least once before anything is built on top of it.**

## Design forks for preflight (K-numbered; grounded recommendations the ACs assume)

**K1 — THE FORK: how does `CohortManifestState` reach `tenant_map_for_store`?**
- **(a) Move the load up.** Read the daemon config + `CohortManifestState::load` into the window between TL #1 (`main.rs:2254`) and the store (`:2274`), build the `TenantMapAdapter`, and pass `Some(Arc<dyn TenantMapPort>)` into `tenant_map_for_store` at `:2286`. Hand the same `Arc<CohortManifestState>` down to the tail dispatch.
- **(b) Late-inject.** Build the store with `None`, then attach the tenant map after the daemon constructs the state.
- **✅ Recommend (a) — and (b) is close to structurally impossible, not merely worse.** `with_tenant_map` is a **consuming builder**: `main.rs:2307-2310` calls `store.with_tenant_map(Arc::clone(map))` on an **owned** `store`, *before* `Arc::new(store)` at `:2311`. By the time the tail dispatch runs, that store is inside `Arc` → inside `LoomLiteAdapter` (`:2318-2322`) → inside `Option<Arc<dyn CollectiveMemoryPort>>` → **moved** into `MemoryManagerAdapter::with_collective_port(collective_port)` (`:2402`) → inside the scheduler. Late injection means either interior mutability on a shipped store or unwinding five layers of `Arc`. **Worse, (b) leaves a window in which the store serves with no tenant map — a fail-OPEN gap in the exact wall 13.1 built.** (a) is ~20 lines in a window that already exists.
- **Cost of (a) that must be named and guarded:** the config read moves from `:7937` to ~`:2260`, so a malformed `MAOS_COHORT_DAEMON_CONFIG` would now fail the boot *earlier, for every mode*. Read the file only when the env var is set; surface the hard error only in the `cohort-a2a-daemon` arm.

**K2 — what happens to `own_boot_nonce` (D3).**
