## What this story is, in one paragraph

13.1 built the **physical** wall, 13.2 the **cryptographic** wall at entry, 13.3 the **governed cross-team row**. All three move *bytes* across the wall. **None of them moves meaning.** A row that lands in team B carrying `source_team = A` is, to every reader in B, an assertion without a chain: the digest says "distilled from 14 prior decisions" and **there is no way to name those 14 decisions, let alone read them**. That is the Reza 4:55 PM scene, and at HEAD it does not reproduce.

**13.3b makes provenance cross the wall.** Three mechanisms, each of which does not exist at HEAD in any form:

- **The chain rides with the row.** `CollectiveKvLeaf` (`replication/leaf.rs:61-78`) has **no `source_log_ref`, no `distillation_depth`, no `intent_lineage`** — there is no wire representation of provenance anywhere in the replication path. A **leaf v3** adds one, under a third domain tag, with **v1 AND v2 canonical bytes byte-identical** — two frozen predecessors now, and (E5) **only the v1 half is currently guarded by anything at all**.
- **Cross-team citation becomes expressible under a ratified rule.** `distillate.rs:339-359` (Story 8.10 AC2b) rejects `CiterUnauthorized` on `e.spirit_pid != spirit_pid` over the **flattened** refs, explicitly *"so a digest-of-digest cannot launder a cross-principal raw frame through an intermediate hop."* This story's ask **is what that control was built to prevent**. It is widened by an **ADR-grade rule with its own negative control**, or not at all.
- **Raw traceback across the wall becomes a consented read.** `LogRecallPort` is 2 methods, `spirit_pid`-only; `recall` hard-pins emitter scope (`log_recall.rs:282`); the consent check is a **comment** (`:378-386`); `LogRecallError` has **no refusal variant**; and `grep -rni team crates/maos-iac/src/` returns **0** — the entire IAC spine is team-blind.

It also **writes the authority that everything above cites and that has never existed**: ADR-058, plus porting ADR-013 and ADR-018 into `docs/adr/`.

It does **not** build per-team TL isolation or the tenant-blind-audit closure (13.5e), collective erasure (13.5b), tenant-mode boot (13.5c), or the Spirit→collective route (13.5d).

As **Reza, running a 400-person fintech as one governed Cortex**, at 4:55 PM with a consolidated proposal in front of me that cites 14 prior schema decisions made by three different teams,

### Rework brief — 2026-07-21 (scouted read-only at HEAD `5b08099a`; GOVERNS this rework)

Reopened after the shipped commit was found RED on live substrate. **This section governs.** Six premises of the dispatching brief were disproved; the corrected versions are below.

**The defect, with the exact path.** `build_replication_bundle_v2` overwrites `leaf.source_region` **and** `leaf.source_team` on every leaf with the envelope identity before `kv_merkle_root` (`replication/bundle.rs:313-315`). Feed it a team-a-origin row under `&team_b` and the origin is silently rewritten; `verify_replication_bundle` then finds everything internally consistent — signature valid under `derive_team_pubkey(seed, region, team_b)`, coherence check at `:432-440` comparing `leaf.source_team == bundle.source_team` (both now team-b), Merkle root matching — and returns `Ok(())`. `apply_verified_replication_bundle` persists `team: leaf.source_team` (`:620-626`), so the row lands at the next hop attributed to team-b. **The failing test IS the empirical proof that verify returns Ok.**

**Why this is not fixable at verify — read before designing.** A relabelled bundle is **byte-indistinguishable** from a genuine team-b first-party bundle. `verify_replication_bundle(bundle, seed)` is a pure function of those bytes, so no verify-side check can refuse it. The read path confirms the model: `store.rs:988-995` verifies the persisted envelope `region_sig` under `team_verifying_keys[(leaf.source_region, leaf.source_team)]` — the persisted-attestation model **structurally requires origin == signer**, and a row carries no origin-signed evidence independent of its attester. Multi-hop origin preservation is **not representable at v3**. The assertion at `cross_region_live.rs:554` therefore demands a property that cannot exist at that layer: **relocate it to build, do not try to satisfy it at verify.**

**THE FIX.** Delete the stamp loop; confine stamping to the `None` case; refuse relabelling with a typed error; extend verify's coherence check to the region axis for v2/v3 only.

```rust
pub fn build_replication_bundle_v2(
    mut leaves: Vec<CollectiveKvLeaf>,
    source_region: &Region,
    source_team: &TeamId,
    base_seed: &[u8; 32],
) -> Result<CrossRegionReplicationBundle, BundleError> {
    for leaf in &mut leaves {
        match &leaf.source_team {
            // First-party leaf with no origin: promotion is the legitimate
            // 13.3 case — there is no provenance to erase.
            None => {
                leaf.source_region = source_region.as_str().to_string();
                leaf.source_team = Some(source_team.clone());
            }
            // Foreign origin: relabelling would erase the only evidence of it.
            Some(origin) if origin != source_team
                || leaf.source_region != source_region.as_str() =>
            {
                return Err(BundleError::LeafOriginRelabelRefused {
                    key: leaf.key.clone(),
                    origin_team: origin.clone(),
                    origin_region: leaf.source_region.clone(),
                    envelope_team: source_team.clone(),
                    envelope_region: source_region.as_str().to_string(),
                });
            }
            Some(_) => {} // already matches — idempotent, no rewrite
        }
    }
    /* ...rest unchanged... */
}
```

Plus at `bundle.rs:432-440`, add `&& leaf.source_region == bundle.source_region` to the **v2/v3 arm only**. ⚠ **Leave the v1 arm untouched** — v1 legitimately transports foreign-origin leaves (`build_replication_bundle` at `:268-290` has no stamp at all, so v2's region stamp was a regression against v1's own model) and its bytes are frozen.

**Region axis is MANDATORY, not optional.** `bundle.rs:314` overwrites `source_region` by the identical mechanism; verify deliberately excludes it (`:433-438` — *"Leaf source_region is NOT constrained"*); apply checks it (`:472-474`) but only in the cross-team arm and only against the envelope, which the stamp guarantees equal, so it can never fire on a builder-produced bundle. **No test covers leaf-origin region laundering** — `region_identity_forge_rejected_count_moves` (`cross_region_live.rs:1244`, mutating `forged.source_region` at `:1281`) is envelope relabelling, a different property.

**Alternatives already evaluated and REJECTED — do not re-litigate:**
- *Separate `origin_team` from `attesting_team` as distinct leaf fields* — **a claim standing in for a control (tally 23)**. Without origin-*signed* evidence, team-b sets `origin_team` to whatever it likes. Costs a v4 tag, a schema migration, and new read/scan/`read_all_rows_from` plumbing to buy nothing.
- *Verify against persisted origin evidence* — `RowAttestation` (`store.rs:74-80`) genuinely is origin-signed evidence, but it is unreachable here: `CollectiveRow` (`store.rs:1139-1157`) does not carry those columns, `read_all_rows_from` (`:1064-1067`) does not select them, and `verify_replication_bundle` has no store handle — it runs at the **destination**, which by definition does not hold the origin's row.
- *Attestation chain (leaf carries origin root + sig + inclusion proof; verify walks it)* — this is the **correct long-term answer** and the only thing that makes multi-hop origin preservation real. It is a v4 wire change plus a new column. **File it as a separate story; do not attempt it here.**

**Honest limits — state these in the Dev Agent Record, do not overclaim.** The build-site guard stops *accidental* laundering by our own code paths. It does **not** stop a malicious peer who hand-crafts a bundle and never calls our builder, and nothing at verify can help there. What remains as the real control is the accountability model already shipped: `attestation_guard` binds every row to whoever signed it, and apply evaluates consent against the **signer** (`is_granted(from_team, ...)` where `from_team = bundle.source_team`). A determined holder can always re-author the plaintext as a fresh first-party row; no cryptographic control prevents that. **This fix restores provenance integrity for well-behaved participants and converts a silent rewrite into a typed error — say exactly that, and no more.**

**Severity note for the record:** this is a **consent bypass**, not attribution cosmetics. Where team-c grants team-b but denies team-a, team-b relabels team-a's row and team-c's `is_granted(team_b, team_c, intent)` passes. Origin-keyed consent is forgeable by any holder.
