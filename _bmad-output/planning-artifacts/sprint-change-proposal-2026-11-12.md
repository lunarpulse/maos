**Family-first profile design (five lines).**
1. Capability facts are data in `xtask/model-profiles.toml`; wire protocol stays in the existing per-vendor drivers.
2. Layers: provider defaults → family (id grammar, `baseline_version`, complete facts) → version entries only where facts change → exact-id `[[models]]` overlay or standalone entry.
3. Grammars are parsed structurally (typed placeholders), never by prefix; the loader and gate reject ambiguous family pairs.
4. A new id inherits from the nearest declared version at or below it, so `claude-opus-6-0` needs zero edits unless a breaking change is found; the result is recorded as `Inherited` (unverified) versus `Declared`.
5. One pure resolver turns intent plus profile into a wire plan and an `Applied` record; no-match or below-baseline ids are refused before any network call.

**Steward procedure (five lines; design §5.11).**
1. An AI agent, on demand or scheduled, outside the runtime; list endpoints and doc pages only, no paid calls, no runtime discovery.
2. Fetch, resolve every allowed/new id through the family rules, diff against vendor facts.
3. Classify: new id with no differing fact (`allowed` line) / family-version boundary (minimal version entry) / model-specific exception (exact overlay) / new family / retirement.
4. Regenerate goldens, run the gates, cross-family agent review; every PR lists `expected_changes`.
5. Escalate to the operator only on a price row, default-model, pinned-model behaviour change, or pin retirement (ruling B7d).
