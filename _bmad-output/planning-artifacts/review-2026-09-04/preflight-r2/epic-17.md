**Top-3 blockers**

1. **17-1 — the Worker is not under T3 today, and AC1's two observables belong to two different sandboxes.** The production Worker spawn is `spawn_and_bridge` = `Command::new(&spec.program)` + `cmd.env(k, v)` (`crates/maos-kernel-core/src/lifecycle/cli_wrapper/runtime.rs:449-468 @9f920180`); it calls neither `spawn_sandboxed` (zero production callers — grep of `crates/maos-bin/src`, `crates/maos-kernel-core/src`) nor `spawn_t3`, whose ONLY production caller is the `smoke-t3` busybox step (`crates/maos-bin/src/main.rs:7027`). The "T3 floor" is asserted at admission (`worker_spawn.rs:596-603`, `lifecycle/cli_wrapper/admission.rs:188`) and never applied — S2 in its purest form. AC1 then asks for `EACCES` on `~/.ssh` (a Landlock/T2 outcome, `security/sandbox/linux.rs:26-80`) **and** a "refused connect" (a T3 `--network=none` outcome, `t3/argv.rs:72`): under T2 the seccomp allow-list contains no `socket`/`connect` (no `SYS_socket`/`SYS_connect` in `linux.rs`) so the dial dies with `EPERM`, not refused; under T3 (`--user=65534 --read-only`, `argv.rs:73,76`) `~/.ssh` is `ENOENT`, not `EACCES`. Neither outcome reaches the TL as a `SandboxBlock` (kind 8) row — those are emitted only from `CapAuditEvent::SandboxBlock` (`capability/cap_audit/writer_task.rs:107-121`); the only row a container-internal error produces is a `CliSubprocessOutput` echo of the fixture's own stdout (`runtime.rs:27-28,562-608`) — a claim standing in for a control. Finally, an egress **allowlist** is not expressible with podman argv (`--network=none` is binary) and rootless podman cannot program nftables, so AC2 needs a host-side proxy — which is also the only mechanism by which AC3's "kernel-minted scoped credential" can keep the raw `ANTHROPIC_API_KEY`/`CODEX_API_KEY` (`worker_cli.rs:668,722`) out of `/proc/<pid>/environ`. That proxy is unpriced, ADR-061 is unwritten (`docs/adr` tops at ADR-059), and AC3 as written reds a pinned CI test (`crates/maos-cli/tests/credential_posture_2c.rs:299-330`, `env_clear_stays_absent_from_the_production_worker_spawn_path`).
2. **17-3b — `log.recall` "over the WASM wire" has no wire to ride, and no production path launches a WASM Spirit.** The WIT world exports `handle-frame`/`on-start`/`on-shutdown` and imports nothing (`wit/spirit.wit:219-232`); the runner is a subprocess with no TL handle (`crates/maos-wasm-host/src/runner.rs:1-38`); the kernel bridge is one-directional (child stdout → `CliSubprocessOutput`, stdin only via `write_stdin_line` `runtime.rs:687`). A guest→host recall needs a WIT import + a runner relay + a request dispatcher somewhere — inside the pinned bridge (kernel lines, contradicting "kernel-Δ 0") or as a maos-bin side-channel service (a fork the epic never names). Separately: `resolve_launch` is only ever called with `SpiritForm::NativeSubprocess` (`worker_spawn.rs:472-489`; zero `WasmComponent` references in `crates/maos-bin/src`); `maos run` parses a TOML manifest (`parse_run_args`, `worker_spawn.rs:44-82`) whose `forms` validator rejects every value but `rust-inproc|subprocess` (`crates/maos-manifest/src/manifest.rs:385-398`, test `:2589-2593` asserts `["wasm"]` is refused); no CI job builds `maos-bin --features wasm-host` (grep of `.github/workflows` empty); `MAOS_FEATURES` is not an env var anywhere (grep empty); `examples/ts-spirit` does not exist (`examples/` = `example-spirit`, `example-spirit-ts`). Exit line 2 has four non-existent tokens and the R2 proposal spells the path differently (`examples/ts-spirit.wasm`, `sprint-change-proposal…round2.md:53`).
3. **17-2 — `cat /sys/fs/cgroup/maos/spirit-<pid>/…` is the wrong layout for both a delegated daemon and a T3 Worker.** `resource_ceiling.rs:104` writes at the cgroup ROOT (`/sys/fs/cgroup/maos/spirit-{pid}`; non-root → `PermissionDenied` → `noop()` handle with an `eprintln!`, `:105-120`); `linux.rs:357-374` writes under the daemon's OWN cgroup (`<own>/maos.slice/spirit-{safe_id}`) — the only delegation-compatible layout; and a T3 Worker's caps are podman flags (`--cpus/--memory/--pids-limit`, `t3/argv.rs:79-81`, `--pids-limit` sourced from `fd_max` as a documented placeholder `:47-57`) living in podman's own `libpod-*.scope`, in neither layout. So there are three mechanisms, not two, and AC1's path is the one that cannot work without root. `cgroup_ceiling_smoke` is `#[ignore]` + `MAOS_CGROUP_TEST`-gated (`crates/maos-kernel-core/tests/cgroup_ceiling_smoke.rs:5-6,15-20`) and appears in no discipline job (grep `cgroup` in `discipline.yml` empty).

Cross-cutting: **three manifest schema changes hide in the ACs** — `[network].egress` (17-1), `pids_max` (17-2), a `wasm-component` form value (17-3b). Every section is `#[serde(deny_unknown_fields)]` (`manifest.rs:9,150,163,290,…`), `MANIFEST_SCHEMA_VERSION = 4` (`crates/maos-spirit-abi/src/lib.rs:33`), and each bump has a ratification precedent (`xtask/abi-ratifications.toml` `9.4b-AC6`, `13.5d`) plus `manifest_field_coverage` (`discipline.yml:647`) and N-1 compat. None is costed; `maos-manifest` has 100 lines of headroom and no 15-2 row.
