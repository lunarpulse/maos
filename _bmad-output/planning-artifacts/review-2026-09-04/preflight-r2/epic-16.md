**Top-3 blockers**

1. **16-3 stands on an assumed foundation.** `CrashDetector::handle_crash` returns `HandleCrashError::NotLoaded` unless the pid has an SCB in the scheduler map (`crates/maos-kernel-core/src/supervision/crash_detector.rs:95-100 @9f920180`) and emits `task.orphaned` **only** for records in `scb.task_assignments_in_flight` (`:141-150`). A CliWrapper Worker has neither: `run_cli_wrapper_manifest` never loads an SCB and journals the exit against `spirit_pid = 0` (`crates/maos-bin/src/worker_spawn.rs:732`). The same ledger drives `ProgressWatchdog` (`progress_watchdog.rs:73,109`), so 16-3 AC2 has the same gap. Also the epic's "kernel-Δ 0–10 (`CrashCause` variant)" is wrong twice: `FaultCause::SignaledByKernel { signal, stderr_tail }` already exists (`crates/maos-domain/src/supervision.rs:99-102`) and `CrashCause` lives in `maos-domain`, not the kernel.
2. **The exit block cannot be run by a machine as written.** Line 3's `maosctl halt resolve <id> --provided-context "…"` does not parse: the real shape is `maosctl halt resolve <halt_id> --spirit <s> --kind provided-context --text "<t>"` with `--spirit` required (`crates/maos-cli/src/cli.rs:711-727`). 16-1 AC1's `maosctl posture shift butler cautious` is likewise `maosctl posture butler --shift cautious` (`cli.rs:676-682`). Line 2 (`@hello-spirit …`) is typed into an interactive REPL (`maos-shell/src/lib.rs:165-176`), not a shell command. And `maosctl spirit inspect butler` exits 0 with "requires --sandbox at v0.3-β" today (`crates/maos-cli/src/subcommands.rs:1881-1885`) and reports no lifecycle state even with `--sandbox`.
3. **"One daemon" is an undecided fork.** `maos shell` builds a full composition root in its own process and returns from `run_shell` before the serving loop (`crates/maos-bin/src/main.rs:3249`); line 4's `maos run … &` builds a second root; `maosctl halt resolve` spawns a third `maos` with a fresh `HaltRegistry::new()` (`main.rs:1985`, seeding hack `:5568-5586`). The epic never says which process binds "the door", how `maosctl` discovers it (today: `MAOS_OPERATOR_HTTP_ENDPOINT` + `MAOS_OPERATOR_BEARER_TOKEN` env, `subcommands.rs:1938-1940`), or what happens when two roots bind the default loopback port. Plus a structural constraint the epic omits: `maos-cli` must never depend on `maos-kernel-core` (`crates/maos-cli/tests/dep_kernel_core_free_test.rs:8-24`) while `maos-control` does (`crates/maos-control/Cargo.toml:11`), so the client cannot link `maos-control`.

## H. Fork audit (rule 7: one decision per fork, before the story leaves backlog)
