The headline

The ZERO-Δ lean did not survive contact

The story shipped a clever plan: materialize the PDP's decisions into the kernel's copy-on-write policy snapshot — zero kernel change. Winston knifed his own author's lean — on correctness, not taste.

Expressing an organisation's forbid by quietly withholding a capability scope does three unforgivable things: it becomes a latent authorization bypass the day the approval prompt goes live; it hands the capability ceiling to out-of-kernel code (inverts invariant I1) and erases the audit distinction manifest-gap vs org-forbid; and subtraction can never express forbid-beats-permit override. The room authorized instead a bounded, named kernel re-pin — a real deny layer that the kernel owns and the PDP can only ever subtract from.

Ratified ledger — 7 forks, 2 catches

What the room decided

F1 · Model tier escalated

opus-4-8 + full §A6

Escalated from opus-4-6. The canned-green story of the epic — a stubbed PDP is indistinguishable from a real one until the policy swaps. §A6 must run the deny live and watch the falsifier red it. Third security-adjacent story running to escalate — now a standing trigger.

F2 · Kernel seam lean overruled

Bounded per_capability_deny

NOT zero-delta. A new OperatorPolicyConfig.per_capability_deny field + one deny-wins arm in evaluate (~+15–25 LOC, FLAG-Winston, HISTORY-disclosed). Kernel keeps the ceiling; the PDP layer only subtracts.

F3 · Reference engine resolved

Cedar, in-process

Engine-agnostic port + one Cedar (cedar-policy, pure-Rust) reference adapter. In-process → the deny tripwire is a real per-commit gate, not advisory-skipped. OPA / Vault are additive-per-port.

F4 · Fail-closed resolved

Freeze + staleness TTL

Four distinct proven-reds: no-config→default · configured-down→closed loud · runtime-drop→frozen · TTL-expiry→PDP-grants revert (Grumbal's stale-permit hole).

F5 · CI provisioning resolved

No service block

Folds into F3 — Cedar runs in-process, so the deny falsifier is a plain cargo test. If OPA/Vault land later, they carry the service container.

F6 · Docs resolved

ADR-050 + NFR-Sec-17

Lead with ADR-050 (binding-v2.0, gated on AC1–AC4 green). NFR-Sec-17 as a security floor. Gate traces to primary + an enterprise-deployment anchor — both cited, or it traces to nothing (Mary).

F7 · Forward-compat resolved

Optional principal_attributes

One opaque field on the port request now — unused in 4a, populated by 11.4c's SSO principal. Don't model the SSO shape today.

Catch B · Auditable deny constraint

AC count holds at 5

"A denial you can't audit is half a feature." Folded as a constraint on AC3 (Task 0 traces it), not a 6th AC. Rich attribution defers to 11.4c's SIEM slice.

The teeth

Four behaviours the gate must prove

01

Real evaluation

Swap the policy → the same request's verdict flips, via two distinct engine runs. A hardcoded map can't flip.

02

Deny actually blocks

An org forbid refuses the capability at issue — even when the manifest grants it (override proven).

03

Fail-closed

PDP down ⇒ freeze last-known-good; after the TTL, granted caps revert to deny. Never fail open.

04

Observable

Every denial is logged — a silent org-deny is not recoverable. Rich attribution rides 11.4c.
